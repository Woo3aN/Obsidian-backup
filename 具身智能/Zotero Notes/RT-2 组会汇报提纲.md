# RT-2 组会汇报提纲

> 配套精读笔记：[[RT-2 - Vision-Language-Action Models Transfer Web Knowledge to Robotic Control]]
> 论文：arXiv 2307.15818，CoRL 2023，Google DeepMind（54 人）

## 1. 总体贡献

**Q：用 2-3 句话总结这篇文章做了什么？**

> 针对「机器人只在训练数据里见过世界、换个物体就崩」这个问题，RT-2 提出把机器人动作编码成 8 个数字 token，直接塞进视觉语言模型（VLM）的词表，和网页上的 VQA 数据混在一起训。
>
> 结果是在真实办公厨房的约 6000 条评测轨迹上，没见过的物体/背景/环境平均成功率 **62%**（上一代 RT-1 是 32%，翻倍），而符号理解、简单推理这类「涌现任务」是 **60%**（RT-1 是 17%，3.5 倍）。
>
> 一句话：**它证明了网页上的常识可以绕过语言接口，直接接管机器人的低层动作。**

## 2. 论文动机

**Q1：想解决什么问题？是老问题还是新问题？**

是**老问题上的新切口**。

- 老问题：机器人泛化（换物体、换场景就不行）。研究了十几年，RoboNet、CLIPort、R3M、RT-1 都在做。
- 新切口：**怎么让 VLM 直接输出低层动作**。2023 年之前，VLM 用到机器人上基本都是「当大脑出计划」或「当眼睛做感知」，没人把它接到关节指令上。

**Q2：相关工作分几类？本文的核心优势是什么？**

| 类别 | 代表 | 怎么用 VLM / 预训练 | 卡在哪 |
|---|---|---|---|
| A. 堆机器人数据 | RoboNet、RT-1 | 不用 VLM | 数据差三四个数量级，补不上 |
| B. 预训练视觉表征 | R3M、VC-1 | 只借视觉编码器 | 借不到语言和常识 |
| C. VLM 当高层规划器 | SayCan、PaLM-E | 出文字计划 | **底层控制器没吃过网页数据，常识被截断** |
| D. VLM 当感知模块 | CLIPort、MOO | 出语义图 / 标物体 | 只补感知，不补动作 |

**本文的优势：不做新模块、不加参数。** 直接把 VLM 的输出空间借给动作——语言和动作共享同一套权重，所以网页知识不用「翻译」就能流到动作上。这是 A/B/C/D 都没做到的。

**Q3：这个问题真实存在吗？有没有简单解法？**

真实。不解决的话机器人只能待在实验室——换个杯子就抓不到，进不了家门。

简单解法有两条，但都不行：

- **多采数据**：网页是 10 亿图文对，机器人最大的数据集才百万条演示。差三四个数量级，短期不可能追上。
- **VLM 出计划 + 小控制器**：就是 C 类。问题在于小控制器没吃过网页数据，「快掉下去的袋子」这种判断传不下去。

## 3. 论文方法

**Q1：主要流程是什么？几个模块？**

```
相机图像 ──ViT──▶ 图像 token
语言指令 ──tokenizer──▶ 文本 token
                ↓
        VLM 语言骨干（自回归）
                ↓
        8 个整数 token（0 132 114 128 5 25 156 200）
                ↓
        反离散化 → 7 维动作（6 位移 + 夹爪）→ 执行约 0.3 秒
                ↓
        重新拍图，回到第一行（闭环）
```

**只有三个模块，而且第三个是 0 参数：**

| 模块 | 干什么 | 参数量 |
|---|---|---|
| ViT | 图像 → patch token | 22B（PaLI-X）/ 4B（PaLM-E） |
| 语言骨干 | 图文联合建模，自回归吐 token | 32B / 12B |
| **动作编码** | 把 8 个数字当 token 用 | **0** |

**Q2：为什么这些模块必须？技术为什么可行？**

- **必须用预训练权重**：表 6 里 5B 模型从零训，泛化只有 9%，等于什么都不会。有预训练权重就是 42%。
- **必须离散成 token**：动作是连续的，但同一个画面有好几种正确做法（多峰），用 MSE 回归会把它们平均成一条撞墙的路线。切成 256 格做分类就没这个问题。
- **为什么可行**：VLM 的输出本来就是「从词表里挑 token」，动作只是「另一种 token」——不需要改结构，只需要约定编码。

**Q3：每个模块对解决问题有什么作用？**

| 模块 / 设计 | 作用 |
|---|---|
| ViT + 语言骨干 | 提供网页学来的语义和常识（「草莓是红的」） |
| 动作 token 化 | 让动作和单词共用输出空间 → 不加参数就能共享知识 |
| **co-fine-tuning（50/50）** | 训动作的时候继续喂网页数据，防止把旧知识忘掉 |
| `terminate` 位 | 让模型自己判断「活干完了」 |

**Q4：什么场景适用？什么场景不适用？**

- **适用**：技能种类少、但物体和场景变化多的任务。抓、放、推、开抽屉——招式就那几种，关键是「对谁做」。
- **不适用**：
  - 需要新动作技能（叠衣服、拧瓶盖、用工具）——训练数据里只有 7 个技能模板
  - 需要高频反馈（擦桌子、倒水）——1–3 Hz 太慢
  - 需要精细操作（插针、拧螺丝）——精度锁死在 bin 宽

**Q5：哪里没做好？你会怎么优化？**

| 问题 | 我会怎么改 | （现实里谁做了） |
|---|---|---|
| 1–3 Hz 太慢 | 一次决策出 50 步动作（action chunking） | π0 |
| 精度锁死在 1/256 | 改回连续动作 + L1 回归 | OpenVLA-OFT |
| 55B 必须上云端 | 换 7B 开源底座 + 量化 | OpenVLA |
| 闭源 | 开源权重和数据 | OpenVLA |

**说白了：这篇的三个坑，2024 年后面三篇论文各填了一个。**

## 4. 论文实验

**Q1：为什么选这些数据集和对比方法？**

- **数据**：直接用 RT-1 那套（13 台机器人、17 个月、约 13 万条示教）。好处是**能干净对比**——数据完全一样，只换底座，涨了多少就是预训练的功劳。
- **对比方法**：四类各挑一个，正好对应 §2 那张表——RT-1（同数据但小模型）、VC-1/R3M（只换视觉表征）、MOO（VLM 当感知）。**这是一个精心设计的对照组，不是随便挑的。**

**Q2：实验设置合理吗？对比公平吗？**

**公平的地方：**

- 所有 baseline 用**完全相同**的机器人数据。
- 涌现能力评测用 A/B testing：四个模型在**完全相同**的条件下一个接一个跑，压低方差。

**可疑的地方（三条）：**

1. **样本量太小**。每组评测只有几十条指令、每条跑 1–5 次，方差极大。证据：5B 模型「未见背景（简单）」那格报了 46%，比 55B 还高——这不可能是能力，就是噪声。
2. **PaLM-E 版的预训练数据可能「作弊」**。论文自己加脚注承认：PaLM-E-12B 的原始预训练里含机器人图像（用于高层 VQA 规划），可能和泛化测试场景相似。
3. **没报置信区间**。62% vs 32% 这种大差距可信，但 44% vs 42% 这种小差距（5B 上 co-fine-tuning 的收益）在这个样本量下没有意义。

**Q3：结论和动机一致吗？有没有挂羊头卖狗肉？**

**一致的部分：**

- 动机说「网页知识能迁移到动作」，实验确实证明了：泛化 2 倍、涌现 3.5 倍。方向对。
- 而且作者很诚实：Limitations 里主动写「**不会获得新动作**」，没有把「涌现」吹成万能。

**有水分的地方：**

- **Seen Tasks 只和 RT-1 打平（91/93 vs 92）。** 也就是说它「没有变强，只是变通」——所有提升都来自语义理解，不来自技能。
- 「涌现」这个词有点营销味。实测是 60%，不是 90%；数学推理只有 25%（PaLI-X）。
- 论文标题写的是 "Transfer Web Knowledge"，但严格说它证明的是「**语义**知识能传，**动作**知识不能传」。这个区分作者在正文里说清楚了，但标题容易误导。

## 5. 总结与思考

**Q1：作为审稿人，三个优点、三个缺点？**

**优点：**

1. **想法极简，可复制**。整个方法就是一条编码约定（动作写成 8 个数字），没有新模块、没有新损失。这种「简单且有效」的工作最有生命力。
2. **实验规模硬**。6000 条真实机器人轨迹，不是仿真、不是 5 个 seed 的小打小闹。这在具身智能里很少见。
3. **诚实**。Limitations 主动承认「不会新动作」「算力是瓶颈」，还点名希望开源模型（LLaVA）变多。

**缺点：**

1. **完全闭源**。代码、权重、数据一样没放。别人既不能复现也不能改进——这是它后来被 7B 的 OpenVLA 追上的直接原因。
2. **工程上不可接受**。1–3 Hz + 必须连云端，断网就瘫痪，没有 fallback。
3. **精度天花板明显**。256 格离散化让动作精度锁死，而且是「分类标签之间没有距离」这种根本性缺陷，不是调参能救的。

**如果我是审稿人，会要求：**

- 补上 5B 上 co-fine-tuning 收益的置信区间（现在那 2 个点的差距站不住）
- 报一下 terminate 的标注流程和一致性
- 至少在 Language-Table 上放代码和权重（那个环境是开源的，没有商业顾虑）

**Q2：学到了什么新奇的东西？**

1. **同一个 token 在不同位置含义不同，能省一大笔**。256 个 token 干 7 个维度的活——如果每维独立要 1792 个，代价大得多。这种「共用词汇表 + 靠位置消歧」的做法很聪明。
2. **图 1 那张三块拼图的画法**。左边「训练数据」、中间「模型」、右边「部署」，底下两条箭头把训练和部署连成一个环——一眼就把整篇论文讲完了。写论文可以学。
3. **一个纯工程 trick 比架构改动收益更大**。co-fine-tuning 就是「机器人数据只占一半，其余继续喂网页数据」，没有任何新结构，但 55B 上值 11 个点。

**Q3：如果交给你做，你会怎么做？**

我不会去碰 55B。

- 底座用 7B 开源模型（Llama 2），因为闭源 55B 最大的问题不是能力不够，是**没法迭代**。
- 数据用 Open X-Embodiment（跨 22 种机器人、350k 轨迹），比 RT-1 那 13 万条多样得多。
- 训练时把 co-fine-tuning 和 action chunking 都加上——前者保泛化，后者保速度。
- 然后跑一个消融矩阵：底座大小 × 数据规模 × 是否 co-finetune × 是否 chunking，看哪个因子最值钱。

（说白了就是 OpenVLA + OFT 的组合。2024 年别人已经做了，说明这个判断不难，难的是有资源做。）

**Q4：一个值得研究的后续想法？**

有个没被认真研究过的点：**视觉 token 和动作 token 的数量比例严重失衡。**

现在一次推理，图像 token 几百个、动作 token 只有 8 个。如果动作也出 chunk（50 步 × 7 维 = 350 个 token），两边就均衡了。

值得问的问题是：**这个比例会不会影响模型学得多好？** 如果视觉 token 远多于动作 token，模型的注意力是不是几乎全花在「看图」上，没多少分给「出动作」？这可以做一个很干净的消融——固定其他变量，只改动作块长度，看动作 token 的准确率怎么变。

这个问题的好处是：不需要大算力（在 LIBERO 这种仿真上就能跑），但结论可能影响所有 VLA 的架构设计。

## 大概率被问到（一句话答案）

**Q：为什么不用扩散模型 / flow matching？**
那是 2024 年才成熟的。RT-2 是 2023 年 7 月的工作，当时主流做法就是离散 token。

**Q：55B 是不是必须的？**
不是。5B 也有 44%，只是泛化差 19 个点。55B 换来的是「更难场景下不崩」，不是「能做更多事」。

**Q：为什么不干脆用 GPT-4V 那种闭源 API？**
2023 年没有支持输出自定义 token 的 API。RT-2 需要能自己控制词表和解码。

**Q：这个和现在的大模型机器人（Gemini Robotics）什么关系？**
同一支团队（DeepMind）的后续。思路一路没变：把动作接进大模型，只是模型换了。

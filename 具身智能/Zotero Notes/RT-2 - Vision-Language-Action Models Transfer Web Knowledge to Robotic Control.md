## 基本情况

- **一句话**：输入「相机图像 + 一句自然语言指令」→ 输出「8 个整数 token」，反解成 7 维动作（末端 6 自由度位姿增量 + 夹爪开合），每维 256 格离散化。
- **开源**：代码、权重、数据**全没放**。这是它后来被 OpenVLA 取代的直接原因——OpenVLA 的第一句动机就是「现有 VLA 基本闭源」。
- **和读过的哪篇最像、差在哪**：和 **OpenVLA** 同属「VLM 直接吐动作 token」这条路，是它的**直系前作**。差别：① 底座用 PaLI-X（5B/55B）/ PaLM-E（12B），全闭源；OpenVLA 用 Llama-2-7B + DINOv2/SigLIP，全开源。② RT-2 动作串是 **8 个 token**（含 `terminate`），OpenVLA 是 **7 个**（砍掉终止位）。③ RT-2 用 **co-fine-tuning**（机器人数据只占 50%–66%），OpenVLA **只用机器人数据**微调，于是灾难性遗忘。
- **一句话定位**：VLA 这个词的出处。它证明的不是「小模型不行」，而是「**网页上学到的语义知识可以绕过语言接口，直接接管低层动作**」。

## ① 动机

### 1.1 任务是什么（具体到一句指令）

办公室厨房里，一台带轮子的机械臂，听一句话收拾桌子：

- `pick up the bag about to fall off the table`（把快要掉下桌的那个袋子拿起来）
- `put the strawberry into the correct bowl`（把草莓放进正确的那只碗）
- `move apple to 3`（把苹果移到数字 3 旁边）

共同点：**技能不复杂**（抓、放、推、开抽屉），**但要求理解场景**。第二句里「正确的那只碗」没说是哪只——得靠常识判断（草莓是红的，红碗配红物）。

### 1.2 以前的两条路都卡在哪

**A. 只用机器人数据硬堆（RT-1 这条路）**

RT-1 用 13 台机器人采了 17 个月、约 13 万条示教，训出 35M 参数的小 transformer。能干 200 多个任务，但：

| 场景 | RT-1 成功率 |
|---|---|
| 见过的任务 | 92% |
| 没见过的物体（简单组） | 31% |
| 没见过的房间 | 26% |

原因很朴素：**模型只在机器人数据里见过世界**。它不知道「可乐罐」「薯片袋」这些词背后是什么东西，只知道这堆像素对应那串动作。

**B. 把 VLM 摆在高层当大脑（SayCan、PaLM-E 这条路）**

VLM 很懂世界，但只会输出文字。于是让它出计划「先走到桌边 → 抓住罐子 → 抬高 → 移到抽屉上方」，再由一个**独立的、专门训的**底层控制器翻译成关节指令。

问题在于：**那个底层控制器一口网页数据都没吃过。** VLM 的常识到这里就被截断——高层知道「那是个快掉下去的袋子」，低层只收到一句 `pick bag`，剩下的全靠自己那点示教数据。

**数据量级的落差是根因：**

| | 规模 |
|---|---|
| 网页图文 | WebLI 100 亿对，筛后 **10 亿** |
| 最大的机器人数据集 | 十万 ~ 百万条演示 |

差三四个数量级。「再采更多机器人数据」短期补不上，只能想办法**借用**网页预训练。

### 1.3 作者的押注

> **动作能不能也当成一种语言？** 把 8 个动作数字当成 8 个英文单词，和「这张图里发生了什么」这种 VQA 题混在一起训，模型自然学会「看到这种画面 + 听到这句话 → 该吐这 8 个数」。**不新增任何参数、不新增任何模块。**

对比一个具体例子，指令 `pick up the bag about to fall off the table`：

- RT-1 见过的指令全长这样：`pick <物体名>`、`move <物体> near <物体>`。它能抽出「pick bag」，但桌上有两个袋子，它没法判断是哪个。
- RT-2 的底座 VLM 在网页上见过无数「东西悬在桌沿、重心偏出去」的照片，所以能把这个短语落到**左边那个半个身子悬空的袋子**上，再复用从机器人数据里学来的 pick 动作。

**核心主张：物理动作还是原来那几种，但「对谁做、在哪做、为什么做」的判断来自网页。**

## ② 架构

### 2.1 三个模块，一个都没新加

![](imgs/rt2/fig-01-中段.png)

图 1 中段放大。从上往下：左上角一个小图像和一行 `Q: what action do the robot take to <task>? A: ...`，两路输入。**蓝色 ViT 框**处理图像，**橙色 LLM 框**里是 token 序列和一根长条（transformer 层堆叠）。

输出端分成两截：左边几个**浅灰蓝小框** = 普通语言 token（它同时还在做 VQA）；最右边**三个紫色小框** = 动作 token。紫色那截引出一条线，落到 `A: 132 114 128 5 25 156` 这个框，再走 `De-Tokenize` 变成 `Robot Action`：`ΔT = [0.1, -0.2, 0]`、`ΔR = [10°, 25°, -7°]`。

**整篇论文的技术内容就在这一条紫线上。**

| 模块 | 来源 / 初始化 | 参数量 | 训练时更新吗 | 作用 |
|---|---|---|---|---|
| ViT | PaLI-X 用 ViT-22B；PaLM-E 用 ViT-4B；PaLI-3B 用 ViT-G/14 | 22B / 4B / 2B | **更新**（全量） | 图像 → patch token |
| 语言骨干 | PaLI-X：encoder-decoder 32B/50 层（类 UL2）；PaLM-E：decoder-only 12B | 32B / 12B | **更新**（全量） | 图文联合建模，自回归出 token |
| 动作编码 | 复用**已有**词表的 256 个 token | **0** | — | 让动作和单词共用输出空间 |

**全部参数参与训练**：没有冻结、没有 LoRA、没有 adapter、没有专门的投影层。论文原话（L54）：

> "the unified output space of our formulation enables model weights to be entirely shared across language and action tasks, **without introducing action-only model layer components**."

两个底座的差别：

- **PaLI-X**：ViT-22B 处理图像 → `n×k` 个 token → projection → **encoder-decoder** 骨干（32B、50 层，类 UL2）自回归输出。
- **PaLM-E**：**decoder-only** LLM（12B），图像经 ViT-4B 投影到语言 embedding 空间，所有东西拼成一条长序列往外吐。

> [!warning] 论文没写清的三件事
> 1. **一次看几帧**：正文完全没提（RT-1 是 6 帧；RT-2 只在 Language-Table 实验里明说用 2 帧连续图像）。
> 2. **坐标系**：动作是基座系还是工具系，没写。图 1 的量纲（0.1 / 10°）暗示位移是米级、角度是度级。
> 3. **底座怎么控**：这台是 7DoF mobile manipulator（L312），但动作串里**没有底座移动的维度**，也没说底座怎么驱动。

### 2.3 八个 token 逐位是什么

**不是「8 维动作」，是 8 个数**：7 个连续量（各分 256 bin）+ 1 个离散二值（不参与量化，见 L81 括号）。

| # | 位 | 物理含义 | 取值 | 图 1 的例子 |
|---|---|---|---|---|
| 1 | `terminate` | 本 episode 是否结束 | **{0,1}，不量化** | 1 |
| 2 | `Δpos_x` | 末端沿 x 平移 | 256 bin | 0.1 |
| 3 | `Δpos_y` | 末端沿 y 平移 | 256 bin | -0.2 |
| 4 | `Δpos_z` | 末端沿 z 平移 | 256 bin | 0 |
| 5 | `Δrot_x` | 绕 x 轴转（roll） | 256 bin | 10° |
| 6 | `Δrot_y` | 绕 y 轴转（pitch） | 256 bin | 25° |
| 7 | `Δrot_z` | 绕 z 轴转（yaw） | 256 bin | -7° |
| 8 | `gripper_extension` | 夹爪张开程度 | 256 bin（0 闭合 → 1 全开） | 0.8 |

- 六个位姿量合起来就是 **6-DoF**：x/y/z 决定手在哪，roll/pitch/yaw 决定手朝哪。
- 旋转用**欧拉角增量，不是四元数**。四元数要 4 个数且有「q 和 −q 同一姿态」的歧义；每步只转一点点，欧拉角增量足够，且天然是 3 个数。
- 夹爪是**张开程度**（连续量），不是开/关二值，能表达「半开」。

> [!important] `terminate` 是干什么的
> **让机器人自己说「我干完了」**。数据组织：一条示教走 100 步，前 99 步 `terminate=0`，最后一步标 `1`。于是模型在学「该往哪走」的同时也在学「什么时候该停」。
>
> 为什么必须有：**「任务完成」是个判断，不是一个动作**。罐子进抽屉之后该干什么？没有终止概念的策略会继续按分布采样——可能松手、可能往回缩、可能再推一下。人工评测时「放进去后稳稳停住」和「放进去后又抖一下碰倒」，成功率差别是实的。
>
> 风险：可能**过早**吐 1。

### 2.4 动作怎么塞进词表（五步）

**第一步：连续值 → 整数。** 7 个维度各自把取值区间均匀切成 256 格，落进第几格就是那个整数 `b ∈ [0,255]`。

```
假设 Δpos_x 归一化到 [-1, 1]
bin_width = (1 - (-1)) / 256 = 0.0078125
某一步 Δpos_x = 0.035
落格： (0.035 - (-1)) / 0.0078125 = 132.48  → 取整 132
```

132 就是图 1 里那一串 `132 114 128 5 25 156` 的第一个——**图就是按这个算的**。RT-2 只写「uniformly into 256 bins」（L81），**没写区间怎么定**；OpenVLA 后来改成用训练数据的 1%–99% 分位数当区间。

**第二步：8 个数拼成一句「话」。** 用空格连起来，比如 `"0 132 114 128 5 25 156 200"`。**模型眼里这是一句话，不是一串标签**。

**第三步：整数 → 已有词表里的某个 token。** 两种做法，RT-2 两条都用过：

- **做法 A（PaLI-X 走这条）——白拿**：PaLI-X 的 tokenizer 里，1000 以内的整数**每个都有独立 token**。bin 132 → token `"132"`，**一个字符都不用改**。
- **做法 B（PaLM-E 走这条，OpenVLA 抄的是这条）——覆盖**：PaLM-E 没有这个便利，就把**最不常用的 256 个 token** 原来的含义扔掉，改当 bin 0…255 用。

为什么选「最不常用」的？改掉它们对语言能力损伤最小。那些 token 原本是「ß」「▁▁▁」这类奇怪子词，网页语料里几乎不出现。

**第四步：token id → 嵌入矩阵的那一行。** 这一步是「不加参数」的真正含义：

```
嵌入矩阵  E ∈ R^(V × d)      V=词表大小（Llama 2 约 32000）, d=4096
token id 31000  →  E 的第 31000 行  →  一个 4096 维向量
```

被覆盖的那 256 个 id，**对应的行一直都在**，只是这 256 行原来记的是「某个奇怪子词长什么样」，现在要被训练成「bin 0 长什么样、bin 1 长什么样……」。所以不是「新增 256 个 token」，是「**把 256 个现成的格子重新指派用途**」。参数量一点没变。

**第五步：解码与反离散化。** 推理时到了该出动作的位置，**只在 256 个动作 token 上做 softmax**（output constraint；不加这条，模型可能吐出一个「的」字）。取概率最大的 `b`，再还原：

```
value = low + (b + 0.5) × bin_width
     = -1 + (132 + 0.5) × 0.0078125 = 0.0352
```

> [!warning] token 本身不带单位
> `132` 这个 token 不携带任何物理意义。想知道它对应多远，必须查这一维的归一化边界。**所有尺度信息都外挂在训练数据的统计量上，模型里没有。**

### 2.5 256 个 token 是总数，7 个维度共用

最容易误解的一点。

```
如果是「每维各 256 个」：  7 维 × 256 = 1792 个 token
论文实际的「总共 256 个」：  256 个 token，7 个维度共用
```

论文原话是 *"reserving **256 tokens** to serve as action tokens"*（L81），256 是**总数**。PaLM-E 那边也是「覆盖最不常用的 **256** 个」。

**共用怎么运作**：同一个编号在不同位置上含义不同。

| 动作串里的位置 | 出现 token `132` | 物理含义 |
|---|---|---|
| 第 2 位（Δpos_x） | 是 | x 方向落在第 132 格 |
| 第 3 位（Δpos_y） | 同一个 id、同一个嵌入向量 | y 方向落在第 132 格 |

**模型靠自回归的「位置」区分**：写第 2 个 token 时，上下文里已经有 `terminate` 了，它知道「我现在在写 x 方向」。

为什么这么设计：**① 省词表开销**（覆盖 256 个低频 token 无害，覆盖 1792 个就要动中频词）；**② 正好够用**（每维切 256 格，档位编号本身就是 0…255，天然对齐）。

代价：**同一个编号在不同维度对应的物理量不一样**（归一化范围不同，单位一个是米、一个是弧度、一个是百分比）。这也是为什么动作串的顺序绝对不能乱——第 2 位永远是 x，第 5 位永远是 roll。

> [!tip] 三个容易混的数
> | 说法 | 数值 | 是什么 |
> |---|---|---|
> | bin（格） | 256 | **每个**连续维度被切成的格子数 |
> | 动作 token | 256 | 词表里被征用的 token 数，与 bin 一对一 |
> | 动作串长度 | **8** | 一次决策吐出的 token 数（7 连续位 + 1 terminate） |
>
> 一次推理 = **8 个位置，每个位置在 256 个候选里选一个，共 8 次 256 路分类。**

### 2.6 为什么不能更简单

**最朴素的做法**：在 VLM 屁股后面接一个专门的动作头（MLP），拿最后一层 hidden state 回归 7 维连续动作。这是所有人的第一反应，也是 CLIPort / MOO 那类工作的思路。

作者不这么做的理由是**「统一输出空间」**：加了动作头，动作就有自己的一套参数，语言任务和动作任务不再共享权重，VLM 的网页知识得先挤进一个小 MLP 再出来。

**我推测**还有第二个原因作者没写：回归连续动作在模仿学习里会遇到**多峰**问题（同一画面有好几种正确做法，MSE 会平均成一条撞墙的中间路线）。离散成 256 个 bin 做分类就绕开了平均。

**那干脆别用 VLM、从头训个大的呢？** 表 6 直接回答：5B 模型 from scratch 泛化平均 **9%**，跟什么都不会差不多；同一个 5B 换成微调预训练权重就 **42%**。**参数再多也换不来网页知识。**

## ③ 训练

### 3.1 损失：就是最简单的下一词预测

**这篇论文里没有损失函数的公式。** 唯一的 align 公式（L82–84）是那串动作字符串的**格式**，不是损失。损失只有附录 E 的一句话（L319）：

> "Both models are trained with the next token prediction objective, **which corresponds to the behavior cloning loss in robot learning**."

人话：**训练数据里的「正确答案」就是示教里人类操作员当时做的那个动作串，让模型一个 token 一个 token 猜，猜错按交叉熵扣分。** 就这么一句话，没有技巧。

标准写法（论文没写，这里补全）：

$$
\mathcal{L}(\theta) = -\sum_{t=1}^{8} \log \pi_\theta\left(y_t \mid y_{<t}, o, \ell\right)
$$

| 符号 | 是什么 | 形状 / 取值 |
|---|---|---|
| $\theta$ | 全部参数（ViT + 骨干），**全量更新** | 5B ~ 55B |
| $o$ | 相机图像 | 论文没写分辨率 |
| $\ell$ | 语言指令 | 一句 |
| $y=(y_1\ldots y_8)$ | 示教里的**正确动作串** | 8 个 token id |
| $\pi_\theta(y_t \mid \cdot)$ | 前 $t-1$ 个 token 之后，第 $t$ 位给出正确 token 的概率 | softmax over 全词表 |

**代一组数字。** 正确动作串 `[0, 132, 114, 128, 5, 25, 156, 200]`，模型给的各位置概率：

```
位置:    1     2     3     4     5     6     7     8
p:     0.90  0.60  0.85  0.70  0.50  0.55  0.45  0.80

L = −[ ln0.90 + ln0.60 + ln0.85 + ln0.70 + ln0.50 + ln0.55 + ln0.45 + ln0.80 ]
  = −[−0.105 −0.511 −0.163 −0.357 −0.693 −0.598 −0.799 −0.223 ]
  = 3.45        （平均每 token 0.43）
```

好还是坏？对照瞎猜：每位置在 256 格里随机选，每 token 损失 $\ln 256 = 5.545$，8 个位置 **44.4**。所以 3.45 说明基本猜对了——第 2、5、7 位概率偏低，正是它还在犹豫的地方。

### 3.2 三个训练选择（不是三个阶段）

RT-2 没有「预训练 → 后训练 → 精调」这种多阶段流程（π0 才有），**就是一锅混着训到底**。三个选择决定成败：

**① 数据配比：机器人数据只占 50%（或 66%）。** 论文最重要的技术贡献。naïve 做法是只拿机器人数据微调（OpenVLA 就这么干）。RT-2 把原来 VLM 的网页 VQA 数据也一起喂，机器人数据通过提高采样权重占住一半：

- RT-2-PaLI-X：机器人数据 ≈ **50%**
- RT-2-PaLM-E：机器人数据 ≈ **66%**

（§B L292）论文给的理由只有一句：*"keeping the original data around... allows the model to not forget its previous concepts learned during the VLM training."*

**② 全参数更新，不冻结。** 没有 LoRA / adapter / 冻结 ViT。55B 全部参与训练。（OpenVLA 的消融也印证：冻结视觉编码器会从 80% 掉到 46.7%。）

**③ 推理时的词表约束（output constraint）。** 训练完，模型在动作位置上理论上可以吐任何 token（包括「的」「apple」）。所以推理时加一条：**只要 prompt 是机器人任务，就只在 256 个动作 token 上采样**；处理普通 VQA 时放开全词表。

### 3.3 为什么用交叉熵而不是 MSE

> [!important] 因果顺序要摆正
> **不是「动作离散化了所以用交叉熵」，而是「要用交叉熵（避免多峰被平均掉）所以必须先离散化」。** 离散化是手段，交叉熵是目的。

**最朴素的做法**：网络输出 7 维浮点向量，用 MSE 逼近示教动作。简单、直接、输出连续值。

**它为什么不行**：同一个画面，示教里有好几种都正确的做法。

```
示教A: 从左绕  ← ─ ┐
示教B: 从右绕  ← ─ ├── 取平均 ──→ 直着撞过去（错）
示教C: 从右绕  ← ─ ┘
```

这叫**多峰问题**（multimodal，一个输入对应多个合法输出）。MSE 的最优解永远是**条件均值**，在多峰分布上就是最差的那个点。

**具体例子**：把罐子往右挪到杯子旁，桌上左边有碗挡着。10 条示教里 6 条从左绕（Δy ≈ −0.15）、4 条从右绕（Δy ≈ +0.15）。

- **MSE**：预测 `Δy = 0.6×(−0.15) + 0.4×(+0.15) = −0.03 ≈ 0`，**直着推过去撞碗**。这个 −0.03 在 10 条示教里一条都没出现过，但它确实让 MSE 最小。
- **256 bin + 交叉熵**：模型输出「bin 96 概率 0.62、bin 160 概率 0.35、其余 254 个 bin 共 0.03」，采样取 bin 96 → Δy = −0.15，**落在真实走过的那条路上**。

**代价（也很硬）**：分类标签之间**没有距离概念**。对交叉熵来说，猜成 bin 133 和猜成 bin 7 一样错。

| 两个动作 | 差多少 | 交叉熵眼里 |
|---|---|---|
| −0.1500 vs −0.1499 | 0.0001 | 同一格，完全一样 |
| −0.1500 vs −0.1562 | 0.0062 | **相邻格 = 完全不同的类** |
| −0.1500 vs +0.1500 | 0.3 | 不同类 |

精度被锁死在 bin 宽上，而且模型学不到「接近」这个概念。**这就是后来 π0 用 flow matching、OpenVLA-OFT 改回连续回归的真正动机——不是嫌离散化麻烦，是嫌它丢掉了动作的连续结构。**

### 3.4 消融：co-fine-tuning 到底值多少

只测泛化（seen tasks 被剔除）：

| 规模 | 训练方式 | 未见物体 E/H | 未见背景 E/H | 未见环境 E/H | **平均** |
|---|---|---|---|---|---|
| 5B | from scratch | 0 / 10 | 46 / 0 | 0 / 0 | **9** |
| 5B | fine-tuning | 24 / 38 | 79 / 50 | 36 / 23 | **42** |
| 5B | **co-fine-tuning** | 60 / 38 | 67 / 29 | 44 / 24 | **44** |
| 55B | fine-tuning | 60 / 62 | 75 / 38 | 57 / 19 | **52** |
| 55B | **co-fine-tuning** | 70 / 62 | 96 / 48 | 63 / 35 | **63** |

三个结论，从硬到软：

1. **从头训 = 白训。** 5B 从零训练平均 9%。注意它「未见背景 Easy」有 46%——这种孤立高分是**噪声**（每组只几十条指令、跑几遍，方差极大），不是能力。作者自己也不敢碰 55B 的 from scratch。
2. **模型规模是实的。** 同样训练方式，55B 比 5B 高 10–19 个点。
3. **co-fine-tuning 在 5B 上「几乎没用」，在 55B 上「很有用」。** 论文没讨论这一点：
   - 5B：44 vs 42，只差 2 点，而且逐项**互相抵消**——未见物体 Easy 从 24 涨到 60（大涨），未见背景 Easy 从 79 **掉到** 67（大跌）。**2 点的平均差在这个评测规模下不显著。**
   - 55B：63 vs 52，差 11 点，六项里五项都更好。这个是实的。

> [!question] 我的解读（推测，未验证）
> 5B 的容量装不下「既要保持网页知识、又要学会动作」，混训互相挤占；55B 有富余容量，混训才真正起「防遗忘」作用。这个解释对不对，得看更大规模上的同款消融——OpenVLA 没做。

## ⑤ 输入输出信息流

### 5.1 一次推理

```
相机图像 ──ViT──▶ 图像 token（几十~几百个）
指令 ──tokenizer──▶ 文本 token（~20 个）
                    │
                    ▼
            [ VLM 骨干：处理前缀 ]
                    │
        ┌───────────┴────────────┐
        │  自回归 8 步，一步一个 token │
        │  "0" → "132" → "114" → … │   ← 串行，不能并行
        └───────────┬────────────┘
                    ▼
        只在 256 个动作 token 上采样（output constraint）
                    ▼
        反离散化 → 7 维动作 → 机械臂执行约 0.3 秒
                    │
                    └──▶ 重新拍图，回到第一行（闭环）
```

两个关键点：

- **8 个 token 是串行生成的**，一次推理要 8 个解码步，这就是 1–3 Hz 的直接来源。
- **训练和推理几乎一样**，唯一差别：训练时答案白给（直接算 loss），推理时要自己采样，且只在 256 个动作 token 里选。

### 5.2 云端大脑：为什么只有 1–3 Hz

> [!important] 这是全文最被后人诟病的设计
> 55B 半精度权重约 110 GB，机载计算单元装不下。论文的方案是**部署在多 TPU 云服务上，通过网络查询**（§3.3），同时服务多台机器人。

**频率低不能全怪参数，这是个乘法关系：**

```
控制频率 ≈ 1 / (一次前向 × 解码步数 + 网络往返 + 图像传输)

55B 的一次前向          慢
× 8 个 token 自回归解码   要串行做 8 遍
+ 云端网络往返
= 300 ~ 1000 ms  →  1–3 Hz
```

**「8 次串行解码」是结构性负担**，躲不开——没有 action chunking，机器人每挪一小步都要完整走一遍「拍照 → 传云端 → 跑 8 个解码步 → 传回来 → 执行」。这就是它做不了「擦桌子」「拧瓶盖」这类需要连续细密反馈的活的根本原因。

论文没写、但实际存在的三个代价：

1. **网络进到了控制回路里**。抖动（jitter）比平均延迟更致命——策略按固定时间间隔训练，实际间隔忽长忽短，动作平滑度直接崩。
2. **断网即瘫痪**。55B 的机器人连「停住」都要靠云端算，没有 fallback。
3. **单点故障**。「一个服务带多台机器人」反过来就是「服务挂了全部趴下」，而且它们共享同一策略，遇到同一个分布外场景会同时出错。

作者在 Limitations 里只承认了一半：*"the computation cost of these models is high... real-time inference may become a major bottleneck"*，把希望寄托在**量化、蒸馏**上。没提可靠性和网络。

> [!note] 2026 年回头看，这条路已经拐弯了
> 现在主流 VLA 都往**本地单卡**跑，四条路各解决一个因子：
>
> | 做法 | 解决哪个因子 | 代表 |
> |---|---|---|
> | 模型做小 | 前向变快 | SmolVLA（450M） |
> | **action chunking** | **消掉「每步都要问」（最关键）** | π0 一次出 50 步，3B 跑 50 Hz |
> | 并行解码 / 连续回归 | 消掉 8 次串行解码 | OpenVLA-OFT（26× 吞吐） |
> | 量化 / 蒸馏 | 压缩权重 | int4 部署 |
>
> action chunking 把「每次决策要多久」和「控制频率多高」**解耦**了。RT-2 是「决策一次 = 走一步」，π0 是「决策一次 = 走 50 步」。**RT-2 必须上云，不是它不能接受慢，而是它的架构让「慢」直接等于「动作卡顿」。**

## ⑥ 例子走一遍

场景用论文 §4.2 的真实例子：**`put the strawberry into the correct bowl`**（桌上一红一蓝两只碗，旁边还有香蕉、苹果）。

**t = 0**

1. 相机拍到：草莓在左、红碗在中、蓝碗在右、几个干扰水果。
2. 拼 prompt：`Q: what action should the robot take to put the strawberry into the correct bowl? A:`
3. ViT 编码图像 → 图像 token；指令 tokenize → 文本 token；两者拼成前缀，送进骨干。
4. 骨干把前缀过一遍（最耗时），然后自回归：
   - 第 1 位 → `0`（还没完）
   - 第 2 位 → `60`（Δpos_x 落在第 60 格 → 往左微移，朝草莓去）
   - 第 3 位 → `128`（Δpos_y ≈ 0）
   - 第 4 位 → `75`（Δpos_z 往下）
   - 第 5–7 位 → `255 255 255`（三个旋转取端点，示意「不变」）
   - 第 8 位 → `240`（夹爪几乎全开）
5. 反离散化 → 7 维动作 → 机械臂执行约 0.3 秒（手伸向草莓）。

**t = 1（重新拍图）**

6. 草莓不在原处了，图像 token 全变。
7. 这一轮第 8 位变成 `90`（夹爪闭合到一半，正在抓）。

**t = 2 … 之后**

8. 抓到之后，第 2–4 位变成朝红碗方向的位移；第 8 位保持「闭合」附近。
9. 某一轮第 1 位变成 `1`（terminate）→ **停止**，episode 结束。

**它凭什么知道是「红色的」那只碗？** 训练数据里从来没有「把草莓放进同色碗」这种指令。这是从网页数据里带过来的常识——草莓是红的、水果通常配同类。**这就是论文说的「涌现」：动作是新组合的，知识是旧的。**

（第 4–9 步的 token 值是示意，不是真跑出来的；论文没公开权重，也没给逐步的 token 序列。）

### 7.5 局限

作者承认的三条：

1. **不会新动作。** 物理技能锁在那 7 个模板里，网页预训练只帮它「换个方式用旧技能」。
2. **慢且贵。** 1–3 Hz，55B 必须云端跑。作者预测「实时推理会成为主要瓶颈」，指向量化 / 蒸馏。
3. **能用的大 VLM 太少。** 希望更多开源模型（文中点名 LLaVA）和商业模型开放微调 API。

附录 G 的失败案例：抓特定部位（比如把手）、训练数据里没有的新动作（擦桌子、用工具）、灵巧动作（叠毛巾）、需要多层间接推理的指令。Language-Table 里典型失败是**推的动力学没学会**——笔直接从桌上滚下去，香蕉的重心和接触点对不上。

> [!warning] 作者没说、但更致命的：闭源
> 代码、权重、数据全没放。别人既没法复现，也没法改进。**这直接导致了 OpenVLA 的出现**——OpenVLA 的第一句动机就是「现有 VLA 基本闭源」。

### 7.6 这篇的地位

RT-2（2023.07）是「动作即 token」这个范式的**奠基工作**，后续所有 VLA 都在它框架里。但它自己的影响力主要体现在**提出范式**，而非被直接使用：

- **2023.10 RT-2-X**：续作，55B，换成跨 22 种机器人的 Open X-Embodiment 数据（350k 条轨迹）。
- **2024.06 OpenVLA**：7B 全开源，在 Google Robot 那几个任务上已能打平 RT-2-X。**七分之一的参数，靠的是更大数据 + 全开源带来的迭代速度。**
- **2024.10 之后 π0 / OFT**：改用 flow matching 或 L1 回归 + action chunking，把 1–3 Hz 的问题解决掉，精度也上去了。

**真正遗产两条：① 动作可以复用词表（不加参数）；② co-fine-tuning（机器人数据只占一半）。** 第二条尤其重要——OpenVLA 因为省了它，语义泛化至今打不过 RT-2-X 系列。

## 延伸笔记（论文之外）

### 交叉熵 vs MSE：为什么分类不用 MSE

| | MSE | 交叉熵 |
|---|---|---|
| 输出假设 | 实数，误差服从**高斯** | 概率分布，**多项分布** |
| 度量 | 欧氏距离 | 分布错位（= 熵 + KL） |
| 最优解 | **条件均值** | **完整的条件分布** |
| 多峰数据 | 均值落在谷底 → 撞墙 | 保留每个峰 → 采样即可 |
| 梯度 | 带 $\hat y(1-\hat y)$ 因子，容易消失 | $\hat y - y$，干净 |
| 有界吗 | 有（≤1） | 无上界 |
| 分辨率 | 连续，无上限 | 锁死在 bin 宽 |

**梯度那条最硬。** 二分类、真值 $y=1$：

$$
\frac{\partial \mathcal{L}_{\text{MSE}}}{\partial z} = 2(\hat y - y)\cdot \hat y(1-\hat y)
\qquad
\frac{\partial \mathcal{L}_{\text{CE}}}{\partial z} = \hat y - y
$$

| 预测 $\hat y$ | 交叉熵梯度 | MSE 梯度 | 差 |
|---|---|---|---|
| 0.01（几乎全错） | **−0.99** | −0.0196 | **50×** |
| 0.10 | −0.90 | −0.162 | 5.6× |
| 0.50 | −0.50 | −0.250 | 2× |
| 0.90 | −0.10 | −0.018 | 5.6× |
| 0.99 | −0.01 | −0.0002 | **50×** |

**模型错得最离谱的时候，MSE 给它的梯度只有 0.02，几乎等于不学。** 因为 $\hat y(1-\hat y)$ 在 $\hat y$ 贴近 0 或 1 时趋近零，把梯度掐掉了。

那个「约掉」不是巧合：交叉熵和 sigmoid / softmax 在数学上是**配对**的（canonical link，来自指数族理论）。用它们搭配，梯度必然化简成「预测减真值」；一旦换搭配（MSE + sigmoid），就必然多出抑制因子。

> [!warning] 「梯度消失」这个说法有一处不精确
> | | 经典梯度消失 | 这里 |
> |---|---|---|
> | 位置 | **层层叠加**，每层导数 < 1 连乘几十次 | **单个位置**：输出层饱和 |
> | 原因 | 网络的**深度** | 激活函数的**形状** |
>
> 严格说 MSE+sigmoid 的问题是**「输出层饱和导致梯度被压制」**，不是「网络太深传不回去」。因为两者都是「小量相乘 → 梯度趋零」，教科书常归到同一个名字下。**这个区分有用**：如果是「网络太深」，换 ResNet / BatchNorm / ReLU 能救；MSE 的问题换这些都没用。

### KL 散度：非负性与单向性

$$
\text{KL}(p \,\|\, q) = \sum_x p(x)\log\frac{p(x)}{q(x)}
$$

**非负（Jensen）**：KL = $\mathbb{E}_p[-\log(q/p)]$，$-\log$ 是凸函数，

$$
\mathbb{E}_p\!\left[-\log\frac{q}{p}\right] \ge -\log \mathbb{E}_p\!\left[\frac{q}{p}\right] = -\log \sum_x q(x) = -\log 1 = 0
$$

等号只在 $p = q$ 时取。

**和交叉熵的关系**：$H(p,q) = H(p) + \text{KL}(p\|q)$。分类标签是 one-hot，**one-hot 的熵是 0**，所以**交叉熵 = KL 散度**。这就是「只算正确类别那一项」的化简的根子——不是因为交叉熵「擅长处理 one-hot」，而是答案那边的熵本来就为零。

> [!important] KL 是单向的：只罚「漏」，不罚「多」
> | 情况 | 项 | 结果 |
> |---|---|---|
> | **真实会发生（$p>0$），模型判死刑（$q=0$）** | $p\log(p/0)$ | **$+\infty$，重罚** |
> | **真实不可能（$p=0$），模型留了余地（$q>0$）** | $0\log(0/q)$ | **0，不罚** |
>
> 最小化 $\text{KL}(p_{\text{data}} \| p_{\text{model}})$ 时，模型**必须覆盖所有在数据里出现过的做法**，但可以在没出现过的动作上乱撒概率。这叫 **mode-covering**——正好是 RT-2 想要的：左绕、右绕都得留着。

### 离散 vs 连续：真正的分水岭是单峰还是多峰

**「连续动作就必须用 MSE」是错的。** 交叉熵在连续分布上的对应物是**负对数似然**，关键在你假设什么分布：

| 假设 | NLL 长什么样 | 能处理多峰吗 |
|---|---|---|
| **单个高斯** | 化简后就是 **MSE**（加方差项） | ❌ 退化成均值 → 撞墙 |
| **高斯混合（GMM）** | 要同时学「几个峰、在哪、各占多少权重」 | ✅ 能，但训练不稳 |
| **256 个自由类别** | 交叉熵 | ✅ 隐式 256 个峰，最简单 |

**单峰高斯假设下的 NLL 恰好就是 MSE。** 所以失败的原因不是 MSE 这个名字，而是它隐含的单峰假设。

> [!note] diffusion / flow matching 是第四条路
> π0 那类方法不用显式分布，而是训一个「去噪」网络，训练时用 MSE（预测噪声或速度）。但**输入里带了随机噪声和噪声水平**，多峰被「初始噪声」吸收了——采样时从不同随机种子出发，落到不同峰上。**所以它们能用 MSE，不是解决了多峰，而是把多峰问题转移到了采样阶段。**

### RT-2 vs OpenVLA 逐项对照

| | RT-2（PaLI-X） | RT-2（PaLM-E） | OpenVLA |
|---|---|---|---|
| 底座 | ViT-22B + UL2 32B | ViT-4B + PaLM 12B | DINOv2 + SigLIP + Llama 2 7B |
| bin 边界 | 均匀 256 bin，区间未写明 | 同左 | 训练数据 **1%–99% 分位** |
| 动作维度 | **8**（含 terminate） | 8 | **7**（无 terminate） |
| 词表处理 | 直接借整数 token `"0"`…`"255"` | 覆盖最不常用 256 个 | 覆盖 Llama 词表最后 256 个 |
| 为什么这么处理 | 整数 token 天然存在 | tokenizer 无整数 token | Llama 只预留 100 个 special token |
| 训练数据 | 机器人 + 网页 **co-fine-tune** | 同左 | **只用机器人数据** |
| 损失 | next-token prediction | 同左 | 同左，**只在动作 token 上算 CE** |
| 推理 | 云端 TPU，1–3 Hz | 云端 | 本地单卡，约 6 Hz |
| 开源 | ❌ | ❌ | ✅ 权重 + 代码 + 数据 |

三处实质差别，从轻到重：

1. **bin 边界**：OpenVLA 唯一真正改良的地方（分位数法自适应数据分布）。
2. **7 维 vs 8 个 token**：OpenVLA 砍掉 `terminate`。它把 22 个异构数据集混在一起训，各家 episode 的结束条件不统一（步数上限 / 手动停 / 失败也停），terminate 标注语义不一致反而是噪声。代价是失去「自己判断干完了」的能力。
3. **不 co-fine-tune —— 影响最大**：OpenVLA 只用机器人数据微调，结果**灾难性遗忘**，语义泛化打不过 RT-2-X。

> [!tip] 一个反直觉的细节
> PaLI-X 借的是**整数 token**，`"132"` 在 VQA 预训练里被大量用过（数学题、日期、计数），嵌入里已经编码了「一百三十二比一百三十一大」这类信息，**bin 132 和 bin 133 在嵌入空间里可能本来就比较近**。
>
> OpenVLA 覆盖的是**低频子词 token**（比如「ß」），它们在嵌入空间里毫无关系，bin 之间的关系得**完全从零学**。
>
> 这可能意味着「借整数」在动作连续性上是更友善的初始化。**但这是推测，论文没做这个消融。**

## 问答记录

**Q：动作到底怎么塞进词表？**
连续值先按 256 格切成整数，再从词表里借 256 个 token 当格子编号。PaLI-X 直接借整数 token（0~255 本来就有），PaLM-E 没这个便利，就把最不常用的 256 个 token 覆盖掉。关键是这些 id 对应的嵌入行本来就在，训练时只是把「某个奇怪子词长什么样」改成「第几格长什么样」——参数量一点没变。

**Q：这套做法和 OpenVLA 一样吗？**
框架完全一样，OpenVLA 原文就写了 follow Brohan et al.，而且抄的是 PaLM-E 那条「覆盖低频 token」的路。三处差别：OpenVLA 用 1%–99% 分位数定 bin 边界、动作只有 7 维（砍了 terminate）、而且不 co-fine-tune。

**Q：七维具体是哪七维？OpenVLA 少的第八个是什么？**
三个平移、三个旋转（欧拉角增量）、一个夹爪张开程度——这是 7 个连续量。RT-2 多的第八个是 `terminate`，二值的，让模型自己说「干完了」。OpenVLA 砍它是因为 22 个数据集各家结束条件不统一（步数上限、手动停、失败也停），标不准反而成噪声。

**Q：256 个 token 是每个维度各 256 个吗？**
不是，总共就 256 个，7 个维度共用一套。同一个编号在不同位置含义不同，模型靠「我现在在写第几位」区分。要是每维独立就得 1792 个，那覆盖最不常用 token 的代价就太大了。

**Q：是不是把大脑搬到云端，因为参数太大？**
是，55B 在机载 GPU 上放不下，论文直接部署在多 TPU 云服务上。但频率只有 1–3 Hz 是两个因子相乘：模型大，**加上每步都要问一次**（没有 action chunking）。代价是网络进了控制回路、断网就瘫痪、单点故障。

**Q：交叉熵和 MSE 的区别？为什么分类不能用 MSE？**
MSE 量欧氏距离、隐含高斯假设；交叉熵量两个分布的错位、对应多项分布。最硬的理由是梯度：MSE 配 sigmoid 会被 `ŷ(1−ŷ)` 掐住，错得最离谱（ŷ=0.01）时梯度只有 0.02，反而几乎不学；交叉熵的梯度就是 `ŷ−y`，错多少推多少。另外 MSE 有上界，不重罚「自信地错」。

**Q：是因为交叉熵处理 one-hot 比较好吗？**
基本对，但因果反了。不是「好处理所以适合」，是它本来就在量分布差距，one-hot 只是分类标签这种特殊分布。化简只是让它算起来便宜——换成软标签它照样能用，只是不能化简成一项，这就是证明。

**Q：KL 散度是什么？为什么一定非负？**
量的是「用 q 近似 p，平均要多付多少代价」。非负由 Jensen 不等式保证，p=q 时取 0。它还是**单向**的：真实会发生而模型判了死刑（p>0, q=0）罚无穷大，真实不可能而模型留了余地（p=0, q>0）不罚——所以最小化 KL 时模型倾向给所有可能都留一点概率，这正好是 RT-2 要的。

**Q：离散化的动作更适合交叉熵吗？**
因果要反过来：不是「离散了所以用交叉熵」，是「要用交叉熵（避免多峰被平均掉）所以必须离散」。真正的分水岭不是离散还是连续，是**单峰假设还是多峰假设**——单峰高斯的负对数似然化简下来恰好就是 MSE。

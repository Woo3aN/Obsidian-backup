# OpenVLA: An Open-Source Vision-Language-Action Model

> **一句话概述**：OpenVLA 是一个 70 亿参数、完全开源的视觉-语言-动作（VLA）模型，它把融合 DINOv2 与 SigLIP 视觉特征的 Llama 2 7B 视觉语言模型在 Open X-Embodiment 的 97 万条真实机器人演示上微调，从而成为能开箱即用控制多种机器人本体、并可借助 LoRA 等参数高效方法快速适配新任务的通用操作策略。(Kim 等, 2024)

## Summary（摘要）

- **问题**：现有 VLA 大多闭源、且缺乏面向新机器人/新任务的微调最佳实践。
- **方案**：7B 参数的 OpenVLA，在 Open X-Embodiment 的 970k 条真实演示上微调 Prismatic-7B VLM。
- **结果**：在 29 项任务上比 55B 的 RT-2-X 高 16.5% 绝对成功率（参数量少 7 倍）；多任务微调比从零训练的 Diffusion Policy 高 20.4%。
- **开源**：模型、部署/微调 notebook 与训练代码库全部开放。

## Key Findings（主要发现）

| 对比项 | RT-1-X | Octo | RT-2-X | OpenVLA |
| --- | --- | --- | --- | --- |
| 参数量 | 35M | 93M | 55B | 7B |
| WidowX 平均成功率 | 18.5% | 20.0% | 50.6% | **70.6%** |
| Google Robot 平均成功率 | 33.3% | 26.7% | 78.3% | **85.0%** |

| 量化精度 | Bridge 成功率 | 显存 |
| --- | --- | --- |
| bfloat16 | 71.3% | 16.8 GB |
| int8 | 58.1% | 10.2 GB |
| int4 | 71.9% | 7.0 GB |

- RT-2-X 在语义泛化上更强（作者归因于更大规模互联网预训练 + 机器人数据与互联网数据联合微调）；OpenVLA 在其余所有任务类别上相当或更好。
- OpenVLA 的整体优势归因于更大训练集（970k vs 350k 轨迹）、更细致清洗（如过滤 Bridge 数据集的全零动作）与融合视觉编码器。
- LoRA 以仅 1.4% 可训练参数达到与全量微调相当的性能；rank 影响可忽略（推荐 r=32）。

## Methodology（方法）

### 3.1 Preliminaries: Vision-Language Models
近期 VLM 由视觉编码器、投影器与 LLM 骨干三部分组成，以下一文本词元预测端到端训练。OpenVLA 基于 **Prismatic-7B**（600M 视觉编码器、2 层 MLP 投影器、7B Llama 2），其 SigLIP 与 DINOv2 特征按通道拼接，DINOv2 带来的空间信息被认为对机器人控制尤其有用。

### 3.2 OpenVLA Training Procedure
- 形式化为"视觉-语言"任务：动作预测映射为文本 token 序列。
- 每个动作维度离散化为 **256 个 bin**，宽度按训练数据动作的 **1st–99th 分位数**均匀划分（而非 min-max），以规避离群动作拉宽区间、降低有效粒度。
- Llama 分词器只留 100 个特殊词元，故直接覆写词表中最少使用的 256 个词元作为动作词元。
- 只对预测动作词元计算交叉熵。

### 3.3 Training Data
以 OpenX 为基础，过滤为至少含一个第三人称相机、使用单臂末端控制的操控数据集，并沿用 Octo 的数据混合权重。曾以 10% 保守权重加入 DROID，但因动作词元准确率始终偏低，在训练最后三分之一阶段移除。

### 3.4 OpenVLA Design Decisions
- **骨干**：Prismatic 在单物体与多物体语言接地任务上都优于 LLaVA（LLaVA 又比 IDEFICS-1 高 35%），归因于 SigLIP-DINOv2 融合的空间推理能力。
- **分辨率**：224×224 与 384×384 无性能差异（后者训练慢 3 倍）→ 选 224。
- **视觉编码器**：必须微调，冻结会明显掉点。
- **训练轮次**：27 个 epoch，token 准确率超 95% 后性能仍在涨。
- **学习率**：固定 2e-5，预热无收益。

### 3.5 Infrastructure for Training and Inference
64 张 A100 训练 14 天（21,500 A100-hours，批大小 2048）。推理 bfloat16 需 15GB 显存、单张 RTX 4090 上约 6Hz；附带远程推理服务器。

## 实验（Experiments）

### 5.1 Direct Evaluations on Multiple Robot Platforms
BridgeData V2 WidowX 17 任务×10 试次 = 170 次推演；Google Robot 12×5 = 60 次。OpenVLA 在 WidowX 平均 **70.6%**，Google Robot **85.0%**。

### 5.2 Data-Efficient Adaptation to New Robot Setups
Franka-Tabletop / Franka-DROID，每任务 10–150 条演示全量微调。Diffusion Policy 在窄单指令任务更强，OpenVLA 在需语言接地的多样多指令任务更优，且两种设置平均成功率均最高，是唯一在所有任务上达到 ≥50% 的方案。

### 5.3 Parameter-Efficient Fine-Tuning
仅微调最后一层或冻结视觉编码器效果明显较差 → **视觉特征向目标场景的适配很关键**。LoRA 以仅 1.4% 可训练参数达到与全量微调相当的性能，单张 A100 上 10–15 小时完成微调，计算量约为全量微调的 1/8。

### 5.4 Memory-Efficient Inference via Quantization
8-bit 量化因额外开销降低推理速度（A5000 上仅 1.2Hz，显著改变系统动力学）→ 成功率降至 58.1%。4-bit 达到 71.9%，与 bfloat16 的 71.3% 相当，显存从 16.8GB 降至 7.0GB。

## 讨论与局限（Discussion and Limitations）

- 只支持**单图像观测**；扩展到多图像、本体感知与观测历史是重要方向。
- 推理吞吐需提升以支持 ALOHA 这类 50Hz 高频控制。
- 测试任务上可靠性有限，通常 **< 90%** 成功率。
- 受算力限制，基座 VLM 规模、与互联网数据联合训练、何种视觉特征最合适等问题仍未充分探索。

## 一句话抓住这篇论文

**OpenVLA = 多模态 VLM（Llama 2 7B + SigLIP/DINOv2 视觉编码器）+ 动作 token 化 + 970k 机器人轨迹微调**，把 VLM 的输出从「文本」改成「动作」，实现「图像 + 语言指令 → 机器人动作」。它在 29 项任务上比 55B 的闭源 RT-2-X 高 **16.5%** 绝对成功率，参数量少 7 倍，并且模型 / 训练代码 / 微调 notebook 全部开源。

## 一、为什么要做 OpenVLA

机器人学习策略的核心弱点是**无法超越训练数据泛化**：单个技能或语言指令训练出的策略，虽然能外推到新的初始条件（物体位置、光照），但对场景干扰物、新物体缺乏鲁棒性，也难以执行没见过的新指令。

而机器人之外，CLIP、SigLIP、Llama 2 这类视觉 / 语言基础模型靠**互联网规模预训练**已经具备这类泛化能力。矛盾在于：

- 机器人数据规模远小于互联网数据——即便最大的机器人操作数据集也只有 **10 万 ~ 100 万** 条演示；
- 这个「数据量级落差」本身就是机会：**把已有的视觉语言基础模型当作核心构件**，来训练能泛化到训练数据之外的机器人策略。

已有 VLA 工作（RT-2 等）证明了这条路可行，但有两个关键障碍挡住了推广：

1. **现有 VLA 基本闭源**——模型架构、训练流程、数据混合都不公开，外界无从复现与改进；
2. **缺乏面向新机器人 / 新任务的微调最佳实践**——尤其在消费级 GPU 这样的普通硬件上如何部署与适配，几乎没人研究。

> [!important] 本文的定位
> OpenVLA 的第一个贡献不是刷分，而是把「**开源 + 可微调**」这件事做扎实，类比开源语言模型生态（Llama 等），让机器人领域有一个能共同迭代的通用策略基座。

## 二、模型架构

> [!important] 三大件（对应论文 Fig. 2）
> ```text
> 输入图像 ──→ SigLIP + DINOv2（融合视觉编码器）
>                       │
>                       ▼
>                  2 层 MLP Projector
>                       │
> 语言指令 ──→ Llama Tokenizer ──┐
>                                ▼
>                        Llama 2 7B 语言骨干
>                                │
>                                ▼
>                        动作 token（7 维动作）
>                                │
>                                ▼
>                     Action De-Tokenizer → 7 维机器人动作
> ```

### 2.1 视觉编码器：SigLIP + DINOv2 融合

OpenVLA 基于 **Prismatic-7B VLM**，视觉部分是**双编码器**：SigLIP 与 DINOv2 分别处理同一批图像 patch，输出特征**按通道拼接（concatenated channel-wise）**。

- **SigLIP**：提供**高层语义**（物体类别、语言可对齐的概念）；
- **DINOv2**：提供**低层空间细节**（位置、形状、朝向）。

论文强调，相比常用的 CLIP-only 或 SigLIP-only 编码器，**加入 DINOv2 特征有助于改进空间推理**，而这对机器人精确控制尤其有用。

### 2.2 语言骨干：Llama 2 7B

- 参数：**7B**（Prismatic-7B VLM 的骨干，视觉编码器 600M，投影器是 2 层 MLP）；
- 训练目标：**下一词元预测（next token prediction）**，端到端训练；
- 视觉特征经投影器映射进语言模型的**输入空间**，与文本 token 一起喂入。

### 2.3 动作 token 化（本题核心机制）

把连续动作表示成 LLM 输出空间里的离散 token：

- 每个动作维度**单独离散成 256 个 bin**，7 维动作 → 7 个动作 token；
- **bin 宽度不按 min-max，而按训练数据动作的 1% 与 99% 分位数**均匀划分——用分位数是为了**忽略离群动作**，否则离群值会把离散区间拉得极宽、降低有效粒度；
- Llama 分词器只为微调预留 100 个 special token，**不够 256 个**，于是**直接覆写词表中最少使用的 256 个 token**（即词表最后 256 个）作为动作 token；
- 训练：标准 next-token prediction，**交叉熵损失只算在动作 token 上**。

## 三、训练数据与关键设计决策

### 3.1 数据构造

以 **Open X-Embodiment（OpenX）** 为基座（当时含 70+ 个机器人数据集、200 万+ 轨迹），做多步清洗：

1. **统一输入输出空间**：只保留「至少含一个第三人称相机 + 单臂末端控制」的操作数据集；
2. **平衡混合**：沿用 **Octo 的数据混合权重**（下采样多样性差的数据集、上采样任务与场景多样的数据集）；
3. **DROID 的取舍**：试过以 **10% 保守权重**加入 DROID，但训练中 DROID 的**动作 token 准确率始终偏低**（可能需更大混合权重或更大模型），为不拖累最终模型，**在训练最后三分之一阶段移除 DROID**，权重重新分配给其他数据集。

最终得到约 **970k** 条机器人 episode（对比 RT-2-X 的 350k）。

### 3.2 五条关键设计决策

| 决策点 | 探索结果 | 结论 |
|---|---|---|
| **VLM 骨干** | Prismatic vs LLaVA vs IDEFICS-1，在 BridgeData V2 上比 | LLaVA 比 IDEFICS-1 高 **35%**（多物体语言接地任务）；Prismatic 再比 LLaVA 高约 **10%** → 选 Prismatic |
| **图像分辨率** | 224×224 vs 384×384 | **无性能差异**，384 训练慢 **3 倍** → 选 224 |
| **视觉编码器** | 微调 vs 冻结 | **必须微调**！冻结会明显掉点（VLM 领域的「冻结更好」结论在 VLA 上不成立） |
| **训练轮次** | 1–2 epoch 够吗？ | 不够，需 **27 个 epoch**，直到动作 token 准确率 > **95%** 后性能仍在涨 |
| **学习率** | 多量级扫描 | 固定 **2e-5**（与 VLM 预训练一致），**warmup 无收益** |

> [!warning] 「冻结视觉编码器会掉点」值得单独记住
> 直觉上冻结视觉编码器能更好保留互联网预训练学到的鲁棒特征，VLM 领域也确实如此。但论文发现 VLA 训练中**微调视觉编码器至关重要**——推测原因是：预训练的视觉骨干**不足以捕捉机器人精确控制所需的细粒度空间细节**。

### 3.3 训练与推理基础设施

- **训练**：64 张 A100 × 14 天 ≈ **21,500 A100-hours**，batch size 2048；
- **推理**：bfloat16 精度约需 **15 GB** 显存，单张 **RTX 4090 上约 6 Hz**（未编译、未用投机采样等加速）；
- **远程推理服务器**：可实时把动作预测流式传给机器人，**不需要本地有强大算力设备**也能控制机器人。

## 四、主要实验结果

### 4.1 多机器人平台直接评测（out-of-the-box）

评测覆盖四类泛化轴：**视觉**（未见背景、干扰物、物体颜色/外观）、**运动**（未见位置/朝向）、**物理**（未见尺寸/形状）、**语义**（未见目标物体、指令、互联网概念），外加**语言接地**（多物体场景下能否操作指令指定的目标）。

| 对比项 | RT-1-X | Octo | RT-2-X | OpenVLA |
|---|---|---|---|---|
| 参数量 | 35M | 93M | 55B | **7B** |
| WidowX（BridgeData V2）平均成功率 | 18.5% | 20.0% | 50.6% | **70.6%** |
| Google Robot 平均成功率 | 33.3% | 26.7% | 78.3% | **85.0%** |

- **WidowX**（17 任务 ×10 试次 = 170 rollouts）：OpenVLA 全面领先；
- **Google Robot**（12 任务 ×5 试次 = 60 rollouts）：OpenVLA 与 RT-2-X 相当，都明显优于 RT-1-X / Octo；
- **唯一的例外是语义泛化**：RT-2-X 更强（如「把可乐罐移到 Taylor Swift 照片旁」），论文归因于 RT-2-X 用了**更大规模互联网预训练数据**，且**机器人数据与互联网数据联合微调**，更好保留了预训练知识；而 OpenVLA 为求简单**只用机器人数据微调**。

> [!important] OpenVLA 反超 RT-2-X 的三个原因
> 1. **更大的训练集**：970k vs 350k 轨迹；
> 2. **更细致的清洗**：例如过滤掉 Bridge 数据集中**全零（no-op）动作**；
> 3. **融合视觉编码器**：同时具备预训练的语义与空间特征。

### 4.2 新机器人上的数据高效适配

在 **Franka-Tabletop**（固定桌面 Franka，5 Hz 控制）与 **Franka-DROID**（可移动桌 Franka，15 Hz 控制）上，用每任务 **10–150 条演示**做全量微调：

- **Diffusion Policy**（从零训练的数据高效模仿学习方法）在**窄的单一指令任务**（如「把胡萝卜放进碗里」）上更强，轨迹更平滑精确；
- **OpenVLA** 在**涉及多物体、需要语言接地的多样多指令任务**上更好，OpenX 预训练让模型更能适应这类任务；
- **OpenVLA 是唯一在所有测试任务上都达到 ≥50% 成功率的方案**，适合作为模仿学习任务的**默认选择**（尤其当指令多样时）。

### 4.3 参数高效微调（PEFT）

| 策略 | 成功率 | 可训练参数 (×10⁶) | 显存（batch 16） |
|---|---|---|---|
| Full FT（全量） | 69.7 ± 7.2% | 7,188.1 | 163.3 GB* |
| 只调最后一层 | 30.3 ± 6.1% | 465.1 | 51.4 GB |
| 冻结视觉编码器 | 47.0 ± 6.9% | 6,760.4 | 156.2 GB* |
| Sandwich | 62.1 ± 7.9% | 914.2 | 64.0 GB |
| **LoRA, rank=32** | **68.2 ± 7.5%** | **97.6** | **59.7 GB** |
| LoRA, rank=64 | 68.2 ± 7.8% | 195.2 | 60.5 GB |

（\* 表示用 FSDP 跨 2 张 GPU 分片）

- **只调最后一层 / 冻结视觉编码器**效果明显较差 → 再次印证「**视觉特征向目标场景的适配是关键**」；
- **LoRA 达到最佳的性能-算力权衡**：仅训练 **1.4%** 参数即匹配全量微调，单张 A100 上 10–15 小时完成，算力约为全量微调的 **1/8**；
- **LoRA rank 影响可忽略**，推荐默认 **r = 32**。

### 4.4 量化推理

| 精度 | Bridge 成功率 | 显存 |
|---|---|---|
| bfloat16 | 71.3 ± 4.8% | 16.8 GB |
| int8 | **58.1 ± 5.1%** | 10.2 GB |
| int4 | **71.9 ± 4.7%** | 7.0 GB |

> [!warning] 8-bit 量化为什么反而最差
> 8-bit 量化**因额外的量化算子开销拖慢了推理速度**——评测用的 A5000 上只能跑到 **1.2 Hz**，而 BridgeData V2 任务用的是 **5 Hz 非阻塞控制器**，速度大幅下降**显著改变了系统动力学**，导致成功率掉到 58.1%。
> **4-bit 反而更快**（显存传输减少补偿了量化开销，A5000 上可达 3 Hz），性能与 bfloat16 相当，显存减半以上。
> **附录 D.4 反证**：改用**阻塞控制（blocking control）**、把推理速度的影响剥离后，8-bit 与 bfloat16、4-bit 表现相当 → 确认掉点原因是推理速度而非精度本身。

## 五、消融实验（附录 D）

| 消融项 | 结果 | 结论 |
|---|---|---|
| **去掉 OpenX 预训练**（只训 Bridge） | 绝对成功率降约 **30%** | OpenX 预训练影响**最大** |
| **去掉 DINOv2**（只用 SigLIP） | 降约 **5%** | 融合编码器有增益，但不如 OpenX 训练关键 |
| **冻结视觉编码器** | **80.0% vs 46.7%** | 微调视觉编码器显著更优 |
| **阻塞控制下量化** | 8-bit / 4-bit / bfloat16 相当 | 印证 4.4 的推断 |

## 六、局限与未来方向

- **只支持单张图像观测**——现实机器人设置是异构的，扩展到多图像、本体感知（proprioceptive）与观测历史是重要方向；
- **推理吞吐不足**——约 6 Hz，**无法支持 ALOHA 这类 50 Hz 高频控制**；需要动作分块（action chunking）或投机采样（speculative decoding）等加速手段；
- **可靠性有限**——测试任务上通常 **< 90%** 成功率；
- **受算力限制，许多设计问题未探索**：基座 VLM 规模对 VLA 性能的影响？机器人动作数据与互联网视觉语言数据共训练是否有帮助？什么样的视觉特征最适合 VLA？

## 七、回到「VLA 到底是什么」

> [!definition] VLA vs VLM vs LLM
> ```text
> LLM：文本 → 文本
> VLM：图像 + 文本 → 文本
> VLA：图像 + 文本 → 动作
> OpenVLA：VLM + 动作 token 化 + 机器人数据微调
> ```
> 关键在于：**VLA 不是「把 LLM 直接部署到机器人」**，而是在一个已经对齐了视觉与语言的 VLM 之上，把输出从「文本」改成「动作」。

**视觉怎么来的？** 来自机器人上的 **RGB 相机**（不是激光雷达、触觉等原始传感器）；图像先经 **SigLIP + DINOv2** 编码，再经 Projector 映射到 Llama 输入空间。

**闭环控制怎么跑？**

```text
相机拍照 → 图像 + 语言指令 → OpenVLA → 动作 → 机器人执行
    → 新状态 → 再拍照 → 再预测 → 再执行
```

模型通常在 GPU / 服务器上跑（论文还专门提供了远程推理服务器），机器人是执行端；**每个时间步都重新观察、重新预测**。

## 八、LLM / VLA 的预测机制（为什么「动作」能和「文本」用同一套机制）

> [!important] 一句话
> LLM 和 VLA 的本质都是「**下一个 token 预测机**」：token → 向量 → Transformer → logits → softmax → 采样 → 自回归。区别只是 **LLM 预测词，VLA 预测动作 token**。

### 8.1 整体流程

```text
文本/动作 → token → 向量 → Transformer 层 → 输出向量 → logits → 概率 → 采样 → 下一个 token
```

### 8.2 分步拆解

**① Token 化**：文本切成 token，每个 token 对应整数 ID，例：`"OpenVLA is great"` → `[1234, 567, 890, 45, 6789]`；VLA 中动作同样被离散成整数 token。

**② Token → 向量**：查嵌入矩阵（`vocab_size × hidden_dim`），每个 token ID 取一行变成 hidden_dim 维向量。

**③ Transformer 层**（每层主要做两件事）：

**自注意力**——每个 token 生成 Query、Key、Value，计算相关性：

$$\text{score}(i, j) = \frac{Q_i \cdot K_j}{\sqrt{d}}$$

softmax 归一化后加权求和 Value：

$$\text{output}_i = \sum_j \text{attn\_weight}(i, j) \times V_j$$

**前馈网络**：

$$\text{FFN}(x) = W_2 \cdot \text{activation}(W_1 x + b_1) + b_2$$

多层堆叠（Llama 2 7B 有 **32 层**），每层带残差连接与归一化。

**④ 向量 → 下一个 token**：取最后一个位置的隐藏向量 $h_{\text{last}}$，经输出投影矩阵得 logits：

$$\text{Logits} = h_{\text{last}} \cdot W_{\text{out}}$$

softmax 变成概率 $P(\text{token}) = \text{softmax}(\text{Logits})$，采样或选最大概率即得下一个 token。

**⑤ 训练时**：已知正确下一个 token，算交叉熵损失 $\text{Loss} = -\log P(\text{正确 token})$，反向传播更新嵌入矩阵、注意力矩阵、FFN、输出投影矩阵。

**⑥ 生成时自回归**：

```text
输入: "OpenVLA"            → 预测 "is"
输入: "OpenVLA is"         → 预测 "great"
输入: "OpenVLA is great"   → 预测 "."
```

每次把新 token 拼回输入，继续预测下一个。

### 8.3 VLA 的动作预测

机制完全一样，只是**词表换成动作 token**：普通 LLM 从 32000 个词里选，OpenVLA 从 **256 个动作 token** 里选；预测出动作 token 后**解码回连续动作**，交给机器人控制器。

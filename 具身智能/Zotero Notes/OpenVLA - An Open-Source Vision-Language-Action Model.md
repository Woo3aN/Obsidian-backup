# OpenVLA: An Open-Source Vision-Language-Action Model

> **一句话概述**：OpenVLA 是一个 70 亿参数、完全开源的视觉-语言-动作（VLA）模型，它把融合 DINOv2 与 SigLIP 视觉特征的 Llama 2 7B 视觉语言模型在 Open X-Embodiment 的 97 万条真实机器人演示上微调，从而成为能开箱即用控制多种机器人本体、并可借助 LoRA 等参数高效方法快速适配新任务的通用操作策略。(Kim 等, 2024)

## 1 Introduction

### 1.1 要解决的问题：泛化不了

机器人学习策略的核心弱点是**无法超越训练数据去泛化**。针对单个技能或单条语言指令训练出来的策略，虽然能外推到新的初始条件（物体位置、光照变化），但：

- 对**场景干扰物**和**新物体**缺乏鲁棒性；
- 难以执行**训练时没见过的新指令**（unseen task instructions）。

而机器人之外的视觉 / 语言基础模型——CLIP、SigLIP、Llama 2——靠**互联网规模预训练**已经具备了这类泛化能力。差距的根源是数据量级：

| 数据类型        | 规模                                          |
| ----------- | ------------------------------------------- |
| 互联网图文数据     | 万亿级 token（SigLIP / DINOv2 / Llama 2 的预训练语料） |
| 最大的机器人操作数据集 | 仅 **10 万 ~ 100 万** 条演示                      |

这个「数据量级落差」本身就是机会：**把已有的视觉语言基础模型当作核心构件**，去训练能泛化到训练数据之外的机器人策略。OpenVLA 就是这条路线的一个直接实现。

> [!note] 传统机器人为什么补不上这个缺口
> 在此之前，机器人技能的来源基本是这几条：**手工编程 / 示教编程 / 遥操作**、**基于模型的控制与规划**（运动学、动力学、MPC）、**模块化感知-规划-控制流水线**、**模仿学习**（行为克隆、DAgger、扩散策略）、**强化学习**（PPO、SAC，常在仿真里训完再 sim-to-real）。
>
> 它们的共同毛病是：**每个任务都要单独教、单独写、单独练**；换个物体、换个说法、换个环境就容易失效；**语言理解很弱**；泛化差。
>
> VLA 换了一条路：先拿互联网图文预训练拿到视觉与语言先验，再用大规模机器人数据微调出「图像 + 语言 → 动作」。一个模型多任务、可跨本体、能被自然语言指挥 —— 这正是 §1.2 里那两个障碍值得被解决的原因。

### 1.2 为什么现有 VLA 没能推广

已有工作（RT-2 等）证明了用预训练 VLM 直接微调出机器人动作是可行的，但有两个关键障碍：

1. **现有 VLA 基本闭源**——模型架构、训练流程、数据混合都不公开，外界无从复现、无从改进；
2. **缺乏面向新机器人 / 新任务的微调最佳实践**——尤其在消费级 GPU 这类普通硬件上如何部署与适配，此前几乎没人研究。

> [!important] 本文的定位
> OpenVLA 的第一个贡献不是刷分，而是把「**开源 + 可微调**」这件事做扎实——类比开源语言模型的生态（Llama 等），让机器人领域有一个能共同迭代的通用策略基座。模型权重、部署与微调 notebook、训练代码库全部开放。

一句话概括三条贡献：**开源一个能打过闭源大模型的通用 VLA**；**系统研究高效微调（LoRA、量化推理）**；**公开权重 + 训练代码 + 微调 notebook**。

### 1.3 先把概念理清：VLA 到底是什么

看这篇文章时最容易含糊的一点是「VLA 和 VLM、LLM 是什么关系」。三者可以按**输入输出**排成一条线：

> [!definition] LLM / VLM / VLA
> ```text
> LLM：文本 → 文本
> VLM：图像 + 文本 → 文本
> VLA：图像 + 文本 → 动作
> OpenVLA：VLM + 动作 token 化 + 机器人数据微调
> ```
> 关键在于：**VLA 不是「把 LLM 直接部署到机器人」**，而是在一个**已经对齐了视觉与语言的 VLM** 之上，把**输出从「文本」改成「动作」**。

- **VLM 本身就是多模态模型**——它已在大规模图文数据上把视觉与语言对齐；
- OpenVLA 基于 **Prismatic-7B** 这个 VLM，在它基础上做动作预测的微调；
- 所以 VLA 的能力来源有两层：**底层是互联网预训练带来的视觉-语言先验**，**上层是机器人数据带来的动作知识**。

## 2 Related Work

论文把相关工作分成三支，每支都对应 OpenVLA 的一个设计取向：

### 2.1 Visually-Conditioned Language Models

视觉条件语言模型（VLM）在互联网规模数据上训练，能从输入图像 + 语言提示生成自然语言，已被用于视觉问答、物体定位等大量任务。近期 VLM 的关键进展是**用架构把预训练视觉编码器与预训练语言模型桥接起来**：

- 早期工作探索过各种**交叉注意力**（cross-attention）方案；
- 新一代开源 VLM 收敛到更简单的「**patch-as-token**」做法——把预训练视觉 Transformer 的 patch 特征**当作 token**，再投影进语言模型的输入空间。这种简洁性让大规模语言模型的训练工具可以直接复用到 VLM/VLA 训练上。

> [!note] patch-as-token 具体在做什么
> ```text
> 图像 → 切成 patch → 每个 patch 经视觉 Transformer 编码 → 特征向量
>      → 投影到语言模型输入空间 → 当作「视觉 token」
>      → 和文本 token 拼成一条序列 → 送进 LLM
> ```
> 相比早期的 cross-attention 方案，它省掉了专门设计的视觉-语言交互层：
>
> - 不需要额外的 cross-attention 模块；
> - 直接复用 LLM 已有的**自注意力**去做跨模态交互；
> - 可以直接复用 LLM 的训练基础设施（FSDP、FlashAttention…），**容易 scale**。
>
> 这条路线是 OpenVLA 能「用极小的代码改动把 7B 语言模型改造成 VLA」的前提。

OpenVLA 正是采用这类工具，并**具体选用 Karamcheti 等人的 VLM 作为预训练骨干**——因为它从多分辨率视觉特征训练，**融合了 DINOv2 的低层空间信息与 SigLIP 的高层语义**，有助于视觉泛化。

### 2.2 Generalist Robot Policies

机器人领域近期趋势是在大规模多样化机器人数据集上训练多任务「**通用策略（generalist policy）**」，覆盖多种机器人本体。最接近的是 **Octo**——同样能开箱控制多种机器人、支持灵活微调。

**与 OpenVLA 的关键差别在模型架构**：Octo 这类先前工作通常把预训练组件（语言嵌入、视觉编码器）与**从零初始化**的额外组件拼起来，在策略训练中「缝合」它们；OpenVLA 则**更端到端**——直接微调 VLM，把机器人动作当作语言模型词表里的 token 来生成。实验证明这条简洁且可扩展的路线显著优于先前的通用策略。

### 2.3 Vision-Language-Action Models

已有不少工作把 VLM 用在机器人上——视觉状态表示、物体检测、高层规划、反馈信号等；也有工作把 VLM 直接集成进端到端操作策略，但往往**引入大量结构约束或要求标定相机**，限制了适用性。

近期一批工作（RT-2 等）与本文思路类似：**直接微调大型预训练 VLM 来预测机器人动作**，这类模型即 VLA。它有三大好处：

1. 在互联网规模的视觉-语言数据上完成了**预训练视觉与语言组件的对齐**；
2. 采用**通用架构**（而非为机器人控制定制的架构），能直接复用现代 VLM 训练的可扩展基础设施，**以极小的代码改动扩展到十亿参数级策略**；
3. 为机器人**打通了受益于 VLM 快速进步的通道**。

与本文最接近的是 **RT-2-X**（55B，在 OpenX 上训练）。本文与它的差别在于：① 用**更强的开源 VLM 骨干 + 更丰富的机器人数据**，以十分之一的参数量反超；② **深入研究了微调**（RT-2-X 完全不涉及微调场景）；③ 首次验证了现代**参数高效微调与量化**方法对 VLA 的有效性；④ OpenVLA 是**首个开源的通用 VLA**。

## 3 The OpenVLA Model

### 3.1 Preliminaries: Vision-Language Models

> [!important] 三大件（对应论文 Fig. 2）
> ```text
> 输入图像 ──→ SigLIP + DINOv2（融合视觉编码器）
>                       │
>                       ▼
>                  MLP Projector
>                       │
> 语言指令 ──→ Llama Tokenizer ──┐
>                                ▼
>                        Llama 2 7B 语言骨干
>                                │
>                                ▼
>                      动作 token（7 维动作）
>                                │
>                                ▼
>                   Action De-Tokenizer → 7 维机器人动作
> ```

近期 VLM 的架构都由三部分组成，并以**下一文本词元预测**为目标端到端训练：

1. **视觉编码器**：把图像映射成一组「图像 patch 嵌入」；
2. **投影器（Projector）**：把视觉编码器的输出嵌入映射进**语言模型的输入空间**；
3. **LLM 骨干**：接收视觉 + 文本 token，做自回归预测。

OpenVLA 具体基于 **Prismatic-7B**：**600M 视觉编码器 + MLP 投影器 + 7B Llama 2**。

**视觉编码器是双份的**。SigLIP 与 DINOv2 分别处理同一批图像 patch，输出特征**按通道拼接（concatenated channel-wise）**：

- **SigLIP**：提供**高层语义**（物体类别、可与语言对齐的概念）；
- **DINOv2**：提供**低层空间细节**（位置、形状、朝向）。

相比常用的 CLIP-only 或 SigLIP-only 编码器，**加入 DINOv2 特征有助于改进空间推理**——而这对机器人精确控制尤其有用。

#### 视觉编码器：一次前向里形状怎么变

论文只说了「600M 双视觉编码器 + 按通道拼接」，没给维度。下面这些形状是按 Prismatic 开源实现推的（骨干 id `dinosiglip-vit-so-224px`，对应 `vit_large_patch14_reg4_dinov2` + `vit_so400m_patch14_siglip_224`）：

```text
输入图像  224 × 224 × 3
   │  切成 14×14 像素的 patch（patch_size = 14）
   ▼
16 × 16 = 256 个 patch，每个展平后 14×14×3 = 588 维
   │  分别过各自的 patch embedding（两路权重独立）
   ├──────────────► DINOv2 ViT-L/14  → 256 × 1024
   └──────────────► SigLIP SoViT-400m/14 → 256 × 1152
   │  按通道拼接（channel-wise concat）
   ▼
256 × 2176
   │  Projector
   ▼
256 × 4096  ──► 与 N 个文本 token 拼成 (256+N) × 4096 ──► Llama 2 7B
```

几个容易记反的点：

- **patch 尺寸是 14×14 像素，不是 16×16**；16 是网格边长（224 ÷ 14 = 16），所以是 **256 个** patch，不是 196 个；
- 每个 patch 展平是 **588** 维（14×14×3），不是 768（768 是 16×16×3，对应 patch_size=16 的模型）；
- 两个编码器**各自做 patch embedding、各自过 Transformer**，不是先拼起来再共同编码；
- 取的是 Transformer 的**中间层** patch 特征（代码注释写的是倒数第二层），不是最后一层——这是 VLM 的常见做法，最后一层特征往往已经过度偏向分类目标；
- 拼接后是 **2176** 维（1024 + 1152），不是 2048。

两个编码器的分工可以直接对照到机器人任务上：

| 编码器 | 擅长 | 对机器人的意义 |
|---|---|---|
| DINOv2 | 空间细节、边缘、形状、位置 | 精确抓取、对齐、避障 |
| SigLIP | 语义、物体类别、语言对齐 | 理解「抓哪个物体」 |

- DINOv2 是**自监督**训练，强在空间；
- SigLIP 是**图文对**训练，强在语义；
- 两路拼接后保留完整两组信息，让后续 LLM 自己决定怎么用。

#### 投影器：把 2176 维接进 4096 维

视觉编码器输出和 Llama 的输入维度对不上（2176 vs 4096），中间靠投影器搭桥。

> [!warning] 这里论文和代码对不上，别背错
> **论文 §3.1 原文写的是「a small 2-layer MLP projector」**。但 OpenVLA 仓库里内嵌的 Prismatic 实现，**融合骨干走的是 3 层分支**（单骨干才是 2 层）：
>
> ```text
> 融合骨干（OpenVLA 用的）：
> 2176 → Linear → 8704 → GELU → Linear → 4096 → GELU → Linear → 4096
>                                   ↑ 中间层 = 4 × 2176
>
> 单骨干：
> D → Linear → 4096 → GELU → Linear → 4096
> ```
>
> 论文写于 2024 年，仓库后续迭代过（Prismatic 后来加了 224px 优化版本、更多 backbone 组合）。**论文没写错，是代码往前走了**。按上面的形状估算，投影器约 **7100 万参数**，占 7B 的 1% 左右 —— 所以论文叫它 "small" 是成立的。

**为什么必须有激活函数**：如果只有线性层，多层线性叠加等价于一层线性——

$$v = W_2(W_1 f + b_1) + b_2 = (W_2 W_1)f + (W_2 b_1 + b_2) = W' f + b'$$

加了 GELU 之后矩阵无法再合并，表达能力才真正变强。

**投影器怎么知道信息来自哪个编码器？它不知道。** 投影器就是固定的矩阵乘法：拼接后的向量 $f = [d_1 \ldots d_{1024}, s_1 \ldots s_{1152}]$，输出的每一维都是这 2176 个输入维度的加权和。前 1024 组权重对应 DINOv2，后 1152 组对应 SigLIP，**训练时反向传播自动学出最优组合**。推理时只做一次固定矩阵乘法，所谓「判断」全部发生在训练阶段。

**为什么视觉特征能和文本拼在一起？** 严格说不是「变成文本」，而是**映射到和文本嵌入同一个 4096 维空间**。文本 token 查嵌入矩阵后也是 4096 维；映射完维度一致就能拼。LLM 看到的只是一串 4096 维向量，**并不区分来源**——是自注意力让所有 token 互相「看」，模型自己学会哪些位置是视觉、哪些是语言。投影器和 LLM 是一起端到端训练的。

#### 视觉是怎么来的：闭环控制

一个容易被「多模态」这个词带偏的问题是：机器人的视觉到底从哪来？

- 来自机器人上的 **RGB 相机**——**不是**激光雷达、触觉等原始传感器；
- 图像先经 **SigLIP + DINOv2** 编码，再经 Projector 映射到 Llama 输入空间。

它跑的是**闭环控制**，每个时间步都重新观察、重新预测：

```text
相机拍照 → 图像 + 语言指令 → OpenVLA → 动作 → 机器人执行
    → 新状态 → 再拍照 → 再预测 → 再执行
```

模型通常在 GPU / 服务器上跑，机器人只是执行端。论文还专门提供了**远程推理服务器**，让本地算力不足时也能实时把动作预测流式传给机器人。

### 3.2 OpenVLA Training Procedure

OpenVLA 把**动作预测形式化为一个「视觉-语言」任务**：输入一张观测图像 + 一条自然语言任务指令，输出一串预测的机器人动作。要让语言模型能输出动作，就得把**连续动作映射成 token**。

**分两步走：**

**① 连续动作 → 离散整数**

- 每个动作维度**单独离散成 256 个 bin**，7 维动作 → 7 个整数，取值范围 ∈ [0…255]；
- **关键细节**：bin 宽度不按 min-max 划分，而是**按训练数据动作的 1% 与 99% 分位数**均匀划分。用分位数是为了**忽略离群动作**——否则个别离群值会把整个离散区间拉得极宽，从而**降低有效粒度**。

> [!note] 算一遍就懂了
> 设某一维动作的训练数据 $q_{1\%} = -0.5$、$q_{99\%} = 0.5$，那么
>
> $$\text{bin width} = \frac{0.5 - (-0.5)}{256} = \frac{1.0}{256} \approx 0.0039$$
>
> 真实动作值 $0.012$ 落在：
>
> $$\frac{0.012 - (-0.5)}{0.0039} \approx 131.3 \;\longrightarrow\; \text{token } 131$$
>
> 也就是说：**落在 1%–99% 区间外的值会被夹到两端**，换来的是区间内 256 级、约 0.004 的分辨率。若改用 min-max，一个 0.3 的离群值就能把分辨率拉粗好几倍。

**② 离散整数 → LLM 词表里的 token**

- Llama 分词器只为微调新引入的 token 预留了 **100 个 special token**，**不够 256 个**；
- 于是直接**覆写词表中最少使用的 256 个 token**（对应词表最后 256 个）作为动作 token；
- 这些 token 原本是**低频子词**，覆盖掉对语言能力影响很小；模型在机器人数据上继续微调时，会**重新学出这些 token 的新含义**。

**训练目标**：标准 next-token prediction，**交叉熵损失只计算在预测的动作 token 上**（不算文本部分）。

**解码**：模型输出动作 token 后，按**每个维度自己的分位数边界**映射回连续值，交给机器人控制器执行。

#### 为什么「动作」能用和「文本」一样的机制

这一点想通之后，整篇论文的机制就顺了——**LLM 和 VLA 的底层预测机制完全相同**：

> [!important] 本质都是「下一个 token 预测机」
> ```text
> token → 向量 → Transformer 层 → 输出向量 → logits → softmax → 采样 → 下一个 token
> ```
> 区别只是：**LLM 从 32000 个词里选，OpenVLA 从 256 个动作 token 里选**。

拆开看这几步：

- **Token 化**：文本切成 token，每个 token 对应一个整数 ID，例：`"OpenVLA is great"` → `[1234, 567, 890, 45, 6789]`；VLA 中动作同样被离散成整数 token；
- **Token → 向量**：查嵌入矩阵（`vocab_size × hidden_dim`），每个 token ID 取一行变成 hidden_dim 维向量；
- **Transformer 层**（Llama 2 7B 共 **32 层**，每层带残差连接与归一化），每层做两件事：

  **自注意力**——每个 token 生成 Query、Key、Value，计算相关性：

  $$\text{score}(i, j) = \frac{Q_i \cdot K_j}{\sqrt{d}}$$

  softmax 归一化后加权求和 Value：

  $$\text{output}_i = \sum_j \text{attn\_weight}(i, j) \times V_j$$

  **前馈网络**：

  $$\text{FFN}(x) = W_2 \cdot \text{activation}(W_1 x + b_1) + b_2$$

- **向量 → 下一个 token**：取最后一个位置的隐藏向量 $h_{\text{last}}$，经输出投影矩阵得 logits，再 softmax 成概率：

  $$\text{Logits} = h_{\text{last}} \cdot W_{\text{out}}, \qquad P(\text{token}) = \text{softmax}(\text{Logits})$$

- **自回归生成**：每次把新 token 拼回输入，继续预测下一个——

  ```text
  输入: "OpenVLA"            → 预测 "is"
  输入: "OpenVLA is"         → 预测 "great"
  输入: "OpenVLA is great"   → 预测 "."
  ```

- **训练时**：已知正确的下一个 token，算交叉熵损失 $\text{Loss} = -\log P(\text{正确 token})$，反向传播更新嵌入矩阵、注意力矩阵、FFN、输出投影矩阵。

> [!tip] 一个容易忽略的代价
> 正因为动作是**逐 token 自回归**生成的，7 维动作就要 7 次前向（严格说是 7 个解码步）—— 这正是它只能跑 6 Hz 的结构性原因，也是 §6 局限里「需要 action chunking / 投机采样」的由来。

**预测出动作 token 之后**，再**解码回连续动作**（Action De-Tokenizer），交给机器人控制器执行。

### 3.3 Training Data

以 **Open X-Embodiment（OpenX）** 为基座——当时含 **70+ 个机器人数据集、200 万+ 条轨迹**，由社区统一成了一套易用格式。

但它**不能直接拿来混着训**：相机角度不同、动作空间不同（有的控末端、有的控关节）、机器人形态不同，异构性非常严重。所以要先做一次清洗，目标只有两个：

1. **统一的输入输出空间**：所有数据都能表示成「单张第三人称图像 + 语言指令 → 7 维末端动作」；
2. **平衡的数据混合**：保证本体、任务、场景的多样性，别让模型偏向某一类数据。

具体规则（沿用 Octo 与 RT-1-X 的做法）：

1. **必须有至少一个第三人称相机**——剔除只有腕部相机的数据，保证视觉输入格式一致；
2. **必须是单臂末端执行器控制**——剔除双臂或直接控关节角的数据，动作空间统一成 **7 维：Δx, Δy, Δz, Δroll, Δpitch, Δyaw, gripper**；
3. **平衡混合**：沿用 **Octo 的数据混合权重**——下采样多样性差的数据集、上采样任务与场景多样的数据集；
4. **DROID 的取舍**：曾以 **10% 保守权重**加入 DROID，但训练中 DROID 的**动作 token 准确率始终偏低**（说明要拟合它的多样性，可能需要更大的混合权重或更大的模型）；为不拖累最终模型，**在训练最后三分之一阶段移除 DROID**，权重重新分配给其他数据集。

最终得到约 **970k** 条机器人 episode（对比 RT-2-X 用的 350k）。

> [!important] 规模到底有多重要
> 附录 D.1 做了对照：同样的 Prismatic 底座、只换成**仅用 BridgeData V2 训练**（OpenVLA-Bridge），Bridge 8 个任务上的平均成功率从 **76.3% 掉到 45.6%**——**绝对下降 30 个百分点**。语言接地那项几乎没受影响，但视觉、运动、物理、语义四类泛化全线下降。这是全文最大的一条消融结论：**场景 / 物体 / 任务的多样性本身就是泛化能力的来源**。

### 3.4 OpenVLA Design Decisions

论文在正式训练前用小规模实验（先在 BridgeData V2 上跑）探索了几个设计点：

| 决策点 | 探索结果 | 结论 |
|---|---|---|
| **VLM 骨干** | Prismatic vs LLaVA vs IDEFICS-1 | LLaVA 比 IDEFICS-1 高 **35%**（多物体语言接地任务）；**Prismatic 再比 LLaVA 高约 10%** → 选 Prismatic |
| **图像分辨率** | 224×224 vs 384×384 | **无性能差异**，384 训练慢 **3 倍** → 选 224 |
| **视觉编码器** | 微调 vs 冻结 | **必须微调**！冻结会明显掉点（80.0% vs 46.7%） |
| **训练轮次** | 1–2 epoch 够吗 | 不够，需 **27 个 epoch**，动作 token 准确率超 **95%** 后性能仍在涨 |
| **学习率** | 多量级扫描 | 固定 **2e-5**（与 VLM 预训练一致），**warmup 无收益** |

几个展开：

**为什么是 Prismatic。** 它是 OpenVLA 团队（Karamcheti 等）自己上一篇论文的 VLM，胜出的核心原因是**双塔视觉**——DINOv2 管精细空间，SigLIP 管语义。机器人不只是要认出「这是茄子」，还要知道**茄子的精确位置和姿态**。Prismatic 并不是什么全新网络结构，而是「视觉编码器 + 投影器 + LLM」这套标准配方里，**用实验筛出了最适合机器人的那一组搭配**。OpenVLA 直接拿它当底座，改造成输出动作 token。

**为什么不追高分辨率。** 分辨率一涨，切出的 patch 就多，视觉 token 序列变长，而 self-attention 的计算量是**随序列长度平方增长**的。实测 384×384 训练时间是 224 的近 3 倍，性能却没提升 —— 这点和纯 VLM 的「看图说话」任务不同，**动作控制对像素密度没那么敏感**。

> [!note] 语言接地实验用的「水槽环境」是什么
> 就是 BridgeData V2 里那个浅蓝色塑料水槽操作台（论文里的 sink / WidowX 场景）。台面上摆满干扰物——玩具蔬菜、瓶子、锅碗。作者在这里设计「语言接地任务」，比如「把红瓶子放进锅里」，专门测模型能不能在**多物体干扰**下听懂指令、找对目标。Prismatic / LLaVA / IDEFICS-1 的横向对比就是在这上面做的。

> [!warning] 「必须微调视觉编码器」和 VLM 的结论相反
> 直觉上冻结视觉编码器能更好保留互联网预训练学到的鲁棒特征，**VLM 领域的研究也确实发现冻结更好**。但论文发现 VLA 训练中**微调视觉编码器至关重要**——推测原因是：预训练的视觉骨干**不足以捕捉机器人精确控制所需的细粒度空间细节**。
>
> 附录 D.3 的数字很硬：在同时测了两种设置的评测里，**微调视觉编码器平均 80.0%，冻结只有 46.7%**。而且作者提到，有些冻结视觉的策略跑起来**行为明显不稳**，所以开发早期就直接放弃了这条路线。

### 3.5 Infrastructure for Training and Inference

- **训练**：64 张 A100 × 14 天 ≈ **21,500 A100-hours**，batch size 2048；
- **推理**：bfloat16 精度约需 **15 GB** 显存，单张 **RTX 4090 上约 6 Hz**（未编译、未用投机采样等加速手段）；
- **量化**：把权重从浮点压成更小的整数，换显存和带宽。4-bit 后显存可降到约 **7 GB**，性能基本不掉（细节见 §5.4）；
- **远程推理服务器**：可实时把动作预测流式传给机器人，**不需要本地有强大算力设备**也能控制机器人——机器人可以不背显卡，把画面传上去、把动作收回来。

> [!note] 27 个 epoch 为什么反常
> 大语言模型预训练通常 1–2 个 epoch 就够，再训就过拟合。但 VLA 不一样：**机器人数据量小得多（97 万条），而控制精度要求极高**，所以模型要把同一批数据反复嚼 27 遍，直到动作 token 的预测准确率超过 95% 才停。这也是「机器人数据稀缺」这条主线的一个侧写。

## 4 The OpenVLA Codebase

论文随模型一起开源了 OpenVLA 代码库——一个用于训练 VLA 的**模块化 PyTorch 代码库**（https://openvla.github.io）：

- **可伸缩**：从在单张 GPU 上微调 VLA，到在多节点 GPU 集群上训练十亿参数级 VLA；
- **支持现代大模型训练技术**：自动混合精度（AMP）、FlashAttention、全分片数据并行（FSDP）；
- **开箱即用**：完整支持在 Open X 数据集上训练，与 HuggingFace 的 `AutoModel` 类集成，并支持 **LoRA 微调**与**量化模型推理**。

## 5 Experiments

> [!info] 本节要回答的三个问题
> 1. 在多机器人与多类泛化设定下，OpenVLA 相比先前的通用策略表现如何？
> 2. OpenVLA 能否被有效微调到新的机器人设置与任务，相比数据高效的模仿学习方法如何？
> 3. 能否用参数高效微调与量化降低训练 / 推理的算力需求，使其更易获取？性能与算力的权衡如何？

### 5.1 Direct Evaluations on Multiple Robot Platforms

在 **WidowX**（BridgeData V2，17 任务 ×10 试次 = **170 次推演**）和 **Google Robot**（12 任务 ×5 试次 = **60 次推演**）上做「开箱即用」评测，覆盖四类泛化轴：

- **视觉**：未见背景、干扰物、物体颜色/外观；
- **运动**：未见物体位置/朝向；
- **物理**：未见尺寸/形状；
- **语义**：未见目标物体、指令、来自互联网的概念。

外加**语言接地**能力评测——多物体场景下，策略能否操作指令指定的那个目标。

| 对比项 | RT-1-X | Octo | RT-2-X | OpenVLA |
|---|---|---|---|---|
| 参数量 | 35M | 93M | 55B | **7B** |
| WidowX 平均成功率 | 18.5% | 20.0% | 50.6% | **70.6%** |
| Google Robot 平均成功率 | 33.3% | 26.7% | 78.3% | **85.0%** |

- **WidowX**：OpenVLA 全面领先；RT-1-X 与 Octo 常连目标物体都抓不对，有时还会原地乱挥手臂；
- **Google Robot**：OpenVLA 与 RT-2-X 相当，都明显优于 RT-1-X / Octo；
- **唯一的例外是语义泛化**：RT-2-X 更强——例如「把可乐罐移到 Taylor Swift 照片旁」，OpenVLA 会失败。

> [!important] 为什么 OpenVLA 能反超 55B 的 RT-2-X
> 1. **更大的训练集**：970k vs 350k 轨迹；
> 2. **更细致的清洗**：例如过滤掉 Bridge 数据集的**全零（no-op）动作**；
> 3. **融合视觉编码器**：同时具备互联网预训练的语义特征与空间特征。
>
> 而语义泛化不如 RT-2-X，是因为 RT-2-X 用了**更大规模互联网数据**，且**机器人数据与互联网数据联合微调**以保留预训练知识；OpenVLA 为求简单**只用机器人数据微调**，于是出现了**灾难性遗忘**——互联网上学到的概念被机器人数据盖掉了。

除了成功率，论文还记录了若干**智能行为**：能绕开干扰物、能把抓取姿态对齐到物体、**抓空了会自己纠正再来一次**。这些不是被显式编程进去的，而是从大规模多样化数据里学出来的。

### 5.2 Data-Efficient Adaptation to New Robot Setups

在 **Franka-Tabletop**（固定桌面 Franka，5 Hz 控制）与 **Franka-DROID**（可移动桌 Franka，15 Hz 控制）上，用每任务 **10–150 条演示**做全量微调：

- **Diffusion Policy**（从零训练的数据高效模仿学习方法，输出是连续动作、轨迹特别平滑）在**窄的单一指令任务**（如「把胡萝卜放进碗里」「把玉米倒进锅里」）上更强；
- **OpenVLA** 在**涉及多物体、需要语言接地的多样多指令任务**上更好——OpenX 预训练让它更能适应这类任务（「从零微调」的消融版本 OpenVLA-Scratch 表现明显更差，印证了这点）；
- **OpenVLA 是唯一在所有测试任务上都达到 ≥50% 成功率的方案**，适合作为模仿学习任务的**默认选择**（尤其当指令多样时）。

换句话说：**单任务、高灵巧度 → Diffusion Policy 更划算；多指令、多物体 → OpenVLA 几乎没对手**。

### 5.3 Parameter-Efficient Fine-Tuning

全量微调每个任务要 8 张 A100 跑 5–15 小时。论文进一步探索更省算力的方案：

| 策略 | 成功率 | 可训练参数 (×10⁶) | 显存（batch 16） |
|---|---|---|---|
| Full FT（全量） | 69.7 ± 7.2% | 7,188.1 | 163.3 GB* |
| 只调最后一层 | 30.3 ± 6.1% | 465.1 | 51.4 GB |
| 冻结视觉编码器 | 47.0 ± 6.9% | 6,760.4 | 156.2 GB* |
| Sandwich | 62.1 ± 7.9% | 914.2 | 64.0 GB |
| **LoRA, rank=32** | **68.2 ± 7.5%** | **97.6** | **59.7 GB** |
| LoRA, rank=64 | 68.2 ± 7.8% | 195.2 | 60.5 GB |

（\* 表示用 FSDP 跨 2 张 GPU 分片）

> [!note] LoRA 到底在做什么
> 冻结原来的大矩阵 $W_0$，在它旁边**并联两个小矩阵** $A$（高斯初始化）和 $B$（零初始化）：
>
> $$h = W_0 x + BAx$$
>
> 因为 $B$ 一开始是 0，模型**起步时和原模型完全等价**，不会一上来就把预训练能力破坏掉。训练结束后可以把两个矩阵乘起来**无缝合并**回原权重：$W_{\text{new}} = W_0 + BA$ —— 推理时**没有任何额外延迟**。
>
> 这也是为什么它只要训练 1.4% 的参数就能追平全量微调。

- **只调最后一层 / 冻结视觉编码器**效果明显较差 → **再次印证「视觉特征向目标场景的适配是关键」**；
- **LoRA 达到最佳的性能-算力权衡**：仅训练 **1.4%** 参数即匹配全量微调，单张 A100 上 10–15 小时完成，算力约为全量微调的 **1/8**；
- **LoRA rank 影响可忽略**，推荐默认 **r = 32**。

### 5.4 Memory-Efficient Inference via Quantization

OpenVLA 作为 7B 模型，推理显存远大于 Octo 这类 <100M 的模型，因此探索量化来降低部署门槛：

| 精度 | Bridge 成功率 | 显存 |
|---|---|---|
| bfloat16 | 71.3 ± 4.8% | 16.8 GB |
| int8 | **58.1 ± 5.1%** | 10.2 GB |
| int4 | **71.9 ± 4.7%** | 7.0 GB |

> [!warning] 为什么 8-bit 量化反而最差
> 8-bit 量化**因额外的量化算子开销拖慢了推理速度**——评测用的 A5000 上只能跑到 **1.2 Hz**，而 BridgeData V2 任务用的是 **5 Hz 非阻塞控制器**。速度大幅下降**显著改变了系统动力学**，成功率因此掉到 58.1%。
> **4-bit 反而更快**（显存传输减少补偿了量化开销，A5000 上可达 3 Hz），性能与 bfloat16 相当，显存减半以上。
> **附录 D.4 反证**：改用**阻塞控制（blocking control）**、把推理速度的影响剥离后，8-bit 与 bfloat16、4-bit 表现相当 → 确认掉点原因是**推理速度**而非精度本身（见附录 D.4）。

## 6 Discussion and Limitations

论文自己列了三条软肋：

1. **输入太单一**——只支持**单张**第三人称图像，没有本体感知（不知道关节角度），也没有历史记忆（忘了上一秒干了什么）。现实里的机器人设置是异构的，扩展到多图像、proprioception、观测历史是重要方向；
2. **推理太慢**——约 6 Hz，**撑不起 ALOHA 这类 50 Hz 的高频控制**，也就不适合更灵巧的双臂协同；需要动作分块（action chunking）或投机采样（speculative decoding）等加速；
3. **可靠性不够**——测试任务上普遍 **< 90%** 成功率，离工业级差得远。

另外还有一批**因为算力没来得及探索**的问题：基座 VLM 的规模对 VLA 性能到底有什么影响？机器人动作数据和互联网图文数据**共训练**有没有用？什么样的视觉特征最适合 VLA？

> [!tip] 后续工作：OFT 把前两条局限都接了
> 同一团队（Kim, Finn, Liang，2025，RSS）的 **OpenVLA-OFT** 就是冲着「自回归太慢 + 离散动作不够好」来的：
>
> - **并行解码 + 动作分块**：用双向注意力**一次前向输出整块动作**，不再逐维自回归 → 动作生成吞吐 **26×**（25 步动作块时 **43×**）；
> - **连续动作表示 + L1 回归**：不再离散成 256 个 bin，直接回归连续值；效果与扩散式微调相当，但收敛和推理都更快；
> - 结果：LIBERO 四个任务套件平均成功率 **76.5% → 97.1%**；ALOHA 双臂上再加 FiLM（OFT+）能跑 25 Hz 语言驱动控制。
>
> 换言之，这篇论文在 2024 年写下的「6 Hz 不够、需要 action chunking」，一年内就被同一条线补上了 —— **读 VLA 这条线时，OpenVLA 与 OFT 要连着看**。

### C RT-2-X vs. OpenVLA in BridgeData V2 Evaluations

论文发现原始 BridgeData V2 里**大量存在全零（no-op）动作**——每条演示的第一个时间步都记录成全零。直接在未清洗数据上训练高表达力的 VLA，会让策略学成**频繁输出全零动作、在评测中「僵住」**。OpenVLA 的做法是**直接过滤掉每条演示的第一个 transition**；而 RT-2-X 未做此预处理，于是改用「**总是查询第二可能的动作**」来规避僵住问题。

> [!note] 为什么不动态查询而是一直取第二可能
> 作者试过「检测到全零就重新查询」，结果**比一直取第二可能更差**。他们的解释是：中途停下来重新查询会引入不可忽略的延迟，让机器人的运动出现**细微中断**，反而改变了系统动力学 —— 这和 §5.4 里 8-bit 掉点的机制如出一辙。

| **OpenVLA-Bridge-SigLIP** | 40.6 ± 5.5% | **−5** | D.2：在上者基础上去掉 DINOv2 |

- **D.1 OpenX 数据**：影响**最大**，绝对成功率掉 30 个百分点；语言接地那项几乎没掉，但四类泛化全线下降；
- **D.2 双视觉编码器**：再掉约 5 个百分点。作者的说法是 DINOv2 的低层空间特征**只在部分情形下**帮到泛化，远不如数据多样性关键；
- **D.3 微调 vs 冻结视觉编码器**：**80.0% vs 46.7%**（另一套评测配置，不能和上表直接比）。冻结视觉的策略有时行为明显不稳。

**D.4 量化推理的剥离实验**：改用**阻塞控制（blocking control）**——每个动作完全执行后才预测下一个——把推理速度的影响剥离后，8-bit 与 bfloat16、4-bit 表现相当，**印证了 §5.4 的推断**：8-bit 掉点是推理速度而非精度本身。

### E LIBERO Simulation Experiments

在 **LIBERO** 仿真基准（Spatial / Object / Goal / Long 四个任务套件）上微调，OpenVLA 取得**最高平均成功率 76.5%** 与最佳平均排名，但**相对其他方法的领先幅度小于真实世界微调**——归因于 OpenVLA 只用**纯真实世界数据**预训练，与仿真域之间存在 gap。

## 延伸笔记（论文之外）

> 这一节不属于论文内容，是把读这篇论文时延伸出去的概念收在一起，方便复习时不必再翻别处。

### LLM 词表与 Tokenization

**词表是什么**：模型认识的所有 token 的集合，每个 token 对应一个整数 ID。**词表大小 = 嵌入矩阵行数 = 输出层类别数**。Llama 2 约 **32,000** 个。

**token 不是完整单词，而是子词**。现代 LLM 用 BPE（Byte Pair Encoding）之类的子词分词，把词切成常见片段：

```text
"unbelievable" → ["un", "believ", "able"]
"tokenization" → ["token", "ization"]
```

32,000 个子词可以组合出几乎任意英文单词；罕见词拆成更小片段甚至字节，**不会出现「无法表示」的情况**。

**中文的情况**：中文不切偏旁（偏旁不是独立 Unicode 字符），基本单位是单字或多字词，常见做法是「单字 + BPE 合并高频词」。「机器」「学习」「人工智能」这类常见词可能各自就是一个 token；罕见字则可能被拆成 UTF-8 字节。

| 模型 | 词表大小 | 中文支持 |
|---|---|---|
| Llama 2 | ~32,000 | 弱，汉字常被拆成字节 |
| Qwen | ~151,000 | 强，含大量中文词 |
| DeepSeek | ~100,000 | 强 |
| GLM | ~150,000 | 强 |

国产模型用 BBPE 并加入大量中文语料，常见词、成语、专业术语能合并成一个 token → **token 数少、推理快、上下文利用率高**。代价是嵌入矩阵和输出层参数变大，低频词训练不充分。

**和 OpenVLA 的关系**：正因为用的是 Llama 2 词表（中文弱、只预留 100 个 special token），才需要**覆盖最后 256 个低频 token** 来塞动作。如果换成词表大得多的国产模型，分配动作 token 会从容得多。

### 端到端与黑箱

**端到端是什么意思**：传统机器人是「感知 → 识别 → 规划 → 控制」多个独立模块串联；端到端是**输入直接到输出**，一个模型整体完成。OpenVLA 就是「图像 + 语言 → VLM → 动作」，中间不显式拆解。

- 好处：结构简单、整体优化、**减少模块间误差累积**、容易扩展；
- 代价：**需要大量数据**、可解释性差、调试困难。

**黑箱感从哪来**：我们其实知道数学机制（token → 向量 → Transformer → logits → softmax → 采样），但不知道**语义决策逻辑**——为什么它输出这个动作？知识分散存储在几十亿参数里，没有显式模块可指。在机器人领域，这会带来**安全、调试、信任**三重问题。社区目前的应对手段包括注意力可视化、探针分析、概念瓶颈、安全层、混合架构等。

**涌现与黑箱**：参数规模 + 数据规模跨过某个门槛后，模型突然表现出推理、上下文学习等能力（GPT-3 / 2020 让学界看到，ChatGPT / 2022 让大众看到）。OpenAI 自己也在做机械可解释性，但仍在早期。**VLA 把 LLM 的黑箱直接搬到了物理世界，风险被放大** —— 这也是「落地」那一节的前提。

### 传统机器人训练 vs VLA

| 维度 | 以前 | VLA |
|---|---|---|
| 技能来源 | 人教每一步、写死程序 | 模型从数据里学 |
| 任务范围 | 每个任务一套程序 | 一个模型多任务 |
| 换物体 | 容易失效 | 有一定泛化能力 |
| 语言 | 理解弱 | 能听懂自然语言 |
| 换机器人 | 每个本体单独适配 | 可跨本体控制 |

传统那套（手工编程 / 示教 / 遥操作、模型控制与 MPC、模块化流水线、模仿学习、强化学习）的共同毛病是**每个任务单独教、单独写、单独练**；VLA 的不同在于先用互联网图文预训练拿到视觉与语言先验，再用大规模机器人数据微调出「图像 + 语言 → 动作」。

### 落地、安全与产业

- LLM 的试错成本低（说错一句重说就行），商业闭环已经跑通；**VLA 面对的是物理世界，试错成本高得多**，安全要求严格；
- 当前 VLA 成功率约 60–80%、推理约 6 Hz，离工业级的 **99%+ / 50 Hz** 还有距离；
- **短期**：物流分拣、工厂搬运等**半结构化**场景；
- **中期**：精度提到 99%+、专用芯片普及；
- **长期**：家庭服务、自动驾驶等开放环境，需要新的安全标准；
- **分层协作**是务实路线：**LLM 当大脑**（理解意图、拆任务），**VLA 当小脑**（把意图变成动作），**传统控制当脊髓和安全层**（保证不撞、不超限）。

两个常被问到的延伸：

- **VLA 能不能用于自动驾驶**：可以，已有 OpenDriveVLA 一类工作，VLA 直接根据画面和指令输出驾驶动作；
- **VLA 和世界模型的关系**：融合是大势。VLA 是「行动派」，强在语义理解与决策；世界模型是「预言家」，强在推演物理变化。未来很可能是 **VLA 负责想，世界模型负责在脑海里预演**。短期 VLA 落地更快，长期世界模型潜力更大。

### 训练相关概念

- **超参数**：人工设定的规则，不由训练自动学。OpenVLA 的关键几项是学习率 **2e-5**、**27** 个 epoch、batch size **2048**。
- **反向传播**：模型预测错了之后，用链式法则从损失往回「追究责任」，算出每个参数该改多少（梯度）。
- **梯度爆炸**：反向传播连乘导致数值无限放大，参数被改废。通用对策是**调小学习率、梯度裁剪**。（注意：OpenVLA 用 2e-5 是因为**与 VLM 预训练保持一致**，论文没有把它归因于防梯度爆炸。）
- **Epoch**：把整个数据集过一遍。大模型通常 1–2 轮，但 VLA 数据少、精度要求高，所以嚼了 27 轮，直到动作 token 准确率过 95%。

### 深度学习基础最小清单

| 概念 | 要懂什么 | 在 OpenVLA 里的对应 |
|---|---|---|
| 线性层 / 全连接层 | $y = Wx + b$，维度怎么算 | 投影器各层；Llama 2 每层里到处都是 |
| 激活函数 | 为什么必须有非线性；ReLU、GELU | 投影器的 GELU；Llama 2 的 SwiGLU |
| 嵌入 Embedding | 本质是查找表，token ID → 向量 | 文本 token、动作 token 都靠它 |
| 反向传播与梯度下降 | 损失、梯度、链式法则、优化器 | 训练时更新全部 7B 参数 |
| 过拟合与正则化 | 概念即可 | 27 epoch 但数据量大，靠规模压住 |

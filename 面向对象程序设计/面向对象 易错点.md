# 左值、右值和引用
## 左值和右值的本质

一个最简单的判断标准：

- **左值 (lvalue)**：**有名字、有内存地址、能被取地址 & 的值**。可以出现在赋值号 `=` 的左边。
- **右值 (rvalue)**：**没有名字、临时的、用完就消失、不能被取地址 & 的值**。只能出现在赋值号 `=` 的右边。

举个最直白的例子：

cpp

运行

```cpp
int a = 10; // a 是左值，10 是右值
int b = a;  // a 是左值，可以被复制；这里 b 也是左值
```

---

## 左值、右值的常见场景

### 1. 典型的左值

只要你能对它取地址 `&`，它就是左值：

cpp

运行

```cpp

int x = 5;
int *p = &x; // ✅ 可以取地址，x 是左值

int arr[3] = {1,2,3};
int *q = &arr[0]; // ✅ 数组元素是左值

int& func() { static int s = 10; return s; }
int *r = &func(); // ✅ 函数返回的引用是左值
```

特点总结：有名字、有稳定内存地址，程序运行期间它一直存在。

### 2. 典型的右值

你**不能**对它取地址，它是临时的：

cpp

运行

```cpp
int a = 10;
int b = a + 5;
// 10 是字面量右值，a+5 是计算产生的临时值，也是右值

int func() { return 20; }
int c = func(); // func() 返回的是临时值，右值
```

特点总结：用完就扔，编译器会在合适的地方把它销毁。

## 和引用的关系
### 一、先明确两个核心概念

1. **引用的本质**：引用就是**给已有的变量起了一个别名**，和原变量共享同一块内存。
2. **绑定**：就是 “引用指向哪个对象 / 值” 的过程。

---

### 二、逐行拆解表格里的三种引用类型

#### 1. 普通左值引用 `T&`

表格

| 可以绑定左值？ | 可以绑定右值？ |
| :------ | :------ |
| ✅ 是     | ❌ 否     |

**含义**：只能绑定到**有名字、有地址、能取 `&`** 的左值，不能绑定到临时的右值。

**例子**：

cpp

运行

```cpp
int a = 10; // a 是左值
int& r1 = a;  // ✅ 合法：r1 是 a 的别名，绑定左值 a
r1 = 20;      // 合法：修改 r1 就是修改 a

int& r2 = 10; // ❌ 报错：10 是右值，普通左值引用不能绑定右值
int& r3 = a + 5; // ❌ 报错：a+5 是临时计算结果，属于右值
```

**为什么不能绑定右值？**

因为普通左值引用允许修改绑定的对象，但右值是临时的、用完就销毁的，修改它没有意义，还容易引发未定义行为，所以 C++ 直接禁止了这种绑定。

---

#### 2. const 左值引用 `const T&`

表格

|可以绑定左值？|可以绑定右值？|
|:--|:--|
|✅ 是|✅ 是|

**含义**：既可以绑定左值，也可以绑定右值，而且绑定右值时，会**延长临时右值的生命周期**，直到这个引用离开作用域。

**例子**：

cpp

运行

```cpp
int a = 10;
const int& r1 = a;  // ✅ 合法：绑定左值，r1 是 a 的只读别名
// r1 = 20; // 报错：const 引用不能修改值

const int& r2 = 10; // ✅ 合法：绑定右值，临时值的生命周期被延长
const int& r3 = a + 5; // ✅ 合法：绑定右值
```

**为什么可以绑定右值？**

因为 `const` 引用不允许修改绑定的对象，绑定临时右值不会出现 “修改临时值” 的问题，所以 C++ 允许这种绑定，还顺便延长了临时值的生命周期。

---

#### 3. 右值引用 `T&&`

表格

|可以绑定左值？|可以绑定右值？|
|:--|:--|
|❌ 否（除非用 `std::move` 转换）|✅ 是|

**含义**：专门用来绑定临时的右值，支持移动语义；如果想绑定左值，需要用 `std::move` 把左值 “强制转换” 成右值。

**例子**：

cpp

运行

```cpp
int a = 10;
int&& r1 = 10;      // ✅ 合法：绑定右值
int&& r2 = a + 5;   // ✅ 合法：绑定右值
int&& r3 = a;       // ❌ 报错：a 是左值，不能直接绑定到右值引用

// 用 std::move 把左值 a 转换成右值，就可以绑定了
int&& r4 = std::move(a); // ✅ 合法
```

**关键注意点**：

右值引用本身是**左值**！比如上面的 `r1`，它是右值引用类型，但它有名字、有地址，所以它本身是左值。这也是你之前题目里 `int&& x` 函数形参里 `int& y = x;` 能通过编译的原因。

---

### 三、一张表总结核心区别

表格

| 引用类型       | 允许修改绑定对象？ | 绑定左值             | 绑定右值 | 核心用途           |
| :--------- | :-------- | :--------------- | :--- | :------------- |
| `T&`       | ✅ 可以      | ✅                | ❌    | 读写访问左值对象       |
| `const T&` | ❌ 不可以     | ✅                | ✅    | 只读访问，延长临时值生命周期 |
| `T&&`      | ✅ 可以      | ❌（需 `std::move`） | ✅    | 移动语义，接管临时对象资源  |

## 例题
4)	【多选题】选出正确的选项
```cpp
void f(int& x) {}
void f(int&& x) {
    int& y = x; //(1)
    const int& z = y+1; //(2)
    int& w=2; //(3)
    f(z); //(4)}
```

A.	(1)处会发生编译错误，因为左值引用无法绑定右值
B.	(2)处不会发生编译错误，因为常量左值引用可以绑定右值
C.	(3)处会发生编译错误，因为非const引用不能绑定到右值
D.	(4)处会发生编译错误，因为传递了const引用
### 选项 A：`(1)处会发生编译错误，因为左值引用无法绑定右值`

❌ **错误**

- `x` 是右值引用形参，但在函数内部，`x` 本身是一个**左值**（有名字的右值引用变量，其值类别为左值）。
- 因此 `int& y = x;` 是合法的左值引用绑定到左值，不会报错。

---

### 选项 B：`(2)处不会发生编译错误，因为常量左值引用可以绑定右值`

✅ **正确**

- `y+1` 是一个临时值，属于**右值**。
- `const int&` 常量左值引用可以绑定到右值，这是 C++ 的标准规则，所以此处编译通过。

---

### 选项 C：`(3)处会发生编译错误，因为非const引用不能绑定到右值`

✅ **正确**

- `2` 是一个字面量，属于**右值**。
- 非 const 的左值引用（`int&`）不能直接绑定到右值，所以此处会编译报错。

---

### 选项 D：`(4)处会发生编译错误，因为传递了const引用`

❌ **错误**

- `z` 是 `const int&` 类型的变量，它本身是一个**左值**。
- 函数 `f` 有两个重载：`void f(int&)` 和 `void f(int&&)`。`z` 是 `const` 左值，无法绑定到非 const 的 `int&`，也无法绑定到 `int&&`（右值引用），所以这里实际会**编译报错**，但选项给出的原因 “因为传递了 const 引用” 不准确，错误的直接原因是**没有匹配的重载版本**，而不是 “传递了 const 引用” 本身。

---

### 最终答案

**正确选项：B、C** ✅

# 内联函数
内联函数在编译时是将该函数的目标代码展开到该函数调用点

内联函数核心机制
`inline` 内联函数的处理发生在**编译阶段**：
编译器会把内联函数的函数体代码（目标代码）直接复制、展开到每一处函数调用的位置，消除普通函数调用的栈跳转开销。

# 核心重载规则
![](imgs/Pasted%20image%2020260616224350.png)

C++ 函数重载判定依据：**函数名相同，形参列表（参数个数、类型、顺序）不同**；仅返回值不同不能构成重载。

逐个分析 4 个函数

1. `int function(int a, int b, int c);`
    
    3 个 int 参数，基准函数。
2. `double function(int a, int b, double c);`
    
    第 3 个参数是 double，和 (1) 参数类型不同，构成重载。
3. `int function(int a, int b);`
    
    仅 2 个参数，参数个数不同，和 (1) 构成重载。
4. `double function(int a, int b, int c);`
    
    参数列表和 (1) 完全一致，仅返回值不同，**不能构成重载**。

结论

(1)(2)(3) 互相可构成重载，对应选项 B。

# 引用传递的定义
![536](imgs/Pasted%20image%2020260616224747.png)

C++ 引用传递的标准形式：**函数形参为引用类型（`int &x`），调用时实参传入普通变量**，形参是实参的别名，二者共享同一块内存。

 各选项判断

- **A**：形参是指针、实参传地址 → 这是**地址传递（指针传递）**，不是引用传递，错误。
- **B**：形参和实参都是数组名 → 数组名本质是首地址，属于地址传递，错误。
- **C**：形参实参都是普通变量 → 属于**值传递**，函数内修改形参不影响外部实参，错误。
- **D**：形参是引用，实参是变量 → 完全匹配引用传递语法，正确。

# 引用核心语法规则
![](imgs/Pasted%20image%2020260616225239.png)

1. 引用定义时**必须初始化**，不能只声明不赋值；
2. 引用只能绑定**同类型普通变量**，不能绑定地址、常量字面量。

 逐个选项分析

- **A) `int &a = &n;`** ❌
    
    `&n` 是变量 n 的内存地址（指针值），引用不能绑定指针，类型不匹配，语法错误。
- **B) `int &a;`** ❌
    
    引用定义时缺少初始化，C++ 规定引用必须立刻绑定变量，禁止悬空引用。
- **C) `int &a = n;`** ✅
    
    `a` 是 int 型引用，直接绑定同类型变量`n`，是标准合法写法，`a`等价于`n`的别名。
- **D) `int &a = 10;`** ❌
    
    字面量`10`是常量，普通左值引用不能绑定常量（需`const int &a = 10;`才合法）。

 补充拓展

若要绑定常量，需使用常引用

# 拷贝构造函数
![](imgs/Pasted%20image%2020260616225820.png)
 A 正确

拷贝构造函数核心作用：用同类型已有对象初始化新对象，语法如 `A a2 = a1;`。

 B 正确

对象**值传递**时，会复制实参对象到形参，自动调用拷贝构造函数；若为引用传递则不会调用。

C 正确

编译器生成的隐式拷贝构造函数执行**逐成员拷贝**：内置类型直接复制值，成员对象会调用自身类的拷贝构造函数完成拷贝。

 D 错误

隐式拷贝构造函数会**直接复制指针成员的地址值**（浅拷贝），并不是不初始化指针；只是浅拷贝会导致两个对象指针指向同一块堆内存，析构时重复释放内存引发崩溃。

---

 补充区分浅拷贝 / 深拷贝

- 隐式拷贝构造 = 浅拷贝：复制指针地址，不新开内存；
- 自定义拷贝构造实现深拷贝：重新分配堆内存，复制指针指向的数据。

# 继承
![](imgs/Pasted%20image%2020260616230311.png)
 答案：A

 解析（选出表达错误的选项）

 核心继承访问规则：
无论何种继承方式，**基类的 private 成员在派生类中完全不可访问**，不存在 “在派生类中仍是 private” 的说法，派生类看不见、无法操作基类 private 成员。

逐个分析选项

- **A（错误）**
    
    公有继承时，基类`private`成员**对派生类完全隐藏、不可访问**，不能说 “在派生类中仍是 private”，派生类没有访问权限。
- **B（正确）**
    
    公有继承：基类`protected` → 派生类中仍为`protected`，派生类内部可访问，外部对象不可访问。
- **C（正确）**
    
    公有继承：基类`public` → 派生类中仍为`public`，内外均可访问。
- **D（正确）**
    
    私有继承：基类`public`/`protected`成员，在派生类中全部降级为`private`，仅派生类内部可访问。

# 指针字符串
![](imgs/Pasted%20image%2020260616230959.png)

 答案：D

 题干说明

`char *p = "abcd";`

`p` 存储字符串常量 `"abcd"` 的首字符`'a'`的内存地址，题目要求**输出这个字符串首地址的数值**。

逐个选项解析

 A) `cout << &p;`

`&p` 是**指针变量 p 自身的内存地址**，不是字符串`"abcd"`的首地址，错误。

B) `cout << p;`

`cout`对`char*`做特殊重载：会把`p`当作字符串，循环输出所有字符直到`'\0'`，输出结果是`abcd`，而非地址数字，错误。

 C) `cout << &p[0];`

`&p[0]`等价于`p`，仍是`char*`类型，`cout`依然会打印完整字符串`abcd`，不输出地址数值，错误。

 D) `cout << (void*)p;` ✅

强制转换为`void*`后，避开`char*`的字符串重载，`cout`会直接打印指针保存的内存地址数字，即字符串首地址，符合题意。

 补充知识点

C++ 中`ostream`对`char*`有专属处理逻辑，用于打印字符串；想要打印字符指针存储的地址，必须强转为`void*`类型。

# 构造与析构顺序
 一、完整构造执行总顺序（含虚继承，本题适用）

固定优先级从先到后：

**1. 所有虚基类 → 2. 普通继承基类 → 3. 类内成员对象 → 4. 自身构造函数体**

 细分规则

1. **虚基类（virtual 继承）最先构造**
    
    不管继承列表写在前还是后，虚基类永远比普通基类先执行；多个虚基类按 `class 子类 :` 后面书写顺序依次构造。
    
    本题：`virtual public B1`，最先构造 B1。
2. **普通公有 / 私有基类次之**
    
    按 `class 子类 :` 后普通继承的书写顺序构造，和初始化列表无关。
    
    本题：`public B2`，虚基类之后构造 B2。
3. **成员对象（类内包含的其他类变量）**
    
    只看**类中定义成员的上下顺序**，完全不看初始化列表书写顺序。
    
    本题定义顺序：`B1 memberB1;` → `B2 memberB2;`，先构造 memberB1，再 memberB2。
4. 最后执行子类构造函数 `{}` 内部代码（本题函数体为空，无输出）

 本题构造执行流程

1. 虚基类 B1 → 2. 普通基类 B2 → 3. 成员 memberB1 → 4. 成员 memberB2

---

 二、析构顺序：严格与构造完全逆序

**成员对象 → 普通基类 → 虚基类**

1. 成员逆序销毁：后构造的成员先析构
    
    本题成员构造顺序 memberB1→memberB2，析构顺序 memberB2→memberB1
2. 普通基类逆序销毁：普通基类先构造的后析构
    
    本题普通基类只有 B2，直接析构 B2
3. 虚基类最后销毁

 本题析构执行流程

1. memberB2 析构 → 2. memberB1 析构 → 3. 普通基类 B2 析构 → 4. 虚基类 B1 析构

---

 三、无虚继承的简化通用版（普通多继承）

 构造

普通基类（继承书写顺序）→ 成员对象（类内定义顺序）→ 自身函数体

 析构

成员逆序 → 普通基类逆序

---

 四、高频易错提醒

1. **初始化列表的书写顺序，完全不控制构造先后**，只负责给构造传参；
2. 内置基础类型（int、double 等）只有赋值，没有构造 / 析构打印；
3. 析构不存在自定义顺序，编译器强制逆序释放资源。

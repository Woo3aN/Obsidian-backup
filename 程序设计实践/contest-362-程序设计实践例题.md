## LinK01 A+B

### 题目描述

输入两个整数，求这两个整数的和是多少。

### 输入

输入两个整数 A, B，用空格隔开，0 ≤ A, B ≤ $10^8$。

### 输出

输出一个整数，表示这两个数的和。

### 样例

**输入：**
```
7 7
```

**输出：**
```
14
```

### 我的代码

```cpp
#include <iostream>
using namespace std;

int main()
{
    int a, b, c;
    cin >> a >> b;
    c = a + b;
    cout << c;
}
```

### 思路要点

- **题目本质**：这是 OI 竞赛的"Hello World"，考察最基本的输入输出语法，没有任何算法难度。
- **输入方式**：使用 `cin >> a >> b` 从标准输入读取两个整数。`cin` 会自动跳过空白字符（空格、换行），所以输入中的空格分隔不是问题。
- **输出方式**：使用 `cout << a + b` 直接输出结果。也可以用 `cout << c` 先存到变量 `c` 中再输出，效果相同。
- **数据类型选择**：题目数据范围是 0 ≤ A, B ≤ $10^8$，两数之和最大为 2×$10^8$。C++ 中 `int` 类型在 32 位系统上能表示的范围约为 -2.1×$10^9$ ~ 2.1×$10^9$（即 -$2^{31}$ ~ $2^{31}$-1），因此用 `int` 完全足够，不会溢出。如果想要更安全，也可以用 `long long`，但本题不需要。
- **易错点**：
  - 不要忘记 `#include <iostream>` 和 `using namespace std;`（或 `std::cin` / `std::cout`）。
  - OJ 判题时只比对输出内容，多余的提示文字（如 `"Please input:"`）会导致 Wrong Answer。

## LinK02 完美立方

### 题目描述

形如 $a^3$ = $b^3$ + $c^3$ + $d^3$ 的等式被称为完美立方等式。例如 $12^3$ = $6^3$ + $8^3$ + $10^3$。编写一个程序，对任给的正整数 N (N ≤ 100)，寻找所有的四元组 (a, b, c, d)，使得 $a^3$ = $b^3$ + $c^3$ + $d^3$，其中 a, b, c, d 大于 1，小于等于 N，且 b ≤ c ≤ d。

### 输入

一个正整数 N（N ≤ 100）。

### 输出

每行输出一个完美立方。格式为：

```
Cube = a, Triple = (b,c,d)
```

请按照 a 的值从小到大依次输出。当 a 相同时，b 值小的优先输出；b 相同时 c 值小的优先；c 相同时 d 值小的优先。

### 样例

**输入：**
```
24
```

**输出：**
```
Cube = 6, Triple = (3,4,5)
Cube = 12, Triple = (6,8,10)
Cube = 18, Triple = (2,12,16)
Cube = 18, Triple = (9,12,15)
Cube = 19, Triple = (3,10,18)
Cube = 20, Triple = (7,14,17)
Cube = 24, Triple = (12,16,20)
```

### 我的代码

```cpp
#include <iostream>
using namespace std;

int main()
{
    int a, b, c, d;
    int N;
    cin >> N;
    for (a = 2; a <= N; a++)
    {
        int a3 = a * a * a;
        for (b = 2; b < N; b++)
        {
            for (c = b; c < N; c++)
            {
                for (d = c; d < N; d++)
                {
                    if (a3 == b * b * b + c * c * c + d * d * d)
                    {
                        cout << "Cube = " << a << ", "
                             << "Triple = "
                             << "(" << b << "," << c << "," << d << ")"
                             << endl;
                    }
                }
            }
        }
    }
    return 0;
}
```

### 思路要点

- **题目本质**：在给定范围内枚举所有可能的四元组 (a, b, c, d)，找出满足 $a^3$ = $b^3$ + $c^3$ + $d^3$ 的组合。由于限制了 b ≤ c ≤ d，可以避免重复枚举同一组合的不同排列。
- **为什么四重循环可行**：N ≤ 100，四重循环的枚举量大约是 $N^4$ / 6（因为有 b ≤ c ≤ d 的约束，组合数约为 C(N,3) 量级），实际计算次数约 1.6×$10^7$（一千六百万），在 OJ 的 1 秒时限内完全可行。现代 CPU 每秒可执行数亿次简单运算。
- **剪枝优化——预计算 $a^3$**：`int a3 = a * a * a;` 放在最外层循环，避免在内层 b、c、d 的每一次迭代中都重新计算 $a^3$。如果不这样做，`a * a * a` 会在最内层被计算 O($N^3$) 次，虽然编译器可能会优化，但手动提出来是好习惯。
- **有序枚举避免重复**：令 `b` 从 2 开始，`c` 从 `b` 开始，`d` 从 `c` 开始。这样天然保证 b ≤ c ≤ d，同时避免产生如 (3,4,5) 和 (4,3,5) 这种实际上等价的重复组合。注意题目要求 "b ≤ c ≤ d"，所以这个顺序也是题目规定的输出顺序。
- **起点的选择**：所有变量从 2 开始而非 1，因为题目明确说 "大于 1"。如果误从 1 开始，会多出一些不满足题目要求的组合（如 a=3, b=1, c=1, d=1 这种 $1^3$+$1^3$+$1^3$ = 3 ≠ 27，实际上也不会成立，但边界条件要严格遵循题意）。
- **复杂度分析**：时间复杂度 O($N^4$/6)，空间复杂度 O(1)。N=100 时可以在 1 秒内完成。
- **易错点**：
  - 内层循环的终止条件写成了 `b < N` 而不是 `b <= N`——看起来像是 bug，但因为 c 和 d 都从更大的值开始，且 $a^3$ = $b^3$ + $c^3$ + $d^3$ 意味着 b、c、d 都小于 a，而 a ≤ N，所以 b < N 实际上不会漏解。不过严格来说写 `b <= N` 更安全、更符合题意。
  - 输出格式要严格匹配 `Cube = a, Triple = (b,c,d)`，包括空格和括号，否则 OJ 判错。

## LinK03 人的周期

### 题目描述

据说人生来就有三个生理周期，分别为体力周期、感情周期和智力周期，它们的周期长度分别为 **23 天**、**28 天**和 **33 天**。每一个周期中有一天是高峰。因为三个周期的长度不同，通常三个周期的高峰不会落在同一天。

对于每个周期，会给出从当前年份的第一天开始，到出现高峰的天数（不一定是第一次高峰出现的时间）。给定一个从当年第一天开始的天数 d，任务是输出从给定时间开始（**不包括**给定时间），下一次三个高峰落在同一天的时间（距给定时间的天数）。

例如：给定时间为 10，下次出现三个高峰同一天的时间是 12，则输出 2（注意这里不是 3）。

### 输入

输入包含多组数据，每一组数据由四个整数组成，数据以 `-1 -1 -1 -1` 结束。

对于每一行的四个整数 p, e, i 和 d：
- p, e, i 分别表示体力、情感和智力高峰出现的时间（从当年第一天开始计算）
- d 是给定的时间，可能小于 p, e 或 i

所有给定时间是非负的且 ≤ 365，所求的时间 ≤ 21252。

### 输出

从给定时间起，下一次三个高峰同一天的时间（距离给定时间的天数）。

### 样例

**输入：**
```
0 0 0 0
0 0 0 100
5 20 34 325
4 5 6 7
283 102 23 320
203 301 203 40
-1 -1 -1 -1
```

**输出：**
```
Case 1: the next triple peak occurs in 21252 days.
Case 2: the next triple peak occurs in 21152 days.
Case 3: the next triple peak occurs in 19575 days.
Case 4: the next triple peak occurs in 16994 days.
Case 5: the next triple peak occurs in 8910 days.
Case 6: the next triple peak occurs in 10789 days.
```

### 我的代码

```cpp
#include <iostream>
using namespace std;

int main()
{
    int p, e, i, d, caseNumber = 0;

    while (cin >> p >> e >> i >> d && p != -1)
    {
        ++caseNumber;
        int k;
        for (k = d + 1; (k - p) % 23; ++k);
        for (; (k - e) % 28; k += 23);
        for (; (k - i) % 33; k += 23 * 28);
        cout << "Case " << caseNumber
             << ": the next triple peak occurs in "
             << k - d << " days." << endl;
    }

    return 0;
}
```

### 思路要点

- **题目本质**：给定三个周期（23、28、33）的起始偏移 p、e、i，以及一个参考日期 d，求大于 d 的最小整数 k，使得 k 与 p 的差能被 23 整除、k 与 e 的差能被 28 整除、k 与 i 的差能被 33 整除。这是中国剩余定理（CRT）的一个特例，但代码中采用的是更直观的「逐步试探 / 步长加速法」，不需要 CRT 的模逆元计算。

- **数学表达**：求解同余方程组：
  ```
  k ≡ p (mod 23)
  k ≡ e (mod 28)
  k ≡ i (mod 33)
  ```
  且 k > d。等价于找最小的 k > d 使得 `(k-p)%23 == 0 && (k-e)%28 == 0 && (k-i)%33 == 0`。

- **三步跳跃法详解**（核心技巧）：

  1. **第一步——满足体力周期**：从 `k = d+1` 开始，每次 `k++`，找到第一个满足 `(k-p) % 23 == 0` 的 k。这一步最多走 23 步就能找到（因为模 23 的余数在连续 23 个整数中必然覆盖 0~22 各一次）。

  2. **第二步——同时满足体力和感情**：从上一步找到的 k 开始，每次让 `k += 23`，继续判断 `(k-e) % 28 == 0`。这里的关键是：k 增加 23 的倍数不会改变 `(k-p) % 23` 的值（因为 `(k+23t - p) % 23 == (k-p) % 23`），所以体力周期的条件始终满足。这一步最多走 28 次（因为 23 和 28 互质，对模 28 来说 +23 可以遍历所有余数）。

  3. **第三步——同时满足三个周期**：从上一步找到的 k 开始，每次让 `k += 23×28 = 644`，判断 `(k-i) % 33 == 0`。同理，+644 不会改变 `(k-p) % 23` 和 `(k-e) % 28` 的值（因为 644 是 23 和 28 的公倍数）。这一步最多走 33 次。三个模数 23、28、33 两两互质，它们的乘积 21252 就是所有三个条件同时满足的周期（即答案不会超过 21252）。

  综上，最坏情况下需要约 23 + 28 + 33 = 84 次循环就能找到答案，远优于从 d+1 到 21252 逐一枚举的 20000+ 次。

- **逐枚 vs 跳跃的直观理解**：想象你每 23 天去一次健身房（体力周期），每 28 天去一次图书馆（感情周期）。如果你想找一天同时去两个地方，不需要一天一天翻日历——只需要在每次去健身房的那天检查是否也要去图书馆即可。三个周期同理，层层叠加。

- **多组输入处理**：`while (cin >> p >> e >> i >> d && p != -1)` 在读取四个整数的同时判断 p 是否为 -1。`cin >> p` 的返回值是 `cin` 对象本身，可以用作布尔判断（读取成功为 true，失败或 EOF 为 false）。题目约定以 `-1 -1 -1 -1` 结束，但只检查 p != -1 就够了。

- **caseNumber 计数器**：每组数据的输出需要标注是第几个 Case，用 `++caseNumber` 从 1 开始递增。

- **复杂度分析**：每组数据最多约 23 + 28 + 33 ≈ 84 次循环，总复杂度 O(每组常数) × T。空间复杂度 O(1)。

- **易错点**：
  - 题目要求输出的是"距离给定时间的天数"即 `k - d`，而不是 k 本身。样例中给定 10，答案是 12，输出 2（因为 12-10=2，"不包括给定时间"）。代码中的 `for (k = d + 1; ...)` 从 d+1 开始正是这个原因。
  - 答案不会超过 21252（23×28×33），在 `int` 范围内。

## LinK04 排序考试

### 题目描述

给定任意 T 组整数，每组整数都要按升序输出。

### 输入

第一行是整数 T，表示一共有 T 组数据。接下来 T 行，每行有 N+1 个数，第一个整数表示该行有 N 个待排序的数字。

T（1 ≤ T ≤ 100），N（1 ≤ N ≤ 1000000）。

### 输出

对于每组整数，按照升序输出排序结果，每个结果占一行。

### 样例

**输入：**
```
3
4 412 120 5560 3760
5 576 66 35 99 88
4 127 100 510 380
```

**输出：**
```
120 412 3760 5560
35 66 88 99 576
100 127 380 510
```

### 我的代码

```cpp
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

int main()
{
    int T;
    cin >> T;
    while (T--)
    {
        int N, value;
        cin >> N;
        vector<int> numbers;
        for (int i = 0; i < N; ++i)
        {
            cin >> value;
            numbers.push_back(value);
        }
        sort(numbers.begin(), numbers.end());
        for (int i = 0; i < N; ++i)
        {
            if (i > 0) cout << " ";
            cout << numbers[i];
        }
        cout << endl;
    }
    return 0;
}
```

### 思路要点

- **题目本质**：多组数据的排序问题。考察标准库 `std::sort` 的使用、动态数组 `vector` 的使用、多组输入的处理方式以及输出格式控制。

- **多组数据框架**：先读入 `T`（组数），然后用 `while (T--)` 循环 T 次。每组先读一个整数 N（该组有多少个数），再读入 N 个整数。

- **为什么用 `vector`**：题目中 N 最大可达 1,000,000（一百万）。如果使用固定大小的数组（如 `int arr[1000000]`），需要在编译时确定大小，而且栈空间通常只有几 MB，存不下这么大的数组（一百万 int ≈ 4MB，可能接近栈限制）。`vector` 在堆上动态分配内存，没有这个限制，而且可以根据需要自动扩容。也可以写成 `vector<int> numbers(N)` 预分配大小后再用下标访问，但 `push_back` 的写法更通用。

- **排序**：`sort(numbers.begin(), numbers.end())` 是 C++ STL 中最常用的排序函数，底层实现是快速排序 + 插入排序 + 堆排序的混合算法（内省排序），时间复杂度 O(N log N)，对一百万元素也足够快。

- **输出格式控制**：每一行的数字之间用空格隔开，但行末不能有多余空格（有些 OJ 对此很严格，会导致 Presentation Error 或 Wrong Answer）。代码用 `if (i > 0) cout << " "` 的技巧：除了第一个数字外，每个数字前先输出一个空格，这样最后一个数字后面就不会有空格。也可以用更简洁的方式：先输出第一个元素，然后循环输出 `" " << numbers[i]`。

- **复杂度分析**：每组排序 O(N log N)，总复杂度 O(Σ N log N)。空间复杂度 O(N)（每组存储 vector）。

- **易错点**：
  - 题目输入格式是每行第一个数表示该行有多少个待排序的数字，读入时容易搞混——第一个数 N 是数量，不能也参与排序。
  - 各组的 N 不同，每轮循环都要重新声明 `vector<int> numbers`（或用 `clear()` 清空），不能把上一组的数据混进来。
  - 需要引入 `<algorithm>`（sort）和 `<vector>`（vector）两个头文件。

## LinK13 输出N皇后的全部摆法

### 题目描述

输入一个正整数 N，输出 N 皇后问题的全部摆法。输出结果里的每一行都代表一种摆法，行里的第 i 个数字如果是 n，就代表第 i 行的皇后应该放在第 n 列。皇后的行、列编号都从 1 开始算。

### 输入

皇后的个数 n（n ≤ 13）。

### 输出

输出长度为 n 的正整数，每行一种摆法。

### 样例

**输入：**
```
4
```

**输出：**
```
2413
3142
```

### 我的代码

```cpp
#include <iostream>
#include <vector>
using namespace std;

int N;
vector<int> res;

void dfs(int n)
{
    if (n == N)
    {
        for (auto x : res) cout << x;
        cout << endl;
        return;
    }

    for (int i = 1; i <= N; i++)
    {
        int k;
        for (k = 0; k < n; k++)
        {
            if (res[k] == i || abs(res[k] - i) == abs(k - n))
                break;
        }
        if (k == n)
        {
            res[n] = i;
            dfs(n + 1);
        }
    }
}

int main()
{
    cin >> N;
    res.resize(N);
    dfs(0);
    return 0;
}
```

### 思路要点

- **题目本质**：经典 N 皇后问题——在 N×N 的棋盘上放置 N 个皇后，使得它们互不攻击（任意两个不在同一行、同一列、同一对角线）。这里要求输出所有解，每行解用一个 N 位数字表示，第 i 位表示第 i 行的皇后放在第几列。

- **DFS 回溯框架**：
  - 逐行放置皇后（`n` 表示当前处理到第几行，从 0 开始），每行尝试 1~N 的每一列。
  - `res[n] = i` 表示第 n 行的皇后放在第 i 列。
  - 放置前先做**冲突检测**（见下），通过后才递归进入下一行。
  - 当 `n == N` 时，说明 N 个皇后全部放置成功，此时 `res[0..N-1]` 保存了一组完整解，直接输出。由于递归会自然回溯（返回上一层尝试下一列），不需要显式的"撤销"操作——`res[n]` 在下一轮循环中会被覆盖。

- **冲突检测详解**（`for (k = 0; k < n; k++)` 检查当前行 n 的候选列 i 与已放置的 0~n-1 行是否冲突）：
  - **同一列**：`res[k] == i` —— 之前某行的皇后已经放在第 i 列了。
  - **同一对角线**：`abs(res[k] - i) == abs(k - n)` —— 如果行差等于列差的绝对值，说明两个皇后在一条斜线上。这是因为在 N×N 棋盘中，45° 斜线上所有格子的 `行 - 列` 为常数，135° 斜线上所有格子的 `行 + 列` 为常数。`|行1 - 行2| == |列1 - 列2|` 同时覆盖了两种情况。
  - 如果内层循环完整结束（`k == n`），说明没有任何冲突，该位置合法。

- **为什么不用布尔数组优化**：LinK14.5 中使用了 `col[]`, `dg[]`, `udg[]` 三个布尔数组 O(1) 判断冲突，这里用的是 O(n) 遍历检查。两种方法在这个数据范围（N ≤ 13）下都可以。遍历检查代码更短，容易理解和记忆；布尔数组版本更高效但需要处理对角线映射的细节。

- **输出格式**：`for (auto x : res) cout << x;` —— `res` 中的每个数字（列号从 1 开始）直接连接在一起组成一个整数串，符合题目要求的格式。注意与 LinK14.5 的输出格式完全不同（那个要求输出棋盘图案）。

- **复杂度分析**：N 皇后在已知所有解的情况下最坏时间复杂度约为 O(N!)，因为第一行有 N 种选择，第二行约 N-2 种……实际搜索树会被剪枝大幅缩小。N=13 时解数为 73712 个，在可接受范围内。

- **易错点**：
  - `res` 的索引从 0 开始，但输出的列号要从 1 开始（i 的范围是 1~N 而非 0~N-1）。
  - `res.resize(N)` 一定要在调用 dfs 之前执行，否则 `res[n] = i` 会出现越界访问（未分配空间）。

## LinK14 求八皇后的第n种解

### 题目描述

八皇后问题一共有 92 组解，每组解用一个皇后串表示：`a = b₁b₂...b₈`，其中 $b_i$ 为第 i 行皇后所处的列数。皇后串的比较：将串视为整数，整数小的排前面。输入一个数 n，要求输出八皇后问题的第 n 个解。

### 输入

第 1 行是测试数据的组数 T，后面跟着 T 行输入。每组测试数据包含一个正整数 n (1 ≤ n ≤ 92)。

### 输出

输出有 T 行，每行输出第 n 个八皇后串。

### 样例

**输入：**
```
2
1
92
```

**输出：**
```
15863724
84136275
```

### 我的代码

```cpp
#include <iostream>
#include <cstring>
#include <cmath>
using namespace std;

int res[92][8];
int path[8];
int count = 0;

void dfs(int n)
{
    if (n > 7)
    {
        for (int k = 0; k < n; k++)
            res[count][k] = path[k];
        count++;
        return;
    }

    for (int i = 1; i <= 8; i++)
    {
        int k;
        for (k = 0; k < n; k++)
        {
            if (path[k] == i || abs(path[k] - i) == abs(k - n))
                break;
        }
        if (k == n)
        {
            path[n] = i;
            dfs(n + 1);
        }
    }
}

int main()
{
    int T, n;
    memset(path, 0, sizeof(path));
    dfs(0);

    cin >> T;
    while (T--)
    {
        cin >> n;
        for (int i = 0; i < 8; i++)
            cout << res[n - 1][i];
        cout << endl;
    }
    return 0;
}
```

### 思路要点

- **题目本质**：与 LinK13 思路一致，但不需要输出所有解，而是支持"按编号查询第 n 个解"。8 皇后的解总数固定为 92 个，所以最适合的策略是**预计算 + 查表**：一次性生成全部解存入二维数组，之后每次查询 O(1) 直接输出。

- **预计算（打表）策略**：
  - 用 `res[92][8]` 存储所有解：92 行（每种解一行），8 列（8 个皇后的列号）。
  - `path[8]` 作为临时数组，在 DFS 过程中记录当前路径。
  - 全局计数器 `count` 从 0 开始，每找到一组完整解就把它拷贝进 `res[count]` 然后 `count++`。
  - DFS 回溯的过程与 LinK13 完全一致：逐行放置，`path[n] = i`，冲突检测，递归。

- **为什么 DFS 顺序天然对应字典序**：DFS 从第 0 行开始，每行从小到大（1→8）尝试列号。这样先找到的解，第 0 行的列号更小（或相等时看第 1 行……依次类推），把皇后串看作 8 位整数的话，先找到的就是较小的——恰好符合题目要求的"整数小的排前面"。

- **查询**：`while (T--)` 读入 n，直接 `res[n-1]` 索引到第 n 个解（数组下标从 0 开始，题目 n 从 1 开始，所以要 -1），遍历 8 列输出即可。

- **时间复杂度**：预计算阶段 O(8!) ≈ 40320 种尝试（实际更少因为剪枝），固定常数。每次查询 O(1)（只是读数组 + 输出 8 个数字）。总复杂度 O(T)。

- **一个有趣的点——为什么是 92**：8 皇后问题共有 92 个解（如果不考虑旋转和镜像对称，只算本质不同的解是 12 个）。这个数字是固定的，可以上网查证。如果 DFS 跑出来的不是 92，说明代码有 bug。

- **易错点**：
  - `memset(path, 0, sizeof(path))` 需要 `<cstring>` 头文件（代码中引入了但实际可以省略，因为 `path` 是全局数组会被零初始化）。
  - `dfs(0)` 从第 0 行开始（而非第 1 行），递归终止条件是 `n > 7`（即已经放置了第 0~7 行共 8 个皇后）。也可以写 `n == 8` 但 `n > 7` 更安全（防御性编程）。
  - 如果忘记给 `res` 赋值而直接 `res[count][k] = path[k]` 语法正确，但必须确保 `count` 不越界（92 在范围内）。

<a id="link145-dfs试炼之n皇后问题"></a>

## LinK14.5 DFS试炼之n皇后问题

### 题目描述

n-皇后问题是指将 n 个皇后放在 n×n 的国际象棋棋盘上，使得皇后不能相互攻击到，即任意两个皇后都不能处于同一行、同一列或同一斜线上。

### 输入

共一行，包含整数 n（1 ≤ n ≤ 12）。

### 输出

每个解决方案占 n 行，每行输出一个长度为 n 的字符串表示棋盘状态：`.` 表示空位，`Q` 表示皇后。每个方案输出完成后，输出一个空行。

### 样例

**输入：**
```
4
```

**输出：**
```
.Q..
...Q
Q...
..Q.

..Q.
Q...
...Q
.Q..
```

### 我的代码

```cpp
#include <iostream>
using namespace std;

const int N = 20;
int n;
char g[N][N];
bool col[N], dg[N], udg[N];

void dfs(int u)
{
    if (u == n)
    {
        for (int i = 0; i < n; i++) puts(g[i]);
        puts("");
        return;
    }

    for (int i = 0; i < n; i++)
        if (!col[i] && !dg[u + i] && !udg[n - u + i])
        {
            g[u][i] = 'Q';
            col[i] = dg[u + i] = udg[n - u + i] = true;
            dfs(u + 1);
            col[i] = dg[u + i] = udg[n - u + i] = false;
            g[u][i] = '.';
        }
}

int main()
{
    cin >> n;
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++)
            g[i][j] = '.';
    dfs(0);
    return 0;
}
```

### 思路要点

- **题目本质**：与 LinK13 一样是 N 皇后问题，但输出格式不同——需要输出完整的棋盘图案（`.` 和 `Q`），每个方案间用空行分隔。此外，这题使用了布尔数组优化冲突检测，是更标准的"N 皇后模板"写法。

- **布尔数组优化冲突检测（模板级写法）**：
  - `col[i]`：第 i 列是否已被占用。`true` 表示已有皇后。
  - `dg[u + i]`：主对角线（左上→右下方向）是否被占用。数学推导：在同一条主对角线上的格子，它们的 `行号 + 列号` 是定值。对于第 u 行第 i 列的格子，这个值是 `u + i`。所以用 `dg[u + i]` 就能标记/查询这条对角线。
  - `udg[n - u + i]`：副对角线（右上→左下方向）是否被占用。数学推导：在同一条副对角线上的格子，它们的 `行号 - 列号` 是定值。直接用 `u - i` 会有负数（当 i > u 时），所以统一偏移 n 得到 `n - u + i`（也可以用 `u - i + n`，效果相同，都保证非负）。
  - 三个数组的容量设计：`col[N]` 需要覆盖 0~n-1 列，`dg[N]` 和 `udg[N]` 需要覆盖 `u+i` 的范围（最大约 n+n=2n），所以 `const int N = 20` 对于 n ≤ 12 绰绰有余。

- **回溯三部曲**——放置一个皇后要做三件事：
  1. **做选择**：`g[u][i] = 'Q'`，标记三个数组 `col[i] = dg[u+i] = udg[n-u+i] = true`。
  2. **递归**：`dfs(u + 1)` 进入下一行。
  3. **撤销选择（回溯）**：`col[i] = dg[u+i] = udg[n-u+i] = false`，`g[u][i] = '.'` 恢复为空位。撤销是关键——只有这样，for 循环尝试下一列时，棋盘和标记数组才能回到"没放过"的状态。

- **棋盘初始化**：所有格子初始化为 `'.'`（用双重循环填充）。只有放置皇后时才改为 `'Q'`，回溯时恢复为 `'.'`。

- **输出**：`puts(g[i])` 直接输出 c-string 的一行（`g[i]` 是 `char[N]`，以 `\0` 结尾）。`puts("")` 输出一个空行，用于分隔不同方案。

- **与 LinK13 的对比**：

  | 方面 | LinK13 | LinK14.5 |
  |------|--------|----------|
  | 冲突检测 | O(n) 遍历 | O(1) 布尔数组 |
  | 输出格式 | 数字串（2413） | 棋盘图案（Q / .） |
  | 方案分隔 | 无 | 空行分隔 |
  | 回溯方式 | 隐式（循环覆盖） | 显式（设为 false / '.'） |
  | 代码复杂度 | 更简短 | 更高效、更规范 |

- **复杂度分析**：与 LinK13 相同，O(N!) 级别，但常数更小（布尔数组 O(1) vs 遍历 O(n)）。N ≤ 12 完全可以接受。

- **易错点**：
  - 对角线索引的偏移方式不是唯一的：`dg[u+i]` 和 `udg[n-u+i]` 换成 `udg[u-i+n-1]` 也能工作，只要保证索引不越界、映射关系正确即可。理解原理比死记下标公式更重要。
  - 三个布尔数组一定要记得回溯（恢复为 false），否则后续搜索会错误地认为某些列/对角线已被占用。
  - 输出需要 `#include <cstdio>`（或使用 `printf/puts`），代码中没有显式引入但可能通过 iostream 间接可用。严格来说建议加上 `<cstdio>`。

## LinK16 放苹果

### 题目描述

把 M 个同样的苹果放在 N 个同样的盘子里，允许有的盘子空着不放，问共有多少种不同的放法？注意：5,1,1 和 1,5,1 是同一种放法（盘子相同、苹果相同）。

### 输入

第一行是测试数据的数目 t（0 ≤ t ≤ 20）。以下每行均包含二个整数 M 和 N，以空格分开。0 ≤ M, N ≤ 10。

### 输出

对输入的每组数据 M 和 N，用一行输出相应的 K（正整数，代表共有几种放法）。

### 样例

**输入：**
```
1
7 3
```

**输出：**
```
8
```

### 我的代码

```cpp
#include <iostream>
using namespace std;

int f(int x, int y)
{
    if (x < y)
        return f(x, x);

    if (x == 0)
        return 1;

    if (y <= 0)
        return 0;

    return f(x, y - 1) + f(x - y, y);
}

int main()
{
    int t, x, y;
    cin >> t;

    while (t--)
    {
        cin >> x >> y;
        cout << f(x, y) << endl;
    }
    return 0;
}
```

### 思路要点

- **题目本质**：经典的"整数划分"问题（也叫"放苹果"问题）——把 M 个不可区分的物品放入 N 个不可区分的容器，允许容器为空。由于苹果相同、盘子相同，方案只取决于每个盘子里有几个苹果（不考虑盘子的排列顺序）。

- **状态定义**：`f(m, n)` 表示把 m 个相同的苹果放入 n 个相同的盘子的方案总数。注意盘子和苹果都是"同样的"（不可区分），所以 5,1,1 和 1,5,1 算同一种——我们只关心每个盘子的苹果数量组成的多重集。

- **递推关系推导**（核心）：
  - **情况 1：m < n（苹果比盘子少）**——即使每个盘子最多放 1 个苹果，也会有 n-m 个盘子空着。空着的盘子不影响计数（盘子不可区分），所以问题退化为 `f(m, m)`（用 m 个盘子装 m 个苹果），多余的盘子直接忽略。
  - **情况 2：m == 0（没有苹果）**——所有盘子都空着，只有 1 种方案。这是递推的边界（base case）。
  - **情况 3：n <= 0（没有盘子）**——有苹果但没盘子，不可能，返回 0。也是边界条件。
  - **情况 4：一般情况 m ≥ n > 0**——递推核心：`f(m, n) = f(m, n-1) + f(m-n, n)`。
    - **第一项 `f(m, n-1)`**：至少有一个盘子是空的。既然有一个空盘，问题等价于把 m 个苹果放入 n-1 个盘子（那个空盘子不影响结果）。这一项覆盖了所有"有空盘子"的方案。
    - **第二项 `f(m-n, n)`**：所有盘子都至少放 1 个苹果。既然每个盘子至少 1 个，我们可以先从 m 个苹果中拿出 n 个，每个盘子预先放 1 个，然后把剩下的 m-n 个苹果任意分配到 n 个盘子中。由于每个盘子已经"非空"了，剩下的分配可以有空盘也可以没有。
    - 这两项**不重不漏**：任何方案要么有空盘（第一项覆盖），要么完全没有空盘（第二项覆盖）。两者互斥且完备。

- **递推过程示例**（M=7, N=3）：
  ```
  f(7, 3) = f(7, 2) + f(4, 3)
  f(7, 2) = f(7, 1) + f(5, 2)
  f(7, 1) = f(7, 0) + f(6, 1) = 0 + ... → 最终 1
  ...
  → f(7, 3) = 8
  ```
  7 个苹果 3 个盘子的 8 种分法是：(7,0,0), (6,1,0), (5,2,0), (5,1,1), (4,3,0), (4,2,1), (3,3,1), (3,2,2)。

- **递归 vs DP**：代码使用的是带记忆化的递归（虽然这里没有显式 memo），数据范围 M, N ≤ 10 非常小，纯递归的计算量也很有限。如果数据范围增大（如 M, N ≤ 100），就需要改用 DP 或加记忆化数组避免重复计算，状态数 O(M×N)。

- **复杂度分析**：纯递归最坏约 O(2^(M+N)) 但实际因为分支中 m 或 n 递减，远小于此。M, N 都不超过 10，完全可以接受。

- **易错点**：
  - 递归边界条件的顺序很重要：`m < n` 的判定必须放在 `n <= 0` 之前，因为当 m < n 时直接归约到 `f(m, m)`，m 可能为 0，最终会被 `m == 0` 捕获返回 1。如果先判断 `n <= 0`，会导致某些情况错误返回 0。
  - 不要忘记处理"全空"方案（m=0），这是一种合法方案（对应题目中"允许有的盘子空着不放"）。
  - 多组输入用 `while (t--)` 处理，cin 读入后立即调用 `f(x, y)`。

## LinK19 递归实现指数型枚举

### 题目描述

从 1∼n 这 n 个整数中随机选取任意多个，输出所有可能的选择方案。

### 输入

输入一个整数 n（1 ≤ n ≤ 15）。

### 输出

每行输出一种方案。同一行内的数必须升序排列，相邻两个数用恰好 1 个空格隔开。对于没有选任何数的方案，输出空行。各行（不同方案）之间的顺序任意（本题有 SPJ）。

### 样例

**输入：**
```
3
```

**输出：**
```

3
2
2 3
1
1 3
1 2
1 2 3
```

### 我的代码

```cpp
#include <iostream>
using namespace std;

const int N = 29;
int n;
bool st[N];

void dfs(int u)
{
    if (u > n)
    {
        for (int i = 1; i <= n; i++)
            if (st[i])
                cout << i << " ";
        cout << endl;
        return;
    }

    st[u] = true;
    dfs(u + 1);

    st[u] = false;
    dfs(u + 1);
}

int main()
{
    cin >> n;
    dfs(1);
    return 0;
}
```

### 思路要点

- **题目本质**：生成集合 {1, 2, ..., n} 的所有子集（幂集）。每个元素要么选、要么不选，共 $2^n$ 种可能。这是指数型枚举（与排列组合型枚举不同，排列是 n! 级别）。

- **DFS 决策树**：把问题看作一棵二叉树——
  - 从 u=1 开始，每层决策一个数：选还是不选。
  - 左分支：`st[u] = true`（选），递归 `dfs(u+1)`。
  - 右分支：`st[u] = false`（不选），递归 `dfs(u+1)`。
  - 当 `u > n` 时（即 n 个数的决策都已完成），到达叶子节点，输出当前选择的子集。

- **为什么输出天然升序**：因为 DFS 按照 1 → 2 → ... → n 的顺序决策，遍历 `st[1..n]` 时也是从小到大检查，所以输出的每个方案内数字必然是升序的。这也符合题目要求"同一行内的数必须升序排列"。

- **状态数组 st[] 的设计**：
  - `st[i] = true` 表示数字 i 被选入当前子集。
  - `st[i] = false` 表示不选。
  - 注意这里没有显式的"回溯撤销"——因为每一层在 `st[u]=true` 递归返回后，紧接着就执行 `st[u]=false` 并再次递归，两次递归的路径互不干扰。第一次递归返回时 `st[u]` 可能还是 true，但第二段会把它覆盖为 false。对于本层而言已经完成了所有子节点，本层返回后上一层的 `st[u-1]` 仍然是上一层的值，没有问题。

- **递归树结构示例（n=3）**：
  ```
                    []
            /              \
        选1: [1]          不选1: []
       /    \             /     \
  选2:[1,2] 不选2:[1] 选2:[2] 不选2:[]
    /  \      /  \      /  \     /  \
  ...（共 8 个叶子）
  ```
  每个叶子对应一个子集，正好 $2^3$ = 8 个。

- **空子集的处理**：`st[1..n]` 全为 false 时，遍历不会输出任何数字，只输出一个 `endl`（空行）。这是合法的方案（"选了 0 个数字"），样例的第一行就是空的。

- **复杂度分析**：方案总数为 $2^n$，n ≤ 15 时最多 32768 种方案。每个方案输出最多 n 个数字，总输出量约 $2^n$ × n ≈ 5×$10^5$ 个数字，完全可行。时间复杂度 O(n·$2^n$)，空间复杂度 O(n)（递归栈 + st 数组）。

- **扩展思考——位运算替代法**：这题也可以不用 DFS，直接用一个整数从 0 到 $2^n$-1 循环，整数的二进制第 i 位为 1 表示选 i。这种方法代码更短，且方案按字典序排列。例如 n=3：
  ```
  for (int mask = 0; mask < (1 << n); mask++) {
      for (int i = 1; i <= n; i++)
          if (mask >> (i-1) & 1)
              cout << i << " ";
      cout << endl;
  }
  ```
  DFS 和位运算两种写法都应该掌握，DFS 更直观，位运算更简洁。

- **易错点**：
  - 数组索引：`st[u]` 中 u 的范围是 1~n，所以数组大小需要 ≥ n+1（代码中 N=29 是够的）。不要从 0 开始。
  - 输出时每个数字后有一个空格，包括最后一个数字后也有（代码写的是 `cout << i << " "`）。虽然 OJ 使用了 SPJ（Special Judge），行末有多余空格通常也能通过，但在非 SPJ 的题目中这可能被判错。
  - 这题有 SPJ（Special Judge），意味着方案的排列顺序任意，不用担心 DFS 顺序是否"正确"——只要所有方案都输出且每种恰好一次即可。

<a id="link05-假币问题"></a>

## LinK05 假币问题

### 题目描述

林克有 12 枚银币（A-L），其中 11 枚真币和 1 枚假币。假币重量不同但不知道是轻还是重。天平称了三次，给定三次称量结果，找出假币并判断轻重。

### 输入

第一行 n 表示测试组数。每组三行，每行格式：`左边硬币 右边硬币 结果`（结果：`even`/`up`/`down`）。

### 样例

**输入：**
```
1
ABCD EFGH even
ABCI EFJK up
ABIJ EFGH even
```

**输出：**
```
K is the counterfeit coin and it is light.
```

### 我的代码

```cpp
#include <iostream>
#include <cstring>
using namespace std;

string Left[3], Right[3], result[3];

bool isfeitcoin(char icoin, bool islight)
{
    string c;
    c.push_back(icoin);
    for (int i = 0; i < 3; i++)
    {
        string l = Left[i], r = Right[i];
        if (!islight) swap(l, r);
        switch (result[i][0])
        {
            case 'e':
                if (l.find(c) != string::npos || r.find(c) != string::npos)
                    return false;
                break;
            case 'u':
                if (r.find(c) == string::npos) return false;
                break;
            case 'd':
                if (l.find(c) == string::npos) return false;
                break;
        }
    }
    return true;
}

int main()
{
    int t; cin >> t;
    while (t--)
    {
        for (int i = 0; i < 3; ++i)
            cin >> Left[i] >> Right[i] >> result[i];
        for (char icoin = 'A'; icoin <= 'L'; icoin++)
        {
            if (isfeitcoin(icoin, true))
            { cout << icoin << " is the counterfeit coin and it is light." << endl; break; }
            else if (isfeitcoin(icoin, false))
            { cout << icoin << " is the counterfeit coin and it is heavy." << endl; break; }
        }
    }
    return 0;
}
```

### 思路要点

- **题目本质**：这是一道经典的逻辑推理编程题——给定三次天平称量的结果，找出 12 枚硬币中唯一的一枚假币，并确定它是轻还是重。题目保证三次称量数据一定可以唯一确定假币。核心思想是**枚举 + 假设验证**：对每一枚硬币，假设它是假币（分别假设轻和重两种可能），然后用三次称量结果去检验这个假设是否自洽。

- **枚举策略**：硬币只有 12 枚（A-L），对于每一枚硬币有两种可能（轻或重），总共 24 种假设。对每种假设，代入三次称量结果检查是否矛盾。如果某假设使得三次称量全部自洽，那么它就是正确答案。数据量极小，24×3 次检查常数时间即可完成。

- **验证逻辑详解（`isfeitcoin` 函数）**：
  - 参数 `icoin` 是当前假设的假币字母，`islight` 表示假设它轻（true）还是重（false）。
  - 如果 `islight` 为 false（即假设假币重），则 swap 左右两边的字符串。这个技巧将"假币重"的情况转化为"假币轻"的对称问题：假币重时，它在哪边哪边就下沉，等价于交换左右后假币轻时对面下沉。这样做避免了写两套相似的判断逻辑。
  - 然后遍历三次称量，根据结果验证：
    - **`even`（平衡）**：假币不能出现在天平的任何一边。如果假币在左边或右边，说明这个假设错误。
    - **`up`（右边高）**：在假币轻的假设下，假币必须出现在右边（因为右边轻才会翘起）。如果假币不在右边，假设错误。
    - **`down`（右边低）**：在假币轻的假设下，假币必须出现在左边（因为左边轻才会下沉）。如果假币不在左边，假设错误。

- **为什么 `up` 和 `down` 的物理意义是这样**：题目中的 `up` 表示右端高（即右边轻），`down` 表示右端低（即右边重）。如果假币是轻的，它所在的一侧会翘起。所以 `up` 时轻假币应在右边，`down` 时轻假币应在左边。重假币的情况恰好相反，因此通过 swap 左右来统一处理。

- **string 的查找操作**：`l.find(c) != string::npos` 检查字符 c 是否在字符串 l 中出现。由于天平每次称量左右两边硬币数相等且每枚硬币只会出现一次（或不出现在某次称量中），所以用 find 就能判断假币是否在某一侧。

- **复杂度分析**：枚举 12 枚币 × 2 种轻重 = 24 种假设。每种假设检查 3 次称量字符串查找，每次 O(字符串长度) ≈ O(4)。总复杂度 O(24×3×4) = O(1)，完全不需考虑性能。

- **易错点**：
  - 理解题目中 `up` 和 `down` 的含义至关重要——`up` 是右端高（右边轻），`down` 是右端低（右边重），不要搞反。
  - swap 的时机：只有当 `islight == false` 时才交换 l 和 r。这是将"假币重"映射为"假币轻交换左右"的标准手法，理解了这个就不容易写错。
  - 一旦找到匹配的假设就 break 跳出循环（代码中用了 break），因为题目保证数据唯一确定假币。
  - 输出格式严格匹配：`K is the counterfeit coin and it is light.` 或 `...heavy.`，注意大小写和空格。

<a id="link09-汉诺塔i"></a>

## LinK09 汉诺塔I

### 题目描述

三根杆 A、B、C，A 有 N 个穿孔圆盘（由下到上变小）。移到 C 杆，每次只能移一个，大盘不能叠小盘。输出移动步骤。

### 样例

**输入：** `3`
**输出：** `A->C / A->B / C->B / A->C / B->A / B->C / A->C`

### 我的代码

```cpp
#include <iostream>
using namespace std;

void move(char start, char target) { cout << start << "->" << target << endl; }

void hanoi(int n, char start, char other, char target)
{
    if (n == 1) { move(start, target); return; }
    hanoi(n - 1, start, target, other);
    move(start, target);
    hanoi(n - 1, other, start, target);
}

int main() { int n; cin >> n; hanoi(n, 'A', 'B', 'C'); return 0; }
```

### 思路要点

- **题目本质**：汉诺塔是递归思想的"Hello World"——将 N 个盘从 A 柱移到 C 柱，B 柱作为辅助。递归的核心在于将大问题分解为"移动上面 N-1 个盘"和"移动最底下 1 个盘"两个子问题。

- **递归三步法**：
  1. **将 N-1 个盘从 A 移到 B**（借助 C 作为中转）。此时 A 只剩最大的盘，B 有 N-1 个较小的盘，C 为空。
  2. **将最大的盘从 A 移到 C**。这是一步直接操作（`A->C`），不需要递归。
  3. **将 N-1 个盘从 B 移到 C**（借助 A 作为中转）。此时所有盘已在 C，完成。

- **递归终止条件**：当 `n == 1` 时，只剩一个盘，直接移动即可（`A->C`），不再递归。

- **递推关系与移动次数**：设 `T(n)` 为移动 n 个盘所需的最少步数。
  ```
  T(n) = T(n-1) + 1 + T(n-1) = 2·T(n-1) + 1
  T(1) = 1
  ```
  展开得 `T(n) = 2ⁿ - 1`。N=3 时需要 7 步，N=64 时需要约 1.8×$10^{19}$ 步（这就是"世界末日"传说的由来）。

- **递归调用栈的直观理解**：`hanoi(3, A, B, C)` 展开：
  ```
  hanoi(2, A, C, B)      → A->B, A->C, B->C  （把两个小盘搬到B）
  A->C                    → （最大盘直接到C）
  hanoi(2, B, A, C)      → B->A, B->C, A->C  （两个小盘从B搬到C）
  ```

- **复杂度分析**：时间复杂度 O($2^n$)，移动次数 = $2^n$-1。空间复杂度 O(n)（递归栈深度）。虽然复杂度是指数级，但 n ≤ 20 时 $2^{20}$-1 ≈ $10^6$ 次移动，在输出限制下完全可行。

- **易错点**：
  - 递归调用时中间参数顺序不能搞错：`hanoi(n-1, start, target, other)` 表示"把上面 n-1 个盘从 start 借助 target 移到 other"，对应汉诺塔第一步。第三个参数是"目标柱"，第四个参数是"辅助柱"。
  - `move(a, b)` 输出的是 `a -> b`，格式为 `A->C`，不要写成 `A -> C`（多了空格）。
  - 递归终止不要忘记 `return`，否则 n=1 时会继续执行后面的递归调用导致无限递归。

<a id="link10-汉诺塔ii"></a>

## LinK10 汉诺塔II

### 题目描述

与 I 相同，但输入包含杆子编号（如 `3 a b c`），输出格式为 `盘号:起始->目标`（如 `1:a->c`）。

### 样例

**输入：** `3 a b c`

**输出：**
```
1:a->c
2:a->b
1:c->b
3:a->c
1:b->a
2:b->c
1:a->c
```

### 我的代码

```cpp
#include <iostream>
using namespace std;

void move(int id, char start, char target) { cout << id << ":" << start << "->" << target << endl; }

void hanoi(int n, int id, char start, char other, char target)
{
    if (n == 1) { move(id, start, target); return; }
    hanoi(n - 1, id, start, target, other);
    int newid = id + n - 1;
    move(newid, start, target);
    hanoi(n - 1, id, other, start, target);
}

int main()
{
    char a, b, c; int n;
    cin >> n >> a >> b >> c;
    hanoi(n, 1, a, b, c);
}
```

### 思路要点

- **题目本质**：与汉诺塔 I 逻辑完全一致，区别在于两点：① 杆子的编号不再是固定的 A/B/C，而是由输入指定（如 `a b c`）；② 输出格式要求带盘号（如 `1:a->c`），圆盘从小到大编号为 1 到 n。

- **盘号追踪的关键**：递归时每个盘子都有唯一的编号。在 `hanoi(n, id, start, other, target)` 中，参数 `id` 表示当前这组盘子中最小的那个盘的编号。当递归处理 `n` 个盘时：
  - 最上面的 n-1 个盘的起始编号仍是 `id`（它们比下面的盘都小，所以编号从 `id` 开始）。
  - 移动最大盘时，它的编号 = `id + n - 1`。因为上面有 n-1 个更小的盘，编号从 id 到 id+n-2，最大盘就是 id+n-1。
  - 举例：n=3, id=1 时，三个盘的编号分别为 1、2、3。递归处理上面 2 个盘（编号 1、2）时传入 id=1；移动最底下盘时编号 = 1+3-1 = 3，正是最大的盘。

- **与汉诺塔 I 的对比**：

| 方面 | 汉诺塔 I | 汉诺塔 II |
|------|---------|----------|
| 柱子编号 | 固定 A/B/C | 输入指定（如 a/b/c） |
| 输出格式 | `A->C` | `1:a->c`（盘号:起始->目标） |
| 递归参数 | (n, start, other, target) | (n, id, start, other, target) |

- **复杂度分析**：与汉诺塔 I 完全相同，O($2^n$) 时间，O(n) 递归栈空间。

- **易错点**：
  - 递归调用 `hanoi(n-1, id, start, target, other)` 时第二个参数仍然是 `id` 而不是 `id+1`——因为上面 n-1 个盘中最小的盘子编号和原来一样。
  - 最大盘编号是 `id + n - 1` 而不是 `id + n`。如果写成 `id + n`，对于 n=3, id=1 的调用会输出盘号 4（但总共只有 3 个盘）。
  - 柱子编号从输入读取，不是硬编码为 A/B/C。

<a id="link15-爬天梯"></a>

## LinK15 爬天梯

### 题目描述

天梯 N 阶，每次可以走 1 阶或 2 阶，求总共有多少种不同走法。

### 样例

**输入：** `3` → **输出：** `3`

### 我的代码

```cpp
#include <iostream>
using namespace std;
const int mod = 1000000007;

int stairs(int n)
{
    if (n <= 1) return 1;
    return (stairs(n - 1) + stairs(n - 2)) % mod;
}

int main() { int N; cin >> N; cout << stairs(N) << endl; return 0; }
```

### 思路要点

- **题目本质**：经典的"爬楼梯"问题——每次可以走 1 阶或 2 阶，求到达第 N 阶的不同走法数。这就是斐波那契数列的变体：`f(n) = f(n-1) + f(n-2)`。

- **递推关系的推导**：考虑最后一步的走法——要到达第 N 阶，最后一步要么从第 N-1 阶走 1 阶上来，要么从第 N-2 阶走 2 阶上来。这两种情况互斥且覆盖了全部可能，因此 `f(n) = f(n-1) + f(n-2)`。

- **边界条件**：`f(0) = 1`（0 阶视为 1 种走法——站着不动），`f(1) = 1`（只能走一步 1 阶）。这与标准斐波那契的 F(1)=1, F(2)=1 等价（如果 N 从 1 开始的话 f(2) = f(1) + f(0) = 2，即走两次 1 阶或一次 2 阶两种）。

- **取模问题**：题目要求结果对 1000000007 取模。这个数是一个常用的大质数（约 $10^9$），用来防止结果溢出。斐波那契数列增长极快——F(46) ≈ 1.8×$10^9$，F(100) ≈ 3.5×$10^{20}$。代码中的 `(stairs(n-1) + stairs(n-2)) % mod` 在每次递归返回时取模，保证了中间结果不溢出。

- **纯递归 vs 记忆化**：代码使用了纯递归，时间复杂度 O($2^n$)，因为 `stairs(n-1)` 和 `stairs(n-2)` 中有大量重复计算（比如 `stairs(n-2)` 被算了两次，`stairs(n-3)` 被算了三次...）。N ≤ 46 时纯递归最坏需要计算约 $2^{46}$ ≈ 7×$10^{13}$ 次，实际上运行会很慢甚至超时。**改进方案**：使用记忆化数组 `memo[N]` 存储已计算的结果，或将递归改为迭代 `for (i=2; i<=N; i++) dp[i] = (dp[i-1] + dp[i-2]) % mod`，时间降为 O(N)。

- **复杂度分析**：纯递归 O($2^n$) 时间、O(n) 空间（递归栈）。迭代版 O(N) 时间、O(N) 或 O(1) 空间（只需要保留前两个值）。

- **易错点**：
  - 取模的位置：必须在加法之后立即取模 `(a + b) % mod`，而不是 `a % mod + b % mod`（后者可能两个都 > mod/2 时溢出 int）。
  - `mod = 1000000007` 而不是 `1000000009` 或 `1e9+7`（虽然它们很接近，但 OJ 常用的是 1e9+7）。
  - N=0 的边界处理：有些写法 `f(0)=0` 会导致 `f(2) = f(1) + f(0) = 1` 而正确答案是 2。确认 `f(0)=1` 是此题的规范。

<a id="link20-递归实现组合型枚举"></a>

## LinK20 递归实现组合型枚举

### 题目描述

从 1∼n 中随机选出 m 个，输出所有可能的组合方案。行内升序，行间字典序。

### 样例

**输入：** `5 3` → 输出 C(5,3) = 10 种组合。

### 我的代码

```cpp
#include <iostream>
using namespace std;

const int N = 30;
int n, m, path[N];

void dfs(int u, int start)
{
    if (u > m)
    {
        for (int i = 1; i <= m; i++) cout << path[i] << " ";
        cout << endl;
    }
    else
    {
        for (int i = start; i <= n; i++)
        { path[u] = i; dfs(u + 1, i + 1); }
    }
}

int main() { cin >> n >> m; dfs(1, 1); return 0; }
```

### 思路要点

- **题目本质**：从 n 个元素中选出恰好 m 个，输出所有 C(n,m) 种组合。与子集枚举（LinK19，选任意多个）和排列枚举（LinK21，顺序敏感）不同，组合不关心顺序——{1,3} 和 {3,1} 是同一组合，只输出一次。因此需要在 DFS 中**强制升序**以避免重复。

- **DFS 设计——start 参数的关键作用**：
  - `dfs(u, start)`：`u` 表示当前正在选第几个数（1~m），`start` 表示当前可选数字的最小值。
  - 在 `for (int i = start; i <= n; i++)` 中，只从 `start` 开始枚举，选中 `i` 后递归调用 `dfs(u+1, i+1)`。
  - 因为下一层从 `i+1` 开始，后面的数一定大于前面的数，天然保证升序。同时也保证了每种组合只生成一次（不会产生 {1,3} 和 {3,1} 两个版本）。

- **与 LinK19（子集枚举）的对比**：
  - 子集枚举：每个元素有"选/不选"两个分支，递归深度 = n，叶子数 = $2^n$。
  - 组合枚举：每层选一个数（只选不放回），递归深度 = m，叶子数 = C(n,m)。
  - 组合枚举的 for 循环从 start 开始，子集枚举没有 for 循环（只有两条固定分支）。

- **递归终止**：`u > m` 表示已经选满了 m 个数，输出 `path[1..m]` 即可。由于枚举时强制升序，path 中的数据已经是升序的。

- **剪枝优化**：当剩余可选数字不足以填满剩余位置时，可以提前返回。例如还剩 `m-u+1` 个位置要填，但只剩 `n-start+1` 个数字可用，如果 `n-start+1 < m-u+1` 则不可能完成。这被称为"组合数的剪枝"，可以进一步缩小搜索空间。代码中没有显式实现这个剪枝（因为 n 和 m 很小），但加上 `if (n - start + 1 < m - u + 1) return;` 即可。

- **复杂度分析**：生成 C(n,m) 种组合，每种组合输出 m 个数。总量级 ≤ C(15,7) = 6435（n≤15 时最大），完全可以接受。时间复杂度 O(C(n,m) × m)，空间复杂度 O(m)（递归栈 + path 数组）。

- **易错点**：
  - `dfs(u+1, i+1)` 而不是 `dfs(u+1, start+1)`。第二个参数是 `i+1`（当前选中值的下一个），这样才能保证选出的数严格递增。
  - 输出格式：每个数后面有一个空格（`cout<<path[i]<<" "`），末尾空格在 SPJ 下通常忽略，但非 SPJ 时可能 PE。
  - path 数组索引从 1 开始（`path[1..m]`），注意数组大小 ≥ m+1。

## LinK21 递归实现排列型枚举

### 题目描述

输出 1∼n 的所有排列，按字典序从小到大。

### 样例

**输入：** `3` → 输出 123、132、213、231、312、321。

### 我的代码

```cpp
#include <iostream>
using namespace std;

const int N = 15;
int n, path[N];
bool st[N];

void dfs(int u)
{
    if (u > n)
    {
        for (int i = 1; i <= n; i++) cout << path[i] << " ";
        cout << endl;
    }
    else
    {
        for (int i = 1; i <= n; i++)
            if (!st[i])
            { path[u] = i; st[i] = true; dfs(u + 1); st[i] = false; }
    }
}

int main() { cin >> n; dfs(1); return 0; }
```

### 思路要点

- **题目本质**：输出 1∼n 的所有排列，按字典序。n 个元素的全排列有 n! 种。与组合不同，排列对顺序敏感——{1,2} 和 {2,1} 是不同排列，都要输出。

- **DFS 设计——布尔标记数组的作用**：
  - `path[u]` 记录第 u 个位置放的数字。
  - `st[i]` 标记数字 i 是否已经被使用。这是排列和组合最本质的区别：组合用 `start` 参数防止重复选同一个元素，排列用 `st[]` 标记。
  - 每一层 DFS，遍历 1∼n 的所有数字，跳过已标记的（`if (!st[i])`）。选中后标记 `st[i]=true`，递归下一层，回溯时恢复 `st[i]=false`。

- **为什么排列不需要 start 参数**：组合中 {1,2} 和 {2,1} 被视为同一个结果，所以需要用 start 强制升序来去重。排列中两者是不同的，所以每一层都要尝试所有未使用的数字，不需要 start 限制。

- **字典序的天然保证**：因为 DFS 每层从 1 到 n 从小到大尝试，先产生的排列一定字典序较小。例如 `path[1]` 先尝试 1（此时后面可以是任意排列），所有以 1 开头的排列都输出完后，`path[1]` 再尝试 2，以此类推。这与字典序的定义完全一致（先比较第一个数，再比较第二个数...）。

- **回溯三部曲**：
  1. 做选择：`path[u] = i; st[i] = true;`
  2. 递归：`dfs(u+1);`
  3. 撤销选择（回溯）：`st[i] = false;`（path[u] 会被下一轮循环覆盖，不需显式清除）。

  回溯是排列 DFS 的关键——如果不恢复 `st[i]`，下一个 i 值的分支就无法使用数字 i，导致漏解。这与组合枚举的 start 方式有本质区别（组合通过递增 start 隐式"排除"已用元素，而非通过标记-回溯）。

- **与 LinK19/20 的对比总结**：

| 方面 | 子集枚举 (LinK19) | 组合枚举 (LinK20) | 排列枚举 (LinK21) |
|------|-------------------|-------------------|-------------------|
| 是否顺序敏感 | 否 | 否 | **是** |
| 去重方式 | 按值递增决策 | start 参数强制升序 | st[] 标记已用 |
| 递归深度 | n | m | n |
| 叶子数 | $2^n$ | C(n,m) | n! |
| 回溯显式恢复 | 不需要（覆盖写入） | 不需要 | **需要** st[] 恢复 |

- **复杂度分析**：n ≤ 9 时 n! ≤ 362880。每个排列输出 n 个数，总输出量约 n × n! ≤ 3.3×$10^6$ 个数字，完全可接受。时间复杂度 O(n × n!)，空间复杂度 O(n)。

- **易错点**：
  - `st[i]` 的回溯恢复绝对不能忘——忘记 `st[i] = false` 会导致每个数字只能用一次，后面的排列会大量缺失。这是排列 DFS 最常见的 bug。
  - `path[u]=0`（代码中）实际上可以省略，因为下一轮循环会覆盖它。但写了也没坏处，有助于代码可读性。
  - `path` 数组索引从 1 开始（u 的范围 1~n），注意数组大小至少 n+1。

## LinK27 大数排序

### 题目描述

给定长度为 n（≤ 100000）的数列，用快速排序按升序输出。

### 样例

**输入：** `12` + 12个大整数 → 输出排序后序列。

### 我的代码

```cpp
#include <iostream>
using namespace std;

const int N = 1000010;
int q[N];

void quick_sort(int q[], int l, int r)
{
    if (l >= r) return;
    int i = l - 1, j = r + 1, x = q[l + r >> 1];
    while (i < j)
    {
        do i++; while (q[i] < x);
        do j--; while (q[j] > x);
        if (i < j) swap(q[i], q[j]);
    }
    quick_sort(q, l, j);
    quick_sort(q, j + 1, r);
}

int main()
{
    int n; scanf("%d", &n);
    for (int i = 0; i < n; i++) scanf("%d", &q[i]);
    quick_sort(q, 0, n - 1);
    for (int i = 0; i < n; i++) printf("%d ", q[i]);
    return 0;
}
```

### 思路要点

- **题目本质**：手动实现快速排序对 n ≤ 100000 的数组排序。与 LinK04（用 `std::sort`）不同，这里要求自己写排序算法。快速排序是分治法最经典的例子，核心在于 partition 操作将数组分为左右两部分。

- **快速排序模板详解**（ACWing 风格的 Y 总模板）：
  - **选取 pivot**：`x = q[l + r >> 1]`，取中间位置的元素作为基准值。取左端点或右端点在有序/逆序数组上会退化为 O($N^2$)，取中间值是常见优化。
  - **双指针 partition**：`i = l - 1, j = r + 1`，然后 `do i++; while (q[i] < x)` 和 `do j--; while (q[j] > x)`。当 i 和 j 都停下时（q[i] >= x 且 q[j] <= x），如果 i < j 则交换 q[i] 和 q[j]。
  - **关键**：模板使用 `while (i < j)` 外循环 + `do-while` 内循环，保证了 i 和 j 最终交错。partition 结束时 j 指向左侧区域的末尾，i 指向右侧区域的开头。
  - **递归**：`quick_sort(q, l, j)` 和 `quick_sort(q, j+1, r)`。**注意**：如果用 j 作为分界，pivot 不能选 q[r]（右端点），否则在特定情况下会无限递归。Y 总模板的注意事项：x = q[l+r>>1] 配合 j 递归，或 x = q[l+r+1>>1] 配合 i 递归。
  - **为什么 i 和 j 的初始值是 l-1 和 r+1**：因为 do-while 会无条件先执行一次 `i++`/`j--`，如果初始值是 l 和 r，第一次循环会跳过第一个/最后一个元素。

- **为什么不用 std::sort**：`std::sort` 是内省排序（快排+堆排+插排混合），底层也是快速排序的思想。手动实现的目的是理解快排的双指针 partition 过程和分治思想。

- **与归并排序（LinK30）的对比**：
  | 方面 | 快速排序 | 归并排序 |
  |------|---------|---------|
  | 分治顺序 | 先 partition 划分，再递归 | 先递归，再 merge 合并 |
  | 稳定性 | 不稳定 | **稳定** |
  | 最坏复杂度 | O($N^2$)（有序时） | O(N log N)（始终稳定） |
  | 额外空间 | O(log N) 递归栈 | O(N) 临时数组 |

- **输入输出优化**：N ≤ 100000，cin/cout 在关闭同步（`ios::sync_with_stdio(false)`）或使用 scanf/printf 时可以高效处理。代码使用 scanf/printf 避免了 IO 瓶颈。

- **复杂度分析**：平均 O(N log N)，最坏 O($N^2$)（数组已有序且选左端点为 pivot 时）。每次 partition 将数组大致均分时效率最高。递归深度平均 O(log N)，最坏 O(N)。

- **易错点**：
  - pivot 选择与递归区间的匹配关系：`x = q[l+r>>1]`（偏向中间偏左）配合 `(l, j)` 和 `(j+1, r)`；`x = q[l+r+1>>1]`（偏向中间偏右）配合 `(l, i-1)` 和 `(i, r)`。弄反会导致死循环或越界。
  - 不要写成 `while (q[i] < x) i++` 而是 `do i++; while (q[i] < x)`。前者在没有小于 x 的元素时 i 不会前进，导致死循环。
  - 数组大小：N ≤ 100000，但代码中 `const int N=1000010` 留了余量（多一个数量级），是个好习惯。

## LinK30 归并排序

### 题目描述

使用归并排序对数组排序，N ≤ 100000。

### 样例

输入 `3 1 2 4 5`，输出 `1 2 3 4 5`。

### 我的代码

```cpp
#include <iostream>
using namespace std;

const int N = 100007;
int numbers[N], tmp[N];

void mergesort(int nums[], int left, int right)
{
    if (left >= right) return;
    int mid = left + right >> 1;
    mergesort(nums, left, mid), mergesort(nums, mid + 1, right);
    int k = 0, p = left, q = mid + 1;
    while (p <= mid && q <= right)
        tmp[k++] = nums[p] <= nums[q] ? nums[p++] : nums[q++];
    while (p <= mid) tmp[k++] = nums[p++];
    while (q <= right) tmp[k++] = nums[q++];
    for (int i = left, k = 0; i <= right; i++, k++) nums[i] = tmp[k];
}

int main()
{
    int n; scanf("%d", &n);
    for (int i = 0; i < n; i++) scanf("%d", &numbers[i]);
    mergesort(numbers, 0, n - 1);
    for (int i = 0; i < n; i++) printf("%d ", numbers[i]);
    return 0;
}
```

### 思路要点

- **题目本质**：手动实现归并排序。与快排"先分后排"不同，归并排序是"先递归到底，再合并回来"。它是稳定的 O(N log N) 排序算法，也是求逆序对（LinK31）的基础。

- **归并排序三步走**：
  1. **分（Divide）**：计算中点 `mid = left + right >> 1`，递归排序左半 `[left, mid]` 和右半 `[mid+1, right]`。
  2. **治（Conquer/Merge）**：双指针 `p = left` 和 `q = mid + 1`，比较 `nums[p]` 和 `nums[q]` 的大小，较小的放入临时数组 `tmp[]`。
  3. **复制回原数组**：将 `tmp[0..k-1]` 复制回 `nums[left..right]`。

- **归并过程详解**：
  ```
  左半: [3, 5, 7]  右半: [1, 4, 6]
  p → 3, 5, 7        q → 1, 4, 6
  ```
  - 第一次比较：3 > 1，1 入 tmp，q++。
  - 第二次比较：3 < 4，3 入 tmp，p++。
  - 依次类推...最终某个半区先耗尽，将另一半剩余元素直接追加到 tmp。
  - tmp 最终为 `[1, 3, 4, 5, 6, 7]`。

- **稳定性**：如果 `nums[p] == nums[q]`，先取 `nums[p]`（左半元素），这样可以保持相等元素的原始相对顺序。代码中的 `nums[p] <= nums[q]`（带等号）正是为了确保稳定性。

- **与快速排序的选择**：
  - 归并排序：始终 O(N log N)，稳定，但需要 O(N) 额外空间（tmp 数组）。
  - 快速排序：平均 O(N log N)，最坏 O($N^2$)，不稳定，但常数更小且原地排序。
  - 需要稳定排序或求逆序对时用归并；追求速度和空间效率时用快排。

- **复杂度分析**：时间 O(N log N)（每次归并 O(N)，共 log N 层）。空间 O(N)（临时数组 tmp）。递归栈深度 O(log N)。

- **易错点**：
  - 递归终止条件 `if (left >= right) return` 别忘了，否则无限递归。
  - 归并后一定要把 tmp 复制回原数组（代码中 `for (int i = left, k = 0; i <= right; i++, k++) nums[i] = tmp[k]`），否则上层归并看到的是未排序的数据。
  - `tmp[k++] = nums[p++]` 这种写法要确保理解 p 和 k 都后置递增。
  - `mid = left + right >> 1` 的优先级：`>>` 低于 `+`，所以等价于 `(left + right) / 2`。

## LinK31 求排列的逆序数

### 题目描述

给定 n 个数的排列，求其逆序对数量（i < j 且 a_i > a_j）。n ≤ 100000。

### 样例

输入 `2 6 3 4 5 1`，输出 `8`。

### 我的代码

```cpp
#include <iostream>
using namespace std;

const int N = 100007;
int numbers[N], tmp[N];

long long mergesort(int nums[], int left, int right)
{
    if (left >= right) return 0;
    int mid = left + right >> 1;
    long long result = mergesort(nums, left, mid) + mergesort(nums, mid + 1, right);
    int k = 0, p = left, q = mid + 1;
    while (p <= mid && q <= right)
    {
        if (nums[p] <= nums[q]) tmp[k++] = nums[p++];
        else { result += mid - p + 1; tmp[k++] = nums[q++]; }
    }
    while (p <= mid) tmp[k++] = nums[p++];
    while (q <= right) tmp[k++] = nums[q++];
    for (int i = left, k = 0; i <= right; i++, k++) nums[i] = tmp[k];
    return result;
}

int main()
{
    int n; scanf("%d", &n);
    for (int i = 0; i < n; i++) scanf("%d", &numbers[i]);
    cout << mergesort(numbers, 0, n - 1);
    return 0;
}
```

### 思路要点

- **题目本质**：给定一个 n 个数的排列，求其逆序对的数量。逆序对定义为 `i < j` 且 `a[i] > a[j]`。逆序数衡量排列的"无序程度"——升序排列逆序数为 0，降序排列逆序数为 n(n-1)/2（最大）。求逆序对是归并排序的经典应用。

- **为什么不能用暴力枚举**：n ≤ 100000，如果暴力双重循环 O($N^2$) ≈ $10^{10}$ 次比较，必定超时。需要 O(N log N) 的算法。

- **归并排序求逆序对的原理**：在归并过程（Merge）中，当右半元素 `nums[q]` 小于左半元素 `nums[p]` 时：
  - 左半 `[p..mid]` 是已排序的，所以如果 `nums[q] < nums[p]`，那么 `nums[q]` 也小于 `nums[p+1], nums[p+2], ..., nums[mid]`。
  - 对于 `nums[q]`，左半中所有大于它的元素都与它构成逆序对，数量恰好是 `mid - p + 1`（左半从 p 到 mid 共这么多个元素）。
  - 关键：这些逆序对在排序过程中被"消除"了（因为归并后 `nums[q]` 会被放到 `nums[p]` 前面），所以这一步必须记录下来。

- **归并求逆序对的直观理解**：
  ```
  左半（已排序）: [2, 6, 8]   右半（已排序）: [1, 4, 9]
                     ↑p=0                  ↑q=0
  ```
  - `nums[q]=1 < nums[p]=2`，说明 1 比左半所有 3 个元素都小（因为左半已排序，最小的 2 都比 1 大），贡献 3 个逆序对：(2,1)、(6,1)、(8,1)。`result += 3`，q++。
  - 现在 `nums[p]=2 < nums[q]=4`，2 正常归入 tmp，p++。
  - `nums[q]=4 < nums[p]=6`，贡献 `3-1 = 2` 个逆序对（4 比 6 和 8 小），q++。
  - ...依此类推。

- **三重返回值设计**：函数返回值是 `long long`，因为逆序数可能超过 int 范围。n=100000 的降序排列有 `100000×99999/2 ≈ 5×10⁹` 个逆序对，而 int（32 位）上限约 2.1×$10^9$，会溢出。

- **复杂度分析**：在归并排序的基础上增加 O(1) 操作（`result += mid-p+1`），总复杂度仍然是 O(N log N)。空间复杂度 O(N)。

- **易错点**：
  - 返回值类型必须是 `long long`，不能用 `int`。代码中 `mergesort` 返回 `long long`，`result` 也声明为 `long long`。
  - 不能在 `nums[p] <= nums[q]` 时计数——必须严格 `<` 时才计数。等号时不构成逆序（因为 a[i] = a[j] 不满足 a[i] > a[j]）。
  - 递归时 `result` 是左右子区间逆序数之和，加上当前归并过程中发现的跨区间逆序对。三个部分缺一不可。

## LinK38 林克的命运之阵

### 题目描述

在方格矩阵中从任意位置出发，只能向下/左/右走，不能重复访问。求走 n 步的不同路径数。n ≤ 20。

### 样例

n=2 → 7 种；n=20 → 54608393。

### 我的代码

```cpp
#include <iostream>
#include <cstring>
using namespace std;

const int N = 70;
int fates[N][N];
int dx[3] = {0, 0, 1}, dy[3] = {-1, 1, 0};

long long dfs(int i, int j, int n)
{
    if (n == 0) return 1;
    long long res = 0;
    fates[i][j] = 1;
    for (int k = 0; k < 3; k++)
    {
        int x = i + dx[k], y = j + dy[k];
        if (fates[x][y] == 0) res += dfs(x, y, n - 1);
    }
    fates[i][j] = 0;
    return res;
}

int main()
{
    int n; cin >> n;
    cout << dfs(0, N / 2, n) << endl;
    return 0;
}
```

### 思路要点

- **题目本质**：在无限网格中，从起点出发只能向下、左、右三个方向走（不能向上），不能重复访问已走过的格子。求走 n 步的不同路径数。这实际上是一个受限的"自回避行走"（self-avoiding walk）计数问题——三个方向 + 不走回头路 = 每次最多 3 种选择。

- **为什么只有三个方向**：题目规定"从第 1 行出发，只能向下、左、右三个方向走"。这意味着整体趋势是向下的（类似于不断前进的时间线），不能回头往上走。这大大限制了搜索空间——如果四个方向都能走，n=20 时搜索树会大得多。

- **DFS 回溯实现细节**：
  - `fates[i][j] = 1` 标记当前格子已访问（进入格子），`fates[i][j] = 0` 回溯（离开格子）。这是典型的不走回头路的实现方式——标记访问过的格子，递归返回时恢复。
  - `if (fates[x][y] == 0) res += dfs(x, y, n - 1)` ——只走未访问的格子。
  - 递归终止：`n == 0` 时返回 1（走了 0 步，当前路径算一种方案）。

- **从中心位置出发的原因**：`dfs(0, N/2, n)` 从数组的中心列开始，给左右走留出足够空间。N=70 意味着左右各有约 35 列的缓冲区，对于最多 20 步（每步最多偏移 1 列）足够了。

- **为什么 $3^n$ 的上界在实际中远小于此**：
  - 虽然每次有 3 个方向可选，但回溯到之前访问过的格子会剪掉很多分支。
  - 随着步数增加，可选的合法方向越来越少（因为不能走回头路，已访问格子逐渐围成"死胡同"）。
  - 实际上 n=20 时答案只有 54608393（约 5.4×$10^7$），远小于 $3^{20}$ ≈ 3.5×$10^9$，说明剪枝效果显著。

- **复杂度分析**：理论上界 O($3^n$)，实际远小于此因为大量路径被剪枝。n ≤ 20 时，总探索节点数可接受（答案本身约 5×$10^7$）。空间复杂度 O($N^2$)（数组 fates[][]）。

- **易错点**：
  - 回溯时必须恢复 `fates[i][j] = 0`。如果不恢复，后续递归分支会错误地认为该格不可达，导致漏解。
  - 数组大小 N=70 是为了给搜索留足够空间。如果有人调大 n 超过 20，可能需要增大 N。
  - 方向数组 `dx[3] = {0, 0, 1}` 和 `dy[3] = {-1, 1, 0}` 对应左、右、下三个方向，没有向上。
  - 结果可能很大（n=20 时约 5×$10^7$），需要用 `long long` 存储。

<a id="link39-净化迷雾森林"></a>

## LinK39 净化迷雾森林

### 题目描述

W×H 网格，`.`表示可走，`#`表示墙，`@`表示起点。从起点走四方向可达的 `.` 区域数量（Flood Fill）。

### 样例

6×9 地图，输出 45。

### 我的代码

```cpp
#include <iostream>
using namespace std;

int w, h;
char fogforest[27][27];

int dfs(int i, int j)
{
    int res = 1;
    fogforest[i][j] = '#';
    int dx[4] = {0, -1, 0, 1}, dy[4] = {1, 0, -1, 0};
    for (int k = 0; k < 4; k++)
    {
        int x = i + dx[k], y = j + dy[k];
        if (x >= 0 && y >= 0 && x < h && y < w && fogforest[x][y] == '.')
            res += dfs(x, y);
    }
    return res;
}

int main()
{
    while (cin >> w >> h, w || h)
    {
        int startx, starty;
        for (int i = 0; i < h; i++)
            for (int j = 0; j < w; j++)
            {
                cin >> fogforest[i][j];
                if (fogforest[i][j] == '@') { startx = i; starty = j; }
            }
        cout << dfs(startx, starty) << endl;
    }
}
```

### 思路要点

- **题目本质**：经典的 Flood Fill（种子填充/洪水灌溉）问题——给定二维网格中的起点，求四方向连通的同类区域大小。这类问题可以用 DFS 或用 BFS 解决，本题使用 DFS。本质是图的连通分量大小计算，每个可达的 `.` 格子都是连通分量中的一员。

- **DFS Flood Fill 步骤**：
  1. 从起点 `@` 开始，将其视为 `.`。
  2. 访问当前格，将值改为 `#`（表示已访问，也相当于"净化"完毕）。计数器 +1。
  3. 检查四个方向的相邻格：如果在边界内且为 `.`，递归访问。
  4. 所有可达的 `.` 都被标记为 `#` 后，递归终止，返回总计数。

- **为什么不回溯**：与 LinK38（命运之阵）不同，这里不需要恢复 `fogforest[i][j]` 的原始值。因为 visit 后直接标记为墙（`#`），防止重复计数即可。这是 Flood Fill 和"求路径数"类 DFS 的本质区别——前者只需知道"遍历了多少格"，后者需要知道"有多少种不同的走法"。

- **DFS vs BFS**：
  - DFS 用递归实现，代码简短，但递归深度可能达到 W×H ≤ 400（20×20），在栈限制内完全安全。
  - BFS 用队列实现，代码稍长但不会有栈溢出风险（LinK51 就是 BFS 版本）。
  - 本题数据范围小（W,H ≤ 20），两种方法均可。

- **多组输入处理**：`while (cin >> w >> h, w || h)` —— 读入两个整数，逗号运算符返回 `w || h`。当 w 和 h 都为 0 时 `w || h` 为 false，循环终止。这是一种常见的"多组数据 + 哨兵 0 0 终止"的模式。

- **找到起点**：双重循环遍历每个字符，找到 `@` 即记录 `(startx, starty)`。题目保证每个数据集合中 `@` 唯一出现一次。

- **复杂度分析**：每个格子最多被访问一次（访问后立即标记为 `#`），时间复杂度 O(W×H)，空间复杂度 O(W×H)（存网格 + 递归栈）。

- **易错点**：
  - 输入顺序是 `w h`（列数在前，行数在后），后面的双层循环是 `for i < h` 再 `for j < w`。不要把 w 和 h 搞反。
  - `fogforest` 大小 27×27 是为了容纳 W,H ≤ 20 加上哨兵边界。
  - 初始时起点 `@` 也要计入答案（"记数时包括初始位置的迷雾"），所以 DFS 入口就是起点。

## LinK43 求二进制中1的个数

### 题目描述

输入 32 位整数（可为负，采用补码表示），用 lowbit 求其二进制中 1 的个数。

### 样例

输入 `9` → `2`；输入 `-2` → `31`。

### 我的代码

```cpp
int lowbit(int n) { return n & -n; }

int NumberOf1(int n)
{
    int res = 0;
    while (n) { n -= lowbit(n); res++; }
    return res;
}
```

### 思路要点

- **题目本质**：统计一个 32 位整数的二进制表示中 1 的个数（也称为"popcount"或"汉明重量"）。关键技巧是使用 `lowbit` 操作——`n & -n` 可以提取出 n 的二进制最低位的 1 及其后面的所有 0。

- **补码与负数的处理**：题目特别提到"负数在计算机中用其绝对值的补码来表示"。在 C++ 中，`int` 类型本身就是补码表示，所以 `lowbit(-2)` 和 `lowbit(2)` 一样都能正常工作。例如 -2 的补码是 `11111111 11111111 11111111 11111110`，`lowbit(-2) = 2`（最低位 1 代表的数值）。

- **lowbit 原理**：
  - `n & -n` 在补码体系下的效果：假设 n 的二进制最低位 1 出现在第 k 位。则 `-n = ~n + 1`。
  - 取反 `~n` 后第 k 位变成 0，后面的所有 0 变成 1。加 1 后这些 1 进位变成 0，第 k 位的 0 变成 1。所以 `-n` 和 `n` 只在第 k 位及更高位相同，`n & -n` 提取出第 k 位的 1。
  - 举例：n = 12（`1100`），`-n = ...11110100`（补码），`n & -n = 0100 = 4`。这正是最低位 1 的权值。

- **while(n) 循环**：`n -= lowbit(n)` 每次消去最低位的 1，计数器 `res++`。当 n=0 时循环结束。对于 32 位整数，最坏循环 32 次（n = -1 = 全 1）。

- **与其他方法的对比**：
  - `__builtin_popcount(n)`（GCC 内置）：编译为 CPU 的 POPCNT 指令，O(1)。
  - 移位法：`while (n) { res += n & 1; n >>= 1; }`，同样 O(位数)。
  - lowbit 法：对于稀疏的 1（如 n 只有少数几个 1），`while (n)` 循环次数 = 1 的个数，比移位法（固定 32 次）更优。

- **复杂度分析**：O(k)，k 为二进制中 1 的个数，k ≤ 32。空间 O(1)。

- **易错点**：
  - `n & (-n)` 和 `n & (~n + 1)` 是等价的，使用 `n & -n` 最简洁。
  - 注意传入的 n 是 `int`（有符号），`lowbit` 返回 `int`。对于 n = -2147483648（INT_MIN），`-n` 会溢出（因为 INT_MAX = 2147483647 < 2147483648），但 `n & -n` 在无符号语义下仍然正确（C++20 前有符号溢出是 UB，但在补码机器上行为一致）。

## LinK44 二进制中1的最低位位置

### 题目描述

给定 16 位数，求其二进制最低位 1 的位置。用打表法 + lowbit。

### 样例

`9` → `0`（二进制 1001，最低位 1 在第 0 位）；`8` → `3`。

### 我的代码

```cpp
#include <iostream>
using namespace std;

#define N 17
int log[1 << N];

void BuildLogTable(int n) { for (int i = 0; i < n; i++) log[1 << i] = i; }

inline int lowbit(int n) { return n & -n; }

int main()
{
    BuildLogTable(N);
    int n; cin >> n;
    cout << log[lowbit(n)];
    return 0;
}
```

### 思路要点

- **题目本质**：给定一个 16 位的十进制数，找到它的二进制表示中最低位 1 的位置（从第 0 位开始计数）。核心思路是 **lowbit + 打表法**——`lowbit(n)` 提取出最低位 1 的权值（必然是 2 的幂），然后通过预处理的表查到该权值对应的是第几位。

- **打表法的精髓**：`log[1<<i] = i` 预计算了所有 2 的幂到其指数的映射。例如 `log[1<<0] = log[1] = 0`，`log[1<<3] = log[8] = 3`。这个表只需要初始化一次（`BuildLogTable`），之后每次查询 O(1) 时间。

- **完整流程**：
  1. 输入 n = 9（二进制 `1001`）。
  2. `lowbit(9) = 1`（二进制 `0001`，最低位 1 在第 0 位）。
  3. `log[1] = 0`，输出 0。
  4. 再如 n = 8（二进制 `1000`），`lowbit(8) = 8`，`log[8] = 3`，输出 3。

- **为什么 lowbit 返回的值一定是 2 的幂**：`n & -n` 只保留最低位 1 及其后面的 0，结果必然形如 `0000...00100...0`，即 2 的某次幂。所以可以用 `log[lowbit(n)]` 查表得到其指数。

- **打表法的适用范围**：当操作的结果范围有限且可枚举时（这里是 16 位，1<<17 = 131072），直接预计算所有可能答案存起来，后续查询 O(1)。这种以空间换时间的策略在竞赛中非常常见，另一个经典例子是 LinK47/48 中 `ones[]` 和 `log[]` 的实现。

- **inline 关键字的意义**：`inline int lowbit(int n)` 建议编译器将函数体直接展开到调用处，避免函数调用的开销。对于像 `lowbit` 这种只有一个表达式的函数，inline 是合适的。

- **复杂度分析**：打表 O($2^{17}$) 时间（约 13 万，一次性），O(1<<17) 空间。每次查询 O(1)。

- **易错点**：
  - 数组大小 `1<<N` 是 1<<17 = 131072，包含了所有 16 位数的 lowbit 结果的索引。N=17 是因为 $2^{16}$ = 65536，数组需要覆盖索引 0..65536，共 65537 个元素。
  - 位的位置从 0 开始计数（第 0 位是二进制最低位）。样例 9（1001）→ 0 验证了这一点。
  - lowbit 的结果可能为 0 吗？对于非零的 n 不会。但如果输入是 0，`lowbit(0) = 0`，此时 `log[0]` 是未定义的（全局数组默认为 0）。题目没有要求处理 n=0 的情况。

## LinK45 真假记忆碎片

### 题目描述

给定初始 9×9 数独矩阵（含 0 表示空位）和一份声称是解的 9×9 矩阵，判断该解是否合法（与初始矩阵的非零格一致，且满足数独规则）。

### 样例

合法解 → `Yes`；不合法 → `No`。

### 我的代码

```cpp
#include <iostream>
#include <cstring>
using namespace std;

const int N = 9, M = 3;
string memory[N] = {{"530070000"}, {"600195000"}, {"098000060"},
                    {"800060003"}, {"400803001"}, {"700020006"},
                    {"060000280"}, {"000419005"}, {"000080079"}};
int a[N][N], b[N][N];
bool st[N + 1];

bool check_input() { /* 检查每行长度=9且数字与初始矩阵一致 */ }
bool check_row()   { /* 每行1-9不重复 */ }
bool check_col()   { /* 每列1-9不重复 */ }
bool check_block() { /* 每个3x3块1-9不重复 */ }

int main()
{
    for (int i = 0; i < N; i++)
        for (int j = 0; j < N; j++)
            a[i][j] = memory[i][j] - '0';
    if (check_input() && check_row() && check_col() && check_block())
        cout << "Yes" << endl;
    else cout << "No" << endl;
    return 0;
}
```

### 思路要点

- **题目本质**：数独验证器（Sudoku Validator）——给定一个 9×9 的已填满的矩阵，判断它是否是给定初始矩阵的有效解。需要同时验证三件事：①填的数字与初始矩阵已知数字一致（合法性），②每行 1~9 不重复，③每列 1~9 不重复，④每个 3×3 九宫格 1~9 不重复。这是 LinK46-48（数独求解器）的前置基础。

- **验证四步流程**：

  1. **`check_input()`**：读入 9 行字符串，检查每行长度是否为 9，每个字符是否为 1~9，以及填入的数字是否与初始矩阵 A 的非零格一致（即原始给出的已知数字不能被改变）。`if (a[i][j] != 0 && a[i][j] != t)` ——初始矩阵该位置是 0 表示可自由填写，如果非零则必须严格匹配。

  2. **`check_row()`**：逐行检查，用 `st[10]`（索引 1~9）标记出现过的数字。如果某数字已出现过（`st[t]` 为 true）或数字不在 1~9 范围内，返回 false。

  3. **`check_col()`**：同理，逐列检查。注意行列索引交换：`b[j][i]`（j 是列，i 是行）。

  4. **`check_block()`**：检查 9 个 3×3 块。`for (x = 0; x < 9; x += 3)` 和 `for (y = 0; y < 9; y += 3)` 枚举每个块的左上角，内部双重 `dx`、`dy` 循环（0~2）遍历块内 9 个格子。

- **为什么三个 check 都用了 `memset(st, false, sizeof(st))`**：每行/每列/每块检查前要重置标记数组，否则上一行/列/块的标记会污染当前检查。

- **布尔数组判重 vs 位运算**：用 `bool st[10]` 是最直观的判重方式，空间 O(1) 时间 O(1)。LinK47/48 中使用位运算（9 位 bitmask）是更高级的替代方案，可以同时表示"哪些数字可用"而不只是"哪些数字已出现"。

- **输入校验（`check_input` 的防御性检查）**：
  - `line.size() != N`：防止某行字符串长度不对（如样例 3 中的 `42689993791` 长度为 11 而非 9）。
  - `t < 0 || t > N`：防止非法字符（如空格、字母）被转换为非法数字。
  - `a[i][j] != 0 && a[i][j] != t`：核心合法性检查——初始矩阵的已知数字不得被推翻。

- **复杂度分析**：读入 + 四个 check 各自遍历 81 个格子，总 O(81×4) ≈ O(1)。空间 O(1)（固定的标记数组）。

- **易错点**：
  - `st` 数组索引是数字 1~9（不是 0~8），所以大小至少 10（`st[N+1]` = `st[10]`）。如果用 `st[9]` 则 `st[9]` 越界。
  - `check_block` 中三层嵌套循环的索引容易搞混：`b[x+dx][y+dy]` 而不是 `b[dx][dy]`。
  - 初始矩阵 A 存储在 `memory[]` 字符串数组中，需要转换为 `a[i][j] = memory[i][j] - '0'`。
  - `memset` 需要 `#include <cstring>`。
  - 四个 check 全部返回 true 才输出 `Yes`，任何一个不通过都是 `No`。这是逻辑与的短路效果——如果 `check_input()` 失败就不会继续读入/检查。

<a id="link46-寻找林克的回忆1"></a>

## LinK46 寻找林克的回忆(1)

### 题目描述

解 9×9 标准数独（数独试炼 I）。输入 9 行字符串，0 表示空位。输出任意一组解。

### 样例

输入 `103000509...` → 输出完整的 9×9 数独解。

### 我的代码

```cpp
#include <iostream>
#include <cstring>
#include <algorithm>
using namespace std;

const int N = 9;
int g[N][N];
bool st_row[N][N + 1], st_col[N][N + 1], st_block[3][3][N + 1];

bool dfs(int x, int y)
{
    if (y == 9) x++, y = 0;
    if (x == 9) { /* 输出解 */ return true; }
    if (g[x][y] != 0) return dfs(x, y + 1);
    for (int t = 1; t <= 9; t++)
        if (!st_row[x][t] && !st_col[y][t] && !st_block[x / 3][y / 3][t])
        {
            st_row[x][t] = st_col[y][t] = st_block[x / 3][y / 3][t] = true;
            g[x][y] = t;
            if (dfs(x, y + 1)) return true;
            g[x][y] = 0;
            st_row[x][t] = st_col[y][t] = st_block[x / 3][y / 3][t] = false;
        }
    return false;
}

int main()
{
    memset(st_row, 0, sizeof(st_row));
    memset(st_col, 0, sizeof(st_col));
    memset(st_block, 0, sizeof(st_block));
    for (int i = 0; i < 9; i++)
        for (int j = 0; j < 9; j++)
        {
            char ch; cin >> ch;
            int t = ch - '0';
            g[i][j] = t;
            if (t != 0)
                st_row[i][t] = st_col[j][t] = st_block[i / 3][j / 3][t] = true;
        }
    dfs(0, 0);
    return 0;
}
```

### 思路要点

- **题目本质**：标准 9×9 数独求解器——给定部分填充的棋盘（0 表示空），使用 DFS 回溯求出任意一组可行解。这是最经典的约束满足问题（CSP）应用之一。

- **布尔数组约束检查（O(1) 查找）**：
  - `st_row[x][t]`：第 x 行中数字 t 是否已使用（t ∈ [1,9]）。
  - `st_col[y][t]`：第 y 列中数字 t 是否已使用。
  - `st_block[x/3][y/3][t]`：第 (x/3, y/3) 个 3×3 块中数字 t 是否已使用。
  - 三个数组联合检查：`if (!st_row[x][t] && !st_col[y][t] && !st_block[x/3][y/3][t])` ——行、列、块都没有这个数字才能放置。

- **DFS 流程**：
  - 按坐标 `(x, y)` 递进：先 y+1（列+1），列满后 x+1, y=0（换行）。
  - 遇到已填数字的格（`g[x][y] != 0`）则跳过，直接递归下一个位置。
  - 到达 `x == 9` 时说明所有格已填满，输出解并返回 true。
  - 遇到空格时，尝试 1~9 的数字，满足约束则放置 + 递归。如果递归返回 true（找到解），则沿路返回 true终止搜索（只需求一解）。

- **初始化**：读入时如果格子有值（非 0），立即将其标记到三个约束数组中。这样已填的数字不会被后续 DFS 覆盖，也避免了初始已填数字冲突导致的无效搜索。

- **只返回 true 的原因**：题目说"如果解决方案不是唯一的，程序可以打印其中任何一种"。所以找到一个解就可以立即停止，返回 true 逐层退出。这与 LinK48（靶形数独，需要找最优解）不同——后者必须遍历全部解。

- **复杂度分析**：最坏时间复杂度是指数级（精确覆盖问题，NP 完全）。但标准数独的搜索空间在有效的约束传播下远小于 $9^{81}$（无约束的情况）。通常实际运行在毫秒级。空间复杂度 O($9^2$) 固定。

- **与 LinK47 的对比**：

| 方面 | LinK46（数独 I） | LinK47（数独 II） |
|------|-----------------|-------------------|
| 输入格式 | 9 行 × 9 字符 | 1 行 81 字符 |
| 约束存储 | 三维 bool 数组 | 位运算（bitmask） |
| 填格顺序 | 逐行逐列顺序 | **优先填候选最少格**（MRV 启发式） |
| 多组输入 | 否 | 是（直到 "end"） |

- **易错点**：
  - 三个约束数组的维度：`st_block[3][3][10]`，第三个维度是 10（数字 1~9）。需要 `[N+1]` 即 `[10]`。
  - 递归时坐标转换：`if (y == 9) x++, y = 0` 而不是 `x++, y = 0` 后继续。
  - `if (g[x][y] != 0) return dfs(x, y+1)` ——跳过已填格时不要忘记 return，否则会继续执行后面的 try 循环。
  - 回溯恢复：放置失败时需要把三个数组和 `g[x][y]` 全部恢复。代码中恢复顺序是放置的反向。

<a id="link47-寻找林克的回忆2"></a>

## LinK47 寻找林克的回忆(2)

### 题目描述

数独试炼 II：多组输入，每组一行 81 个字符（`.` 代表空），含多组数据直到 "end"。用**位运算 + 优先填最少候选格**优化。

### 样例

输入含 `.` 的一行 81 字符，输出完整数独串。

### 我的代码

```cpp
#include <iostream>
#include <algorithm>
using namespace std;

const int N = 9;
int ones[1 << N], log[1 << N];
int row[N], col[N], block[3][3];
string str;

inline int lowbit(int x) { return x & -x; }

void init()
{
    for (int i = 0; i < N; i++) row[i] = col[i] = (1 << N) - 1;
    for (int i = 0; i < 3; i++)
        for (int j = 0; j < 3; j++) block[i][j] = (1 << N) - 1;
}

inline int get(int x, int y) { return row[x] & col[y] & block[x / 3][y / 3]; }

bool dfs(int cnt)
{
    if (!cnt) return true;
    int minv = 10, x, y;
    for (int i = 0; i < N; i++)
        for (int j = 0; j < N; j++)
            if (str[i * 9 + j] == '.')
            {
                int t = ones[get(i, j)];
                if (t < minv) { minv = t; x = i; y = j; }
            }
    for (int i = get(x, y); i; i -= lowbit(i))
    {
        int t = log[lowbit(i)];
        row[x] -= 1 << t; col[y] -= 1 << t; block[x / 3][y / 3] -= 1 << t;
        str[x * 9 + y] = '1' + t;
        if (dfs(cnt - 1)) return true;
        row[x] += 1 << t; col[y] += 1 << t; block[x / 3][y / 3] += 1 << t;
        str[x * 9 + y] = '.';
    }
    return false;
}

int main()
{
    for (int i = 0; i < N; i++) log[1 << i] = i;
    for (int i = 0; i < 1 << N; i++)
    { int s = 0; for (int j = i; j; j -= lowbit(j)) s++; ones[i] = s; }
    while (cin >> str, str[0] != 'e')
    {
        init();
        int cnt = 0;
        for (int i = 0, k = 0; i < N; i++)
            for (int j = 0; j < N; j++, k++)
                if (str[k] != '.')
                { int t = str[k] - '1'; row[i] -= 1 << t; col[j] -= 1 << t; block[i / 3][j / 3] -= 1 << t; }
                else cnt++;
        dfs(cnt); cout << str << endl;
    }
    return 0;
}
```

### 思路要点

- **题目本质**：同样是数独求解器，但有几处重要升级：① 支持多组输入（直到 "end"），② 使用**位运算**替代三维 bool 数组，③ 使用**最少剩余值（MRV）启发式**优先填候选最少的格，大幅加速。这也是《算法竞赛进阶指南》中经典的数独位运算模板。

- **位运算状态表示**：
  - `row[i]`、`col[j]`、`block[3][3]` 各是一个 9 位的 bitmask（实际值 0~511），第 t 位（0 ≤ t ≤ 8）为 1 表示数字 t+1 可用，为 0 表示已被占用。
  - 初始化：`(1 << N) - 1 = 511 = 111111111₂`，表示所有 9 个数字都可用。
  - 放置数字 t（0-based）：`row[x] -= 1 << t`，即把第 t 位置 0。
  - 撤销：`row[x] += 1 << t`，即把第 t 位置回 1。
  - 候选集合：`get(x, y) = row[x] & col[y] & block[x/3][y/3]` ——三者按位与，得到同时被三个约束允许的数字集合。
  - 遍历候选集合：`for (int i = get(x,y); i; i -= lowbit(i))` ——每次取出最低位的 1（通过 `lowbit`），直到集合为空。这是遍历 bitmask 的所有 1 位的经典写法。

- **MRV 启发式（最少剩余值优先）**：
  - 原理：在所有空格中，优先选择"可选数字最少的格子"来填充。这样做缩小了搜索树的宽度，是最基本的 CSP 搜索优化。
  - 实现：`ones[get(i,j)]` 预计算了每个 mask 中 1 的个数（即可选的数字个数）。遍历所有空格，找到 `ones[get(i,j)]` 最小的格子 `(x, y)`。
  - 效果：在标准 9×9 数独中，MRV 启发式可以将搜索节点数减少数个数量级。

- **ones[] 和 log[] 的预计算**：
  - `log[1<<i] = i`：O(1) 确定某个 1-bit 代表数字几（`log[lowbit(i)]`）。例如 `lowbit(i) = 8 = 1000₂`，`log[8] = 3`，代表第 3 位（数字 4）。
  - `ones[i]`：mask i 中 1 的个数。用 `for (j = i; j; j -= lowbit(j)) s++` 逐位计数。
  - 这些表在程序启动时一次性计算好（总大小 $2^9$ = 512 × 2 = 1024 个元素），之后所有查询 O(1)。

- **与 LinK46 的关键区别——非顺序填格**：LinK46 按 (0,0)→(0,1)→...→(8,8) 顺序填，LinK47 则每步动态选择最优空格。这使得 DFS 递归时 `cnt`（剩余空格数）作为唯一状态，不再需要传递坐标。

- **多组输入格式**：输入是 81 个字符的长字符串（或含 `.` 的字符串），以 "end" 结尾。对每行：初始化→标记已有数字→DFS→输出结果。

- **复杂度分析**：理论上界 O($9^n$) 指数级，但 MRV + 约束传播的实际搜索量极小。标准数独一般 < 1000 次递归即可完成。

- **易错点**：
  - 位运算用的是 0-based 数字（t ∈ [0,8]），与用户看到的 1-based（1~9）不同。放置时 `'1' + t` 转换，读取时 `str[k] - '1'` 转换。
  - `block` 数组索引是 `i/3` 和 `j/3`（整除得到 0/1/2），与 bool 数组版相同。
  - 回溯时恢复顺序是放置的反向：放置时 `row -= (1<<t)`，恢复时 `row += (1<<t)`。
  - `lowbit` 返回的是某一位的值（如 8），不是位号（如 3）。必须通过 `log[lowbit(i)]` 转换为位号。

<a id="link48-寻找林克的回忆3"></a>

## LinK48 寻找林克的回忆(3)

### 题目描述

**靶形数独**（数独试炼 III）：每个格子有靶形分值（中心 10 分，向外递减至 6 分）。在解数独的同时求**最高总分**（填入数字 × 格分之和）。无解输出 -1。

### 样例

输入 9×9 空格分隔的数字 → 输出最高分 2829。

### 我的代码

```cpp
#include <iostream>
#include <algorithm>
using namespace std;

const int N = 9, M = 1 << N;
int ones[M], log[M];
int row[N], col[N], block[3][3], g[N][N];
int ans = -1;

inline int lowbit(int x) { return x & -x; }
inline int get(int x, int y) { return row[x] & col[y] & block[x / 3][y / 3]; }
inline int get_score(int x, int y, int t)
{ return (min(min(x, 8 - x), min(y, 8 - y)) + 6) * t; }

void init()
{
    for (int i = 0; i < N; i++) log[1 << i] = i;
    for (int i = 0; i < M; i++)
        for (int j = i; j; j -= lowbit(j)) ones[i]++;
    for (int i = 0; i < N; i++) row[i] = col[i] = block[i / 3][i % 3] = M - 1;
}

void draw(int x, int y, int t)
{
    int s = 1;
    if (t > 0) g[x][y] = t;
    else { s = -1; t = -t; g[x][y] = 0; }
    t--;
    row[x] -= (1 << t) * s; col[y] -= (1 << t) * s;
    block[x / 3][y / 3] -= (1 << t) * s;
}

void dfs(int cnt, int score)
{
    if (!cnt) { ans = max(ans, score); return; }
    int minv = 10, x, y;
    for (int i = 0; i < N; i++)
        for (int j = 0; j < N; j++)
            if (!g[i][j])
            {
                int t = ones[get(i, j)];
                if (t < minv) { minv = t; x = i; y = j; }
            }
    for (int i = get(x, y); i; i -= lowbit(i))
    {
        int t = log[lowbit(i)] + 1;
        draw(x, y, t);
        dfs(cnt - 1, score + get_score(x, y, t));
        draw(x, y, -t);
    }
}

int main()
{
    init();
    int cnt = 0, score = 0;
    for (int i = 0; i < N; i++)
        for (int j = 0; j < N; j++)
        {
            int t; cin >> t;
            if (t) { draw(i, j, t); score += get_score(i, j, t); }
            else cnt++;
        }
    dfs(cnt, score);
    cout << ans << endl;
    return 0;
}
```

### 思路要点

- **题目本质**：靶形数独——在标准数独规则的基础上，每个格子有一个靶形分值（离中心越近越高，6~10 分）。目标是找到总分数最高的解（每个格子分数 × 填入数字，求和），无解输出 -1。这是 LinK47 的升级版——需要求最优解而非任意解。

- **与 LinK47 的两个核心区别**：

  1. **必须搜索全部解**：LinK47 在 `dfs(cnt)` 找到第一个解后返回 true 就停止了。LinK48 永远返回 void，用 `ans = max(ans, score)` 记录最优分数。即使找到一个可行解也不能停止，必须继续搜索其他解（因为可能有更高分）。

  2. **每个格子有权值**：`get_score(x, y, t) = (min(min(x, 8-x), min(y, 8-y)) + 6) * t`。`min(x, 8-x)` 结果是 0（最外圈）到 4（最内圈）。加上 6 后得到 6（最外圈）到 10（最内圈）。乘以填入的数字 t 得到该格的贡献分。

- **draw 函数的巧妙设计**：
  - `draw(x, y, t)`：当 t > 0 时放置数字 t（`s=1`）；当 t < 0 时撤销放置（`s=-1`，t 取绝对值变回正数）。
  - 通过 `s` 的正负来控制位运算 mask 的加减（放置时 `row[x] -= 1<<t * s` 即 `row[x] -= 1<<t`；撤销时 `row[x] -= 1<<t * (-1)` 即 `row[x] += 1<<t`）。
  - 这种设计将放置和撤销统一为一个函数，减少了代码重复和出错概率。

- **分数计算的双重角色**：
  - `score` 在 DFS 递归中作为一个累积参数传递，每放置一个数字就加上该格的贡献。
  - 初始时已有数字的分数在 main 中预先累加：`score += get_score(i, j, t)`。
  - 当 `cnt == 0`（所有空格填满），当前累积分 `score` 就是完整方案的总分，用 `ans = max(ans, score)` 更新最优。

- **复杂度分析**：与 LinK47 相同的最坏指数复杂度，但必须遍历全部解。好在标准数独的解空间很小（通常只有 1~2 组解），MRV 启发式极大缩减搜索树，实际运行极快。

- **易错点**：
  - `ans` 初始化为 -1（而不是 0），因为无解时需要输出 -1。如果初始化为 0，无解时会错误输出 0（而 0 是一个不可能的总分吗？不，实际上不可能达到 0 分因为每格至少 6×1=6 分×81 格=486 分，所以 `ans==-1` 用于区分"还没找到"和"找到了 0 分"是安全的）。
  - `draw` 中 `t` 先减 1（转为 0-based）再操作 mask，和 LinK47 一样。
  - 不要忘记 `init()` 函数中的 `block[i/3][i%3]` 初始化（代码中用 `block[i/3][i%3]` 的循环方式替代了 LinK47 中的双重循环，等效）。

## LinK51 净化迷雾森林(广搜)

### 题目描述

与 LinK39 相同，但用 **BFS 替代 DFS**。

### 我的代码

```cpp
#include <iostream>
#include <queue>
using namespace std;

typedef pair<int, int> PII;
const int N = 25;
int n, m;
char g[N][N];

int bfs(int sx, int sy)
{
    queue<PII> q;
    q.push({sx, sy}); g[sx][sy] = '#';
    int res = 0;
    int dx[] = {-1, 0, 1, 0}, dy[] = {0, 1, 0, -1};
    while (q.size())
    {
        auto t = q.front(); q.pop(); res++;
        for (int i = 0; i < 4; i++)
        {
            int x = t.first + dx[i], y = t.second + dy[i];
            if (x < 0 || x >= n || y < 0 || y >= m || g[x][y] != '.') continue;
            g[x][y] = '#'; q.push({x, y});
        }
    }
    return res;
}

int main()
{
    while (cin >> m >> n, n || m)
    {
        for (int i = 0; i < n; i++) cin >> g[i];
        int x, y;
        for (int i = 0; i < n; i++)
            for (int j = 0; j < m; j++)
                if (g[i][j] == '@') { x = i; y = j; }
        cout << bfs(x, y) << endl;
    }
}
```

### 思路要点

- **题目本质**：与 LinK39（DFS 版）完全相同的题目，只是要求使用 BFS 实现 Flood Fill。DFS 用递归（栈），BFS 用队列——两种遍历方式的对比练习。

- **BFS vs DFS 在 Flood Fill 中的对比**：

| 方面 | DFS（LinK39） | BFS（本题） |
|------|-------------|-----------|
| 数据结构 | 递归调用栈 | `queue` 队列 |
| 遍历顺序 | 深度优先（走到死路再回头） | 逐层扩展（一圈一圈扩散） |
| 代码量 | 更短（递归天然简洁） | 稍长（需要 queue 操作） |
| 栈/队列溢出风险 | W×H ≤ 400 时无风险 | 队列大小 ≤ W×H，安全 |
| 空间 | O(W×H) 递归栈 | O(W×H) 队列 |

- **BFS 标准模板**：
  1. 起点入队，标记为已访问（`g[sx][sy] = '#'`）。
  2. `while (q.size())`：取出队首，计数器+1（代表净化了一个区域），四方向扩展。
  3. 合法的新格子（未出界且为 `.`）入队并标记为 `#`。
  4. 队列为空时所有可达区域已统计完毕。

- **为什么入队前就标记为 `#`**：防止同一格子被多次入队。如果在出队后才标记，同一格子可能被多个相邻格同时发现并重复入队。这是一个常见的 BFS 优化/正确性保证。

- **PII（pair<int,int>）类型**：`typedef pair<int, int> PII` 简化了坐标的表示。`q.push({x, y})` 入队，`auto t = q.front()` 获取队首，`t.first`/`t.second` 访问坐标。

- **复杂度分析**：每个格子入队出队一次，O(W×H) 时间，O(W×H) 空间（队列最大容量为所有格子数）。与 DFS 版相同。

- **易错点**：
  - 输入循环条件 `cin >> m >> n, n || m` 中 m 和 n 的顺序：先读 m（列）后读 n（行），与 LinK39 相同。
  - 在 while 循环中每读一组新数据就要重新扫描起点 `@` 的位置。
  - `continue` 的使用：四个方向中有出界或不是 `.` 的跳过。

<a id="link52-波克布林的巡逻范围"></a>

## LinK52 波克布林的巡逻范围

### 题目描述

m×n 网格，从 (0,0) 出发走四方向，不能进入行坐标+列坐标数位之和 > k 的格子。求可达格子数。

### 样例

k=18, m=40, n=40 → 1484。

### 我的代码

```cpp
#include <iostream>
#include <queue>
#include <vector>
using namespace std;

int get_int_sum(int x) { int s = 0; while (x) s += x % 10, x /= 10; return s; }
int get_pair_sum(pair<int, int> p) { return get_int_sum(p.first) + get_int_sum(p.second); }

int bfs(int threshold, int rows, int cols)
{
    if (!rows || !cols) return 0;
    vector<vector<bool>> st(rows, vector<bool>(cols, false));
    queue<pair<int, int>> q;
    int dx[] = {-1, 0, 1, 0}, dy[] = {0, 1, 0, -1};
    int res = 0; q.push({0, 0});
    while (q.size())
    {
        auto t = q.front(); q.pop();
        if (st[t.first][t.second] || get_pair_sum(t) > threshold) continue;
        res++; st[t.first][t.second] = true;
        for (int i = 0; i < 4; i++)
        {
            int x = t.first + dx[i], y = t.second + dy[i];
            if (x >= 0 && x < rows && y >= 0 && y < cols) q.push({x, y});
        }
    }
    return res;
}

int main()
{
    int k, m, n; cin >> k >> m >> n;
    cout << bfs(k, m, n);
}
```

### 思路要点

- **题目本质**：给定 m×n 网格和一个阈值 k，从 (0,0) 开始做 BFS，只有行列坐标的十进制数位之和 ≤ k 的格子才能访问。求可达格子总数。这道题源自《剑指 Offer》"机器人的运动范围"问题。

- **数位和约束**：`get_int_sum(x)` 对整数 x 逐位求和（如 35→3+5=8）。两个坐标的数位和加起来就是 `get_pair_sum({i, j}) = get_int_sum(i) + get_int_sum(j)`。只有这个和 ≤ k 才能进入。

- **BFS 中的约束检查位置**：代码在**出队后**检查约束（而不是入队前）。这意味着即使数位和超标的格子也会被入队，但出队时被 `continue` 跳过不计入 res。这种写法简单但会多加入一些队列元素。更优的写法是入队前就检查约束。

- **二维 vector 的 bool 标记**：`vector<vector<bool>> st(rows, vector<bool>(cols, false))` 动态分配 m×n 的布尔标记数组。与固定大小数组 `bool st[N][N]` 相比，vector 可以根据实际的 m、n 精确分配空间。使用 `st[行][列]` 记录是否已访问。

- **BFS 遍历逻辑**：
  1. (0,0) 入队。
  2. 出队，如果 `st[x][y]` 为 true 或数位和超标则 `continue`。
  3. `res++` 并标记已访问。
  4. 四方向扩展，新坐标在矩阵内则入队。

- **边界条件**：`if (!rows || !cols) return 0` ——如果矩阵为 0×N 或 N×0，直接返回 0。防御性编程。

- **复杂度分析**：最坏访问所有 m×n ≤ 2500 个格子（m, n ≤ 50）。每个格子 O(1) 处理，总 O(m×n)。空间 O(m×n)（标记数组 + 队列）。

- **易错点**：
  - 数位和计算中 `x % 10` 取最低位，`x /= 10` 去掉最低位，循环直到 x=0。
  - 坐标从 0 开始（`(0,0)` 是起点），所以 (35,37) 的数位和 = (3+5) + (3+7) = 18。
  - BFS 不保证按距离排序出队（因为每条边权重相同，直接用普通 queue 即可，不需要优先队列）。

<a id="link53-加农的入侵"></a>

## LinK53 加农的入侵

### 题目描述

在 X×Y 网格上，加农从 (Mx, My) 开始向 **8 个方向**（含对角线）扩散污染。`.` 可污染，`*` 是障碍。求污染整个区域所需天数（BFS 最远距离）。

### 样例

4×3 地图 → 4 天；10×10 地图 → 6 天。

### 我的代码

```cpp
#include <iostream>
#include <queue>
#include <cstring>
using namespace std;

typedef pair<int, int> PII;
const int N = 110;
int n, m;
PII start;
char g[N][N];
int dist[N][N];
const int dx[8] = {1, -1, 0, 0, 1, -1, 1, -1};
const int dy[8] = {0, 0, 1, -1, 1, -1, -1, 1};

int bfs()
{
    memset(dist, -1, sizeof(dist));
    queue<PII> q; q.push(start);
    dist[start.first][start.second] = 0;
    int res = 0;
    while (q.size())
    {
        auto t = q.front(); q.pop();
        for (int i = 0; i < 8; i++)
        {
            int x = t.first + dx[i], y = t.second + dy[i];
            if (x < 1 || x > n || y < 1 || y > m) continue;
            if (g[x][y] == '*' || dist[x][y] != -1) continue;
            dist[x][y] = dist[t.first][t.second] + 1;
            res = max(res, dist[x][y]);
            q.push(make_pair(x, y));
        }
    }
    return res;
}

int main()
{
    cin >> m >> n >> start.second >> start.first;
    start.first = n + 1 - start.first; // 坐标系转换：左下角(1,1) → 数组下标
    for (int i = 1; i <= n; i++) cin >> g[i] + 1;
    cout << bfs() << endl;
    return 0;
}
```

### 思路要点

- **题目本质**：在 Y×X 网格中，从 (Mx, My) 开始向 8 个方向做 BFS 扩散（污染），`.` 可扩散，`*` 是障碍物。求污染所有可达空地所需的天数——等于 BFS 从起点到最远可达格的最短距离（步数）。

- **8 方向 BFS**：与之前 4 方向问题不同的关键升级。`dx[8] = {1, -1, 0, 0, 1, -1, 1, -1}` 和 `dy[8] = {0, 0, 1, -1, 1, -1, -1, 1}` 定义了上、下、左、右、四个对角线共 8 个方向。因为加农可以向对角线方向污染（散播无死角），这是物理意义上的自然扩散。

- **距离数组记录步数**：`dist[x][y]` 记录起点到该格的最短步数。初始化全 -1（未访问），起点 = 0。每访问一个新邻格：`dist[neighbor] = dist[current] + 1`。同时更新 `res = max(res, dist[neighbor])`。BFS 结束后 `res` 就是最远格子的步数。

- **坐标系转换（易错点）**：
  - 题目坐标原点在**左下角**：(Mx, My) 中 Mx 是离左边界的列数，My 是离下边界的行数。
  - 代码数组原点在**左上角**：`g[1]` 对应第一行（物理上是最上面一行）。
  - 转换公式：`start.first = n + 1 - start.first`（Y 是总行数 n，My=start.first 是 y 坐标，倒过来）。
  - 举例：n=3 行，My=1（题目说左下角），转换后 `start.first = 3+1-1 = 3`，数组中的第 3 行（最底下一行），正确。

- **cout << bfs() 的含义**：BFS 返回的是最大步数（从 0 开始）。样例中最大步数为 4，输出 4。起点在第 0 天已污染，步数=天数（因为每走一步正好过一天）。

- **复杂度分析**：最坏访问所有 Y×X ≤ 10000 个格子，每个格 8 次方向检查。O(Y×X)，完全可以接受。

- **易错点**：
  - 输入顺序是 `X Y Mx My`（列数在前、行数在后，与之前几题不同！），代码中用 `cin >> m >> n >> start.second >> start.first`（m=列=X，n=行=Y）。
  - 坐标原点的转换公式 `n + 1 - y` 如果忘写，会导致起点完全错误，BFS 结果也就全错了。
  - 8 方向数组比 4 方向多一倍，注意不要写反 `dx` 和 `dy` 的对应关系。
  - `dist` 数组初始化为 -1 用 `memset(dist, -1, sizeof(dist))`。注意不能初始化为 0，因为 0 是起点的距离。

<a id="link57-dijkstra求最短路1"></a>

## LinK57 Dijkstra求最短路(1)

### 题目描述

给定 n 点 m 边的**有向图**，边权为正。求 1 号点到 n 号点的最短距离。不可达输出 -1。

### 样例

3 个点 3 条边：1→2(2), 2→3(1), 1→3(4) → 最短距离 3。

### 我的代码

```cpp
#include <iostream>
#include <cstring>
#include <algorithm>
using namespace std;

const int N = 510;
int n, m;
int g[N][N], dist[N];
bool st[N];

int dijkstra()
{
    memset(dist, 0x3f, sizeof(dist));
    dist[1] = 0;
    for (int i = 0; i < n - 1; i++)
    {
        int t = -1;
        for (int j = 1; j <= n; j++)
            if (!st[j] && (t == -1 || dist[t] > dist[j])) t = j;
        for (int j = 1; j <= n; j++)
            dist[j] = min(dist[j], dist[t] + g[t][j]);
        st[t] = true;
    }
    if (dist[n] == 0x3f3f3f3f) return -1;
    return dist[n];
}

int main()
{
    scanf("%d%d", &n, &m);
    memset(g, 0x3f, sizeof(g));
    while (m--)
    {
        int a, b, c; scanf("%d%d%d", &a, &b, &c);
        g[a][b] = min(g[a][b], c); // 处理重边
    }
    printf("%d\n", dijkstra());
    return 0;
}
```

### 思路要点

- **题目本质**：单源最短路径（SSSP）的标准问题——求从 1 号顶点到 n 号顶点的最短距离。所有边权为正，使用 Dijkstra 算法。这是图论中最基础的算法之一。

- **朴素 Dijkstra 算法（O($N^2$)）**：
  
  1. **初始化**：`dist[1] = 0`（源点到自身距离为 0），其余 `dist[i] = INF`（0x3f3f3f3f ≈ 1.1×$10^9$）。
  
  2. **主循环**（n-1 次）：每次从**未确定**的点中选 `dist` 最小的点 t，将其标记为已确定（`st[t] = true`）。然后用 t 的所有出边去**松弛**邻接点：`dist[j] = min(dist[j], dist[t] + g[t][j])`。
  
  3. **结果**：`dist[n]` 即为最短距离。若 `dist[n] == INF` 表示不可达，返回 -1。

- **为什么叫"松弛"**：`dist[j] = min(dist[j], dist[t] + g[t][j])` 意思是"从源点经过 t 再到 j 的距离，是否比当前从源点直接到 j 的距离更短"——如果更短就更新。这个操作叫 Relaxation。

- **邻接矩阵 vs 邻接表**：
  - 本题使用邻接矩阵 `g[N][N]`（二维数组），适合**稠密图**（m 接近 $n^2$）。N ≤ 500 时 $N^2$ = 250000 的循环完全可以接受。
  - 如果是稀疏图（m 较小），应使用邻接表 + 优先队列（堆优化 Dijkstra），复杂度 O(M log N)。

- **重边处理**：`g[a][b] = min(g[a][b], c)` ——如果存在多条 a→b 的边，只保留权值最小的那条。邻接表不需要这个处理（直接全部保留即可）。

- **0x3f 初始化技巧**：
  - `memset(g, 0x3f, sizeof(g))` 将每个字节设为 0x3f，int 的四个字节就是 `0x3f3f3f3f` ≈ 1.06×$10^9$。
  - 这个值有双重好处：① 足够大，表示无穷远（题目边权最大 $10^4$，路径和 ≤ 5×$10^8$，1e9 足够）；② `0x3f3f3f3f + 0x3f3f3f3f` 不会溢出 `int`（≈ 2.12×$10^9$ < 2.14×$10^9$ = INT_MAX），可以安全地进行加法。
  - 也可以用 `0x3f` 而非 `0x7f`：`0x7f7f7f7f` > INT_MAX 会溢出为负数。

- **为什么选择 t 后要 `st[t] = true`**：Dijkstra 的正确性依赖于"当前 dist 最小的点，其 dist 已经是最优的，不需要再更新"。标记为已确定后，后续循环跳过 `st[t]` 为 true 的点，避免重复处理。如果没有 `st[]` 标记，算法会反复更新已确定的点，虽然结果可能仍然正确但会浪费大量时间。

- **复杂度分析**：外层循环 n 次，内层找最小值 O(n) + 松弛 O(n)，总 O($N^2$)。空间 O($N^2$)（邻接矩阵）。

- **易错点**：
  - `dist` 和 `g` 都初始化为 `0x3f3f3f3f`。忘记初始化 `g` 会导致不可达边被当作权值为 0 的边。
  - 松弛前必须确保 `dist[t] != INF`，否则 `dist[t] + g[t][j]` 会溢出（虽然 0x3f3f3f3f+0x3f3f3f3f < INT_MAX 安全，但如果用了 0x7f...就溢出了）。
  - 重边处理极易忘记：没有 `min(g[a][b], c)` 的话，后面输入的更长的重边会覆盖更短的那条。
  - 输出时如果 `dist[n] == INF` 返回 -1。不要写成 `dist[n] == 0x3f3f3f3f` 后用魔法数字。

## LinK62 数字三角形

### 题目描述

数字三角形是动态规划的入门题。图1给出了一个数字三角形，从三角形的顶部到底部有很多条不同的路径。对于每条路径，把路径上面的数加起来可以得到一个和，你的任务就是找到最大的和。

注意：路径上的每一步只能从一个数走到正下方和右下方的位置。

### 输入

第一行是一个整数 N（1 < N ≤ 1000），给出三角形的行数。下面的 N 行给出数字三角形。数字的范围在 0 到 100 之间。

### 输出

输出最大的和。

### 样例

**输入：**
```
5
7
3 8
8 1 0
2 7 4 4
4 5 2 6 5
```

**输出：**
```
30
```

### 我的代码

```cpp
#include <iostream>
#include <cstring>
#include <algorithm>
using namespace std;

const int N = 1010;
int n;
int f[N][N];

int main()
{
    cin >> n;
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= i; j++)
            cin >> f[i][j];

    for (int i = n - 1; i; i--)
        for (int j = 1; j <= i; j++)
            f[i][j] += max(f[i + 1][j], f[i + 1][j + 1]);

    cout << f[1][1] << endl;
    return 0;
}
```

### 思路要点

- **题目本质**：经典的数字三角形（也叫做"数字金字塔"），是动态规划（DP）的入门题。给定一个三角形排列的数字，从顶部出发，每次只能走到正下方或右下方的数字，求路径上所有数字之和的最大值。这道题是 DP 思想的第一个实践——将大问题分解为小问题，从底向上递推最优值。

- **DP 状态定义**：`f[i][j]` 表示从 `(i, j)` 出发到达底部所能获得的最大和。注意这里的定义是"从当前点出发到终点"，而不是"从起点到当前点"——两种定义都可以，但递推方向不同。

- **递推关系（核心）**：
  - 从 `(i, j)` 出发，下一步只能走向 `(i+1, j)`（正下方）或 `(i+1, j+1)`（右下方）。
  - 因此：`f[i][j] = a[i][j] + max(f[i+1][j], f[i+1][j+1])`
  - 即当前位置的最优值 = 当前位置的值 + 下一步两个选择中的较大者。

- **自底向上的递推策略**：
  - 代码采用"自底向上"（bottom-up）的方式：从倒数第二行 `i = n-1` 开始向上计算，每一行的每个位置取下一行两个相邻位置的最大值。
  - 这种策略的好处：不需要额外的 DP 数组——直接在原数组 `f` 上原地累加修改，空间复杂度 O($N^2$) 但可以原地操作。
  - 最后 `f[1][1]` 就是从顶点出发到任意底部节点的最大路径和。

- **为什么不用自顶向下**：自顶向下（从第 1 行递推到第 n 行，最后遍历第 n 行取 max）也可以，但需要在最后一行扫描全部 N 个值取最大。自底向上则答案集中在 `f[1][1]`，更简洁。

- **递推过程示例**（以样例数据为例）：
  ```
         7               30            ← 最终答案在 f[1][1]
       3   8    →    23   21
     8   1   0   →  20   13   10
   2   7   4   4  →  7    12   10   10
  4   5   2   6   5（第 n 行：边界，f[n][j] = a[n][j]）
  ```
  从倒数第二行开始：`f[4][1] = 2 + max(4, 5) = 7`，`f[4][2] = 7 + max(5, 2) = 12`，以此类推。

- **为什么可以原地修改**：因为 `f[i][j]` 只依赖于下一行的 `f[i+1][j]` 和 `f[i+1][j+1]`，当第 i 行被更新后，第 i+1 行的原始值已经不再需要。这种技巧在简单 DP 中很常见（如 01 背包的一维优化同理）。

- **复杂度分析**：时间 O($N^2$)（每个格子被计算一次），空间 O($N^2$)（存储三角形）。N ≤ 1000 时 $N^2$ = $10^6$，完全可以在 1 秒内完成。

- **易错点**：
  - 三角形的列数并非固定的 N——第 i 行只有 i 列，循环时要注意 `j <= i` 而非 `j <= n`。
  - 逆序遍历 `for (int i = n - 1; i; i--)` 的含义是从 n-1 逐行递减到 1（`i` 为 0 时循环终止），不要写成 `i >= 0`（第 0 行不存在）。
  - `max(f[i+1][j], f[i+1][j+1])` 中不要搞混列号：左下方是 `f[i+1][j]`（同列），右下方是 `f[i+1][j+1]`（列+1）。

<a id="link63-林克的01背包"></a>

## LinK63 林克的01背包

### 题目描述

林克面临一个艰难的选择——他的背包容量有限，而面前摆放着价值不同的物品（各种套装）。有 N 件物品和一个容量是 V 的背包。每件物品只能使用一次。第 i 件物品的体积是 vi，价值是 wi。求解将哪些物品装入背包，可使这些物品的总体积不超过背包容量，且总价值最大。输出最大价值。

**数据范围**：0 < N, V ≤ 1000，0 < vi, wi ≤ 1000。

### 输入

第一行两个整数 N, V，用空格隔开，分别表示物品数量和背包容积。接下来有 N 行，每行两个整数 vi, wi，用空格隔开，分别表示第 i 件物品的体积和价值。

### 输出

输出一个整数，表示最大价值。

### 样例

**样例 1**

输入：
```
4 5
1 2
2 4
3 4
4 5
```

输出：
```
8
```

### 我的代码

```cpp
#include <iostream>
#include <algorithm>
using namespace std;

const int N = 1007;
int n, m;
int v[N], w[N];
int f[N][N];

int main()
{
    cin >> n >> m;
    for (int i = 1; i <= n; i++)
        cin >> v[i] >> w[i];

    for (int i = 1; i <= n; i++)
        for (int j = 0; j <= m; j++)
        {
            f[i][j] = f[i - 1][j];
            if (j >= v[i])
                f[i][j] = max(f[i][j], f[i - 1][j - v[i]] + w[i]);
        }

    cout << f[n][m] << endl;
    return 0;
}
```

### 思路要点

- **题目本质**：01 背包问题是动态规划的"第二个 Hello World"（第一个是数字三角形），也是所有背包问题的基础。N 件物品，每件要么选（1）要么不选（0），因此叫做"01 背包"。背包的约束是总容量 V，目标是总价值最大。

- **DP 状态定义**：`f[i][j]` 表示从前 i 件物品中选，总体积不超过 j 的情况下，所能获得的最大价值。这是一个二维 DP：
  - 第一维 i：考虑了前 i 件物品
  - 第二维 j：当前背包的剩余容量约束

- **递推关系推导（核心——第 i 件物品选还是不选）**：

  对于第 i 件物品，有两种可能：
  1. **不选第 i 件**：`f[i][j] = f[i-1][j]`（问题退化为前 i-1 件物品、容量 j）。
  2. **选第 i 件**（前提：`j >= v[i]`）：`f[i][j] = f[i-1][j - v[i]] + w[i]`（从前 i-1 件中选，容量留出 v[i] 给第 i 件，加上第 i 件的价值 w[i]）。

  取两种可能的最大值：`f[i][j] = max(f[i-1][j], f[i-1][j-v[i]] + w[i])`。

- **为什么第二层的 j 从 0 到 m 正序**：二维版本中 j 的遍历顺序无所谓，因为 `f[i][j]` 只依赖上一行 `f[i-1][...]`。正序或逆序都不影响结果。

- **最终答案的位置**：`f[n][m]` 表示考虑了所有 n 件物品、背包容量为 m 时的最大价值。

- **与一维优化的关系**：01 背包的经典优化是将二维数组压缩为一维：`for (j = m; j >= v[i]; j--) f[j] = max(f[j], f[j-v[i]] + w[i])`。逆序遍历 j 是为了保证 `f[j-v[i]]` 用的是上一轮的旧值（即 `f[i-1][j-v[i]]`）而不是本轮刚更新的 `f[i][j-v[i]]`。本题代码使用二维版本，更直观易理解；一维版本在 LinK64（完全背包）中会对比学习。

- **递推过程示例**（N=4, V=5）：
  ```
  物品: (v=1,w=2), (v=2,w=4), (v=3,w=4), (v=4,w=5)

  i=0: f[0][*] = 0（没有物品可选）
  i=1: 只能选第1件，f[1][j] = 2 (j>=1)，0 (j<1)
  i=2: 选或不选第2件...
        j=3: max(f[1][3], f[1][1]+4) = max(2, 2+4) = 6
  ...
  → f[4][5] = 8（选第2件和第3件：v=2+3=5, w=4+4=8 ✓）
  ```

- **复杂度分析**：时间 O(N×V)，空间 O(N×V)（可优化到 O(V)）。N, V ≤ 1000 时 N×V = $10^6$，完全可接受。

- **易错点**：
  - 二维版本中 `if (j >= v[i])` 判断不能忘——容量不够时只能不选。
  - `f[i][j] = f[i-1][j]` 这一行必须先执行（先继承不选的情况），再用选的情况与之比较取 max。
  - 物品编号从 1 开始（方便 `f[i-1]` 中 i=0 作为"无物品"的 base case）。
  - 与完全背包的区别：01 背包中 `f[i][j] = max(f[i-1][j], f[i-1][j-v[i]] + w[i])`（依赖上一行），完全背包是 `f[i][j] = max(f[i-1][j], f[i][j-v[i]] + w[i])`（依赖同一行），注意 `[i-1]` vs `[i]` 的细微差异。

<a id="link64-林克的完全背包"></a>

## LinK64 林克的完全背包

### 题目描述

有 N 种物品和一个容量是 V 的背包，每种物品都有无限件可用。第 i 种物品的体积是 vi，价值是 wi。求解将哪些物品装入背包，可使这些物品的总体积不超过背包容量，且总价值最大。输出最大价值。

**数据范围**：0 < N, V ≤ 1000，0 < vi, wi ≤ 1000。

### 输入

第一行两个整数 N, V，用空格隔开，分别表示物品种数和背包容积。接下来有 N 行，每行两个整数 vi, wi，用空格隔开，分别表示第 i 种物品的体积和价值。

### 输出

输出一个整数，表示最大价值。

### 样例

**输入：**
```
7 884
6148 6786
8500 8620
6136 6930
8700 6732
409 3388
9925 642
4324 5208
```

**输出：**
```
6776
```

### 我的代码

```cpp
#include <iostream>
#include <algorithm>
using namespace std;

const int N = 1010;
int n, m;
int v[N], w[N];
int f[N];

int main()
{
    cin >> n >> m;
    for (int i = 1; i <= n; i++)
        cin >> v[i] >> w[i];

    for (int i = 1; i <= n; i++)
        for (int j = v[i]; j <= m; j++)
            f[j] = max(f[j], f[j - v[i]] + w[i]);

    cout << f[m] << endl;
    return 0;
}
```

### 思路要点

- **题目本质**：完全背包——每件物品可以选无限次。与 01 背包的"每件最多 1 次"不同，完全背包中同一个物品可以被反复选取。这是背包问题的第二种基本变体。

- **DP 状态定义**（一维优化）：`f[j]` 表示容量为 j 的背包能获得的最大价值。使用一维数组而非二维，因为完全背包的递推关系天然适合正序一维滚动。

- **与 01 背包的核心区别——递推关系**：
  - 01 背包：`f[i][j] = max(f[i-1][j], f[i-1][j-v[i]] + w[i])` —— 依赖上一行 `[i-1]`
  - 完全背包：`f[i][j] = max(f[i-1][j], f[i][j-v[i]] + w[i])` —— 依赖同一行 `[i]`
  
  解释：01 背包中选了第 i 件后只能从前 i-1 件中继续选；完全背包中选了第 i 件后，仍可以从前 i 件中继续选（因为选无限次），所以是 `f[i][j-v[i]]` 而不是 `f[i-1][j-v[i]]`。

- **一维数组正序 vs 逆序的深刻理解**：

  - **01 背包一维必须逆序**：`for (j = m; j >= v[i]; j--)`。因为 `f[j-v[i]]` 需要的是上一轮的旧值（代表 `f[i-1][j-v[i]]`）。如果正序，`f[j-v[i]]` 可能已经被本物品更新过了（变成了 `f[i][j-v[i]]`），就等价于同一物品被选了多次——而这正是完全背包的行为！
  
  - **完全背包一维必须正序**：`for (j = v[i]; j <= m; j++)`。正序遍历时 `f[j-v[i]]` 被本物品更新过也没关系——因为我们正希望它代表 `f[i][j-v[i]]`（选了当前物品后还能继续选）。如果逆序，就退化成了 01 背包。

  这个对比是理解 01 背包和完全背包降维优化的关键！

- **递推过程示例**（完全背包，N=3, V=5）：
  ```
  处理 (v=1,w=2) 后:
  j=1: f[1]=max(f[1],f[0]+2)=2
  j=2: f[2]=max(f[2],f[1]+2)=max(0,2+2)=4
  j=3: f[3]=6
  j=4: f[4]=8
  j=5: f[5]=10
  ...
  最终 f[5]=10（5个第1件 = 5体积, 10价值）
  ```

- **复杂度分析**：时间 O(N×V)，空间 O(V)（一维优化后）。N, V ≤ 1000 时 N×V = $10^6$。

- **易错点**：
  - 完全背包一维的循环方向是**正序** `j = v[i] → m`，而 01 背包是**逆序** `j = m → v[i]`。两题搞混是最常见的错误！
  - 正序从 `j = v[i]` 开始（而非 j = 0），因为 j < v[i] 时物品放不下，无需更新。

<a id="link65-多重背包问题1"></a>

## LinK65 多重背包问题(1)

### 题目描述

有 N 种物品和一个容量是 V 的背包。第 i 种物品最多有 si 件，每件体积是 vi，价值是 wi。求解将哪些物品装入背包，可使物品体积总和不超过背包容量，且价值总和最大。输出最大价值。

**数据范围**：0 < N, V ≤ 100，0 < vi, wi, si ≤ 100。

### 输入

第一行两个整数 N, V，用空格隔开，分别表示物品种数和背包容积。接下来有 N 行，每行三个整数 vi, wi, si，用空格隔开，分别表示第 i 种物品的体积、价值和数量。

### 输出

输出一个整数，表示最大价值。

### 样例

**输入：**
```
4 5
1 2 3
2 4 1
3 4 3
4 5 2
```

**输出：**
```
10
```

### 我的代码

```cpp
#include <iostream>
#include <algorithm>
#include <cstring>
using namespace std;

const int N = 110;
int n, m;
int f[N];

int main()
{
    cin >> n >> m;
    for (int i = 1; i <= n; i++)
    {
        int v, w, s;
        cin >> v >> w >> s;
        for (int j = m; j >= 0; j--)
            for (int k = 1; k <= s && k * v <= j; k++)
                f[j] = max(f[j], f[j - k * v] + k * w);
    }
    cout << f[m] << endl;
    return 0;
}
```

### 思路要点

- **题目本质**：多重背包——每种物品有固定的数量上限 si（介于 01 背包的"最多 1 个"和完全背包的"无限个"之间）。这是背包问题的第三种基本变体。数据范围较小（N, V ≤ 100），可以直接用暴力枚举每种物品选几个。

- **朴素解法——三重循环暴力枚举**：
  - 对每种物品 i，枚举选 k 个（0 ≤ k ≤ s[i]，且 k×v[i] ≤ j）。
  - 转移方程：`f[j] = max(f[j], f[j - k*v] + k*w)`。
  - 本质是"把多重背包拆成 01 背包"：每种物品看作 s 件相同的独立物品，然后用 01 背包的方法处理。

- **为什么 j 是逆序**：因为把每个 k 看作 01 背包中独立的一件物品（选了 k 个就不能在同一轮中再选），逆序遍历保证每件物品至多被选一次。

- **数据范围分析**：N, V ≤ 100，三重循环的最坏情况是 N × V × max_s ≈ 100 × 100 × 100 = $10^6$，完全可以在 1 秒内完成。这也是为什么本题不需要二进制优化（LinK66 的数据范围更大，必须优化）。

- **与 01/完全背包的对比**：
  | 方面 | 01 背包 | 完全背包 | 多重背包（朴素） |
  |------|---------|----------|-----------------|
  | 每件可选次数 | 1 | ∞ | 0～s |
  | 一维 j 遍历方向 | 逆序 | 正序 | 逆序（01 模式） |
  | 额外枚举维度 | 无 | 无 | **k：选几个** |

- **复杂度分析**：时间 O(N × V × max_s) ≈ $10^6$（本题范围），空间 O(V)。如果 s 很大（如 10000），则需要二进制优化（见 LinK66）。

- **易错点**：
  - j 必须逆序！如果正序会导致同一个 k 的物品被多次选取（变成完全背包行为），最终可能超过 si 的限制。
  - 内层 k 循环的条件 `k <= s && k * v <= j` 两个都要检查：不能超过数量上限，也不能超过当前容量。
  - 读入在循环内完成，处理完一种物品后立即丢弃其数据，不用数组存储。

<a id="link66-多重背包问题2"></a>

## LinK66 多重背包问题(2)

### 题目描述

题目与 LinK65 完全一致（多重背包），但数据范围扩大到：0 < N ≤ 1000，0 < V ≤ 2000，0 < vi, wi, si ≤ 2000。朴素 O(N × V × s) 的三重循环会超时（最坏 4×$10^9$），必须使用**二进制优化**将多重背包转化为 01 背包。

### 输入

第一行两个整数 N, V，用空格隔开，分别表示物品种数和背包容积。接下来有 N 行，每行三个整数 vi, wi, si，用空格隔开，分别表示第 i 种物品的体积、价值和数量。

### 输出

输出一个整数，表示最大价值。

### 样例

**输入：**
```
4 5
1 2 3
2 4 1
3 4 3
4 5 2
```

**输出：**
```
10
```

### 我的代码

```cpp
#include <iostream>
#include <algorithm>
#include <cstring>
using namespace std;

const int N = 12010, M = 2010;
int n, m;
int v[N], w[N];
int f[M];

int main()
{
    cin >> n >> m;
    int cnt = 0;
    for (int i = 1; i <= n; i++)
    {
        int a, b, s;
        cin >> a >> b >> s;
        int k = 1;
        while (k <= s)
        {
            cnt++;
            v[cnt] = a * k;
            w[cnt] = b * k;
            s -= k;
            k *= 2;
        }
        if (s > 0)
        {
            cnt++;
            v[cnt] = a * s;
            w[cnt] = b * s;
        }
    }
    n = cnt;

    for (int i = 1; i <= n; i++)
        for (int j = m; j >= v[i]; j--)
            f[j] = max(f[j], f[j - v[i]] + w[i]);

    cout << f[m] << endl;
    return 0;
}
```

### 思路要点

- **题目本质**：多重背包的大数据版本。朴素 O(N×V×s) 在 s ≤ 2000 时最坏复杂度 = 1000 × 2000 × 2000 = 4×$10^9$，远超时限。必须使用**二进制拆分优化**将多重背包转化为 01 背包。

- **二进制优化原理（核心——打包法）**：
  - 问题：每种物品最多选 s 次，如果直接拆成 s 个独立的物品，物品总数 = Σ s_i，最多 2×$10^6$ 件，仍太大（2×$10^6$ × 2000 = 4×$10^9$）。
  - 关键洞察：用二进制表示任意 0~s 之间的整数。例如 s=13：
    - 13 = 1 + 2 + 4 + 6（前三个是 2 的幂，最后是 6 的余数）
    - 这四个"打包物品"的组合可以表示 0~13 之间的**任意数量**。
  - 拆分法则：`k = 1, 2, 4, 8, ...` 依次倍增，直到剩余 `s` 不够再拆一个 `k` 时，将剩余的 `s` 作为最后一个打包。
  - 每个打包物品：体积 = k×v，价值 = k×w（相当于 k 件原物品的捆绑）。

- **复杂度分析**：
  - 拆分后物品总数 = O(Σ log(s_i))。最坏情况：1000 种物品，每种 s=2000，$log_2$(2000) ≈ 11，总物品数 ≈ 11000 件。
  - 01 背包 O(物品数 × V) = 11000 × 2000 ≈ 2.2×$10^7$，完全可以接受。
  - 比朴素优化了约 200 倍！

- **拆分示例**（s=13 时）：
  ```
  循环: k=1, s=13→12, 打包(1*v, 1*w)
        k=2, s=12→10, 打包(2*v, 2*w)
        k=4, s=10→6,  打包(4*v, 4*w)
        k=8>6, 停止
  剩余: s=6, 打包(6*v, 6*w)
  → 打包总件数 = 4，可组合出 0~13 所有整数。
  ```

- **与 LinK65 的对比**：
  | 方面 | LinK65（朴素） | LinK66（二进制优化） |
  |------|--------------|-------------------|
  | 复杂度 | O(N×V×s) | O(N×V×log s) |
  | N, V 范围 | ≤ 100 | ≤ 1000, V ≤ 2000 |
  | 核心技巧 | 三重循环枚举 k | 二进制拆分 + 01 背包 |

- **易错点**：
  - 拆分过程中 `s -= k` 后不要忘记检查剩余的 `s > 0` 再追加最后一个打包。
  - 拆分完后 `n = cnt` 更新物品总数，后续 01 背包用新 n。
  - 数组 v 和 w 的大小要开 `N = 12010` 而非原始的 1010。
  - `while (k <= s)` 不是 `while (k < s)`——当 k == s 时还要再拆一次。

<a id="link67-分组背包问题"></a>

## LinK67 分组背包问题

### 题目描述

有 N 组物品和一个容量是 V 的背包。每组物品有若干个，同一组内的物品最多只能选一个。每件物品的体积是 vij，价值是 wij，其中 i 是组号，j 是组内编号。求解将哪些物品装入背包，可使物品总体积不超过背包容量，且总价值最大。输出最大价值。

**数据范围**：0 < N, V ≤ 100。

### 输入

第一行有两个整数 N, V，用空格隔开，分别表示物品组数和背包容量。接下来有 N 组数据：
- 每组数据第一行是一个整数 Si，表示第 i 个物品组的物品数量；
- 每组数据接下来 Si 行，每行有两个整数 vij, wij，表示第 i 个物品组的第 j 个物品的体积和价值。

### 输出

输出一个整数，表示最大价值。

### 样例

**输入：**
```
3 5
2
1 2
2 4
1
3 4
1
4 5
```

**输出：**
```
8
```

### 我的代码

```cpp
#include <iostream>
#include <algorithm>
#include <cstring>
using namespace std;

int n, m;
int v[110][110], w[110][110], f[110], s[110];

int main()
{
    scanf("%d%d", &n, &m);
    for (int i = 1; i <= n; i++)
    {
        scanf("%d", &s[i]);
        for (int j = 1; j <= s[i]; j++)
            scanf("%d%d", &v[i][j], &w[i][j]);
    }

    for (int i = 1; i <= n; i++)
    {
        for (int j = m; j >= 1; j--)
        {
            for (int k = 1; k <= s[i]; k++)
            {
                if (v[i][k] <= j)
                    f[j] = max(f[j], f[j - v[i][k]] + w[i][k]);
            }
        }
    }

    printf("%d", f[m]);
    return 0;
}
```

### 思路要点

- **题目本质**：分组背包——N 组物品，每组内最多选 1 件。这可以看作 01 背包的推广：01 背包中每组只有 1 件物品（只有"选或不选"），分组背包中每组有 Si 件但至多选其一。

- **DP 状态定义**：`f[j]` 表示容量为 j 的背包能获得的最大价值（一维优化）。

- **核心决策——在组内做选择**：
  - 对于第 i 组：要么一个都不选（f[j] 保持不变），要么选组内某个物品 k（`f[j] = max(f[j], f[j-v[i][k]] + w[i][k])`）。
  - 关键：同一组内的物品之间是互斥的——通过**对每个 j 先枚举组内所有物品**来体现互斥。

- **循环顺序的正确理解**（重要！）：
  ```
  for i = 1..n:            // 枚举组
      for j = m..0:         // 逆序！
          for k = 1..s[i]:  // 枚举组内物品
              if v[i][k] <= j: 更新
  ```
  - **为什么 j 必须逆序**：和 01 背包同理，`f[j-v[i][k]]` 必须来自上一组的状态。逆序确保每组至多贡献一个物品。
  - **为什么 k 在最内层**：对于固定的容量 j，遍历组内所有物品，取最好的一个。这保证了互斥性。

- **如果 k 和 j 循环颠倒会怎样**（常见错误）：
  - `for i → for k → for j = v..m`（正序 j）会导致同一物品被选多次，失去分组互斥的效果。

- **复杂度分析**：时间 O(Σ s[i] × V) = O(总物品数 × V)，最坏 100×100×100 = $10^6$。空间 O(V)。

- **易错点**：
  - j 逆序（和 01 背包一致），不能正序（正序会变成"组内完全背包"）。
  - `if (v[i][k] <= j)` 不可省略——容量不够时不能选该物品，但组内其他物品可能可以选。

<a id="link68-混合背包问题"></a>

## LinK68 混合背包问题

### 题目描述

有 N 种物品和一个容量是 V 的背包。物品一共有三类：
- 第一类物品只能用 1 次（01 背包）；
- 第二类物品可以用无限次（完全背包）；
- 第三类物品最多只能用 si 次（多重背包）。

每种体积是 vi，价值是 wi。求解将哪些物品装入背包，可使物品体积总和不超过背包容量，且价值总和最大。输出最大价值。

### 输入

第一行两个整数 N, V，用空格隔开，分别表示物品种数和背包容积。接下来有 N 行，每行三个整数 vi, wi, si：
- si = -1 表示第 i 种物品只能用 1 次；
- si = 0 表示第 i 种物品可以用无限次；
- si > 0 表示第 i 种物品可以使用 si 次。

### 输出

输出一个整数，表示最大价值。

### 样例

**输入：**
```
4 5
1 2 -1
2 4 1
3 4 0
4 5 2
```

**输出：**
```
8
```

### 我的代码

```cpp
#include <iostream>
#include <algorithm>
#include <cstring>
using namespace std;

const int N = 1007;
int n, m;
int f[N];

int main()
{
    cin >> n >> m;
    for (int i = 0; i < n; i++)
    {
        int v, w, s;
        cin >> v >> w >> s;

        if (!s)
        {
            for (int j = v; j <= m; j++)
                f[j] = max(f[j], f[j - v] + w);
        }
        else
        {
            if (s == -1) s = 1;

            for (int k = 1; k <= s; k *= 2)
            {
                for (int j = m; j >= k * v; j--)
                    f[j] = max(f[j], f[j - k * v] + k * w);
                s -= k;
            }
            if (s)
            {
                for (int j = m; j >= s * v; j--)
                    f[j] = max(f[j], f[j - s * v] + s * w);
            }
        }
    }

    cout << f[m] << endl;
    return 0;
}
```

### 思路要点

- **题目本质**：混合背包——将 01 背包、完全背包、多重背包三种类型混合在一起。每件物品的类型由参数 si 决定：si=-1（01 背包）、si=0（完全背包）、si>0（多重背包）。

- **分类处理策略**：
  - **si = 0（完全背包）**：直接套用完全背包的正序一维模板：`for (j = v; j <= m; j++)`。
  - **si = -1（01 背包）**：将 s 设为 1，然后走多重背包的二进制拆分流程。
  - **si > 0（多重背包）**：使用 LinK66 的二进制拆分优化，转化为 01 背包后用逆序一维处理。

- **三种背包模型的递推关系总结**：

  | 类型 | si 值 | 一维 j 方向 | 递推方程 |
  |------|-------|------------|---------|
  | 01 背包 | -1（或 1） | 逆序 | `f[j] = max(f[j], f[j-v] + w)` |
  | 完全背包 | 0 | **正序** | `f[j] = max(f[j], f[j-v] + w)` |
  | 多重背包 | > 0 | 逆序（拆分后） | 二进制拆分 + 01 背包 |

  注意 01 和完全的递推公式表面相同，区别仅在于 j 的遍历方向！

- **复杂度分析**：时间 O(Σ log(s_i) × V)（多重背包部分），完全背包部分 O(N×V)。在 N, V ≤ 1000 时可接受。

- **易错点**：
  - `if (!s)` 判断 s 是否为 0（完全背包），不要和 01 背包（s=-1）搞混。
  - 二进制拆分中 s 变量被修改（`s -= k`），但完全背包不经过拆分，不受影响。
  - 三种类型的处理在同一个 `f[]` 数组上顺序进行，因为各类物品互相独立、可以混合选取。

## LinK69 摘花生

### 题目描述

Hello Kitty 来到一片有网格状道路的矩形花生地，从西北角进去，东南角出来。地里每个道路的交叉点上都有种着一株花生苗，上面有若干颗花生，经过一株花生苗就能摘走该它上面所有的花生。Hello Kitty 只能向东或向南走，不能向西或向北走。问 Hello Kitty 最多能够摘到多少颗花生。

### 输入

第一行是一个整数 T，代表一共有多少组数据。接下来是 T 组数据。

每组数据的第一行是两个整数 R 和 C，分别代表花生苗的行数和列数。接下来 R 行数据，每行有 C 个整数，表示每株花生苗上的花生数目 M。

**数据范围**：1 ≤ T ≤ 100，1 ≤ R, C ≤ 100，0 ≤ M ≤ 1000。

### 输出

对每组输入数据，输出一行，内容为 Hello Kitty 能摘到的最多花生颗数。

### 样例

**输入：**
```
2
2 2
1 1
3 4
2 3
2 3 4
1 6 5
```

**输出：**
```
8
16
```

### 我的代码

```cpp
#include <iostream>
#include <cstring>
#include <algorithm>
using namespace std;

const int N = 110;
int n, m;
int w[N][N], f[N][N];

int main()
{
    int T;
    cin >> T;
    while (T--)
    {
        cin >> n >> m;
        for (int i = 1; i <= n; i++)
            for (int j = 1; j <= m; j++)
                cin >> w[i][j];

        for (int i = 1; i <= n; i++)
            for (int j = 1; j <= m; j++)
                f[i][j] = max(f[i - 1][j], f[i][j - 1]) + w[i][j];

        cout << f[n][m] << endl;
    }
    return 0;
}
```

### 思路要点

- **题目本质**：二维网格上的最大路径和问题。从左上角 (1,1) 出发，只能向右或向下移动，到达右下角 (n,m)，求经过格子的数字之和的最大值。这是数字三角形（LinK62）的二维网格版本。

- **DP 状态定义**：`f[i][j]` 表示从起点 (1,1) 走到 (i,j) 所能摘到的最大花生数。

- **递推关系**：
  - 到达 (i,j) 的方式只有两种：从上方 (i-1,j) 向下走一步，或从左边 (i,j-1) 向右走一步。
  - 因此：`f[i][j] = max(f[i-1][j], f[i][j-1]) + w[i][j]`

- **与 LinK62（数字三角形）的对比**：
  | 方面 | 数字三角形 (LinK62) | 摘花生 (LinK69) |
  |------|-------------------|-----------------|
  | 形状 | 三角形 | 矩形 |
  | 移动方向 | 左下 + 右下 | 右 + 下 |
  | 递推方向 | 自底向上 | **自顶向下** |
  | 列数变化 | 每行不同 | 每行固定 |

- **边界处理**：由于 `max(f[i-1][j], f[i][j-1])` 在 i=1 或 j=1 时会访问 f[0][j] 或 f[i][0]，全局数组默认初始化为 0，恰好正确——起点 (1,1) 的上方和左方都是 0。

- **多组数据**：用 `while (T--)` 处理。每组内 f 数组不需要显式清空——因为每次计算 `f[i][j]` 时会被新值覆盖。

- **复杂度分析**：每组 O(R×C) 时间，总 O(T×R×C) ≤ 100×100×100 = $10^6$。空间 O(R×C)。

- **易错点**：
  - 移动方向限制是"只能向东或向南"（右或下），不是四方向。
  - `f[i][j]` 初值不能设 INF——这里求最大值且 w[i][j] ≥ 0，默认 0 是正确的。

<a id="link70-最低通行费"></a>

## LinK70 最低通行费

### 题目描述

一个商人穿过一个 N×N 的正方形的网格，去参加一个非常重要的商务活动。他要从网格的左上角进，右下角出。每穿越中间 1 个小方格，都要花费 1 个单位时间。商人必须在 (2N - 1) 个单位时间穿越出去。在经过中间的每个小方格时，都需要缴纳一定的费用。这个商人期望在规定时间内用最少费用穿越出去。请问至少需要多少费用？

注意：不能对角穿越各个小方格（即，只能向上下左右四个方向移动且不能离开网格）。

### 输入

第一行是一个整数 N，表示正方形的宽度。后面 N 行，每行 N 个不大于 100 的正整数，为网格上每个小方格的费用。

**数据范围**：1 ≤ N ≤ 100。

### 输出

输出一个整数，表示至少需要的费用。

### 样例

**输入：**
```
5
1  4  6  8  10
2  5  7  15 17
6  8  9  18 20
10 11 12 19 21
20 23 25 29 33
```

**输出：**
```
109
```

### 我的代码

```cpp
#include <iostream>
#include <cstring>
#include <algorithm>
using namespace std;

const int N = 110, INF = 1e9;
int n;
int w[N][N], f[N][N];

int main()
{
    scanf("%d", &n);
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= n; j++)
            scanf("%d", &w[i][j]);

    for (int i = 1; i <= n; i++)
    {
        for (int j = 1; j <= n; j++)
        {
            if (i == 1 && j == 1)
                f[i][j] = w[i][j];
            else
            {
                f[i][j] = INF;
                if (i > 1)
                    f[i][j] = min(f[i][j], f[i - 1][j] + w[i][j]);
                if (j > 1)
                    f[i][j] = min(f[i][j], f[i][j - 1] + w[i][j]);
            }
        }
    }

    printf("%d\n", f[n][n]);
    return 0;
}
```

### 思路要点

- **题目本质**：与 LinK69（摘花生）几乎是同一题，但求**最小值**（最少费用）而非最大值。时间限制 (2N-1) 是障眼法——从左上到右下的最短路径（只走右和下）恰好需要 2N-1 步，意味着商人**不能走回头路**。所以实际只允许向右或向下。

- **时间限制的隐含信息**：
  - N×N 网格，从 (1,1) 到 (N,N)，每步穿过 1 个小方格花费 1 单位时间。
  - 如果只能向右或向下，需要走 (N-1) + (N-1) = 2N-2 步，经过 2N-1 个格子（包括起点）。
  - 恰好等于题目给定的最长时间限制 → 不能绕路！

- **DP 状态定义**：`f[i][j]` 表示从起点到 (i,j) 的最小费用。

- **递推关系**：
  - `f[i][j] = min(f[i-1][j], f[i][j-1]) + w[i][j]`（当 i>1 或 j>1 时）
  - 起点特殊处理：`f[1][1] = w[1][1]`。

- **与摘花生（LinK69）的差异要点**：

  | 方面 | 摘花生 | 最低通行费 |
  |------|--------|----------|
  | 优化目标 | **最大值** | **最小值** |
  | INF 初始化 | 不需要（默认 0 即可） | **需要**（防止 min 时选到 0） |
  | 边界处理 | 天然正确（f[0][*]=0） | **必须特殊处理**（f[0][*]=0 会被 min 选中） |
  | f[i][j] 公式 | max + w | min + w |

- **为什么必须初始化 INF**：因为求最小值时，如果 `f[0][j] = 0`（默认初值），`min(f[i-1][j], f[i][j-1])` 会选中 0 而非真正的路径值，导致错误。所以需要用 `INF = 1e9` 初始化所有非起点的 f 值。

- **复杂度分析**：O($N^2$) 时间，O($N^2$) 空间。N ≤ 100 时 $N^2$ = 10000，轻松完成。

- **易错点**：
  - 忘记将非起点的 f 设为 INF，导致 `min(f[i-1][j], f[i][j-1])` 错误选 0。
  - INF 值的选择：`1e9` 足够大（路径费用最大约 10000×100 = $10^6$，远小于 1e9），且不会溢出。
  - 时间限制 (2N-1) 是关键约束——理解成只能右/下才能通过。
  - 起点 (1,1) 的费用也要计入！

## LinK71 最长上升子序列

### 题目描述

给定一个长度为 N 的数列，求数值严格单调递增的子序列的长度最长是多少。

**数据范围**：N ≤ 1000。

### 输入

第一行包含整数 N。第二行包含 N 个整数，表示完整序列。

### 输出

输出一个整数，表示最大长度。

### 样例

**输入：**
```
7
3 1 2 1 8 5 6
```

**输出：**
```
4
```

### 我的代码

```cpp
#include <iostream>
#include <cstring>
#include <algorithm>
using namespace std;

const int N = 1010;
int n;
int a[N], f[N];

int main()
{
    scanf("%d", &n);
    for (int i = 1; i <= n; i++)
        scanf("%d", &a[i]);

    for (int i = 1; i <= n; i++)
    {
        f[i] = 1;
        for (int j = 1; j < i; j++)
            if (a[j] < a[i])
                f[i] = max(f[i], f[j] + 1);
    }

    int res = 0;
    for (int i = 1; i <= n; i++)
        res = max(res, f[i]);

    printf("%d\n", res);
    return 0;
}
```

### 思路要点

- **题目本质**：最长上升子序列（LIS, Longest Increasing Subsequence）——在一个序列中找一个子序列（不要求连续），使得每个元素严格大于前一个元素，求这样的子序列的最大长度。这是"线性 DP"的核心代表题。

- **子序列 vs 子串**：子序列不要求连续（可以跳过中间的元素），而子串要求连续。LIS 是子序列问题。

- **DP 状态定义**：`f[i]` 表示以第 i 个数**结尾**的最长上升子序列的长度。关键：状态必须定义到"以谁结尾"，因为后续的递推需要知道最后一个元素是什么。

- **递推关系**：
  - 对于每个位置 i，枚举它前面所有的位置 j（j < i）：
    - 如果 `a[j] < a[i]`（可以接在后面）：`f[i] = max(f[i], f[j] + 1)`
    - 如果 `a[j] >= a[i]`：不能接，跳过。
  - 初始化：`f[i] = 1`（每个数单独成为一个长度为 1 的上升子序列）。
  - 最终答案：`max(f[1], f[2], ..., f[n])`（不一定是 f[n]！最长子序列不一定以最后一个元素结尾）。

- **递推过程示例**（`3, 1, 2, 1, 8, 5, 6`）：

  ```
  i=1, a[1]=3: 前面没有, f[1]=1
  i=2, a[2]=1: a[1]=3 > 1, 不能接, f[2]=1
  i=3, a[3]=2: a[2]=1<2能接, f[3]=f[2]+1=2
  i=4, a[4]=1: 不能接, f[4]=1
  i=5, a[5]=8: a[3]=2<8 → f[5]=3 (1→2→8)
  i=6, a[6]=5: a[3]=2<5 → f[6]=3 (1→2→5)
  i=7, a[7]=6: a[6]=5<6 → f[7]=4 (1→2→5→6)
  
  最终 max = 4
  ```

- **复杂度分析**：时间 O($N^2$)（双重循环），空间 O(N)。N ≤ 1000 时 $N^2$ = $10^6$，可接受。N 更大时（如 $10^5$）需要贪心 + 二分优化（见 LinK72）。

- **易错点**：
  - 最终答案是遍历所有 f[i] 取最大值，不能直接输出 f[n]——最长上升子序列不一定以最后一个元素结尾！
  - 初始化 `f[i] = 1` 不能忘。
  - 严格递增的条件是 `a[j] < a[i]`（不能有等号）。

## LinK72 最长上升子序列(2)

### 题目描述

与 LinK71 完全相同的 LIS 问题，但数据范围扩大到 N ≤ 100000。O($N^2$) 的朴素 DP 会超时（$10^{10}$ 次操作），必须使用**贪心 + 二分**优化到 O(N log N)。

### 输入

第一行包含整数 N。第二行包含 N 个整数，表示完整序列。

### 输出

输出一个整数，表示最大长度。

### 样例

**输入：**
```
7
3 1 2 1 8 5 6
```

**输出：**
```
4
```

### 我的代码

```cpp
#include <iostream>
#include <algorithm>
using namespace std;

const int N = 100010;
int n;
int a[N], q[N];

int main()
{
    scanf("%d", &n);
    for (int i = 0; i < n; i++)
        scanf("%d", &a[i]);

    int len = 0;
    for (int i = 0; i < n; i++)
    {
        int l = 0, r = len;
        while (l < r)
        {
            int mid = l + r + 1 >> 1;
            if (q[mid] < a[i])
                l = mid;
            else
                r = mid - 1;
        }
        len = max(len, r + 1);
        q[r + 1] = a[i];
    }

    printf("%d\n", len);
    return 0;
}
```

### 思路要点

- **题目本质**：LIS 的大数据版本。N ≤ 100000 时 O($N^2$) 的朴素 DP（$10^{10}$ 次操作）会超时，必须用 O(N log N) 的贪心 + 二分优化。

- **贪心 + 二分优化原理（核心）**：

  维护一个数组 `q[]`，其中 `q[i]` 表示**长度为 i 的上升子序列的末尾元素的最小值**。

  - 贪心思想：对于相同长度的上升子序列，末尾元素越小，后续元素越容易接在后面。所以我们只关心每种长度下末尾元素的最小值。
  - 可以证明 `q[]` 是**严格单调递增**的。
  - 处理每个新元素 a[i] 时，在 `q[]` 中二分查找**最后一个小于 a[i] 的位置 r**，然后更新 `q[r+1] = a[i]`。

- **二分查找细节**：
  - 查找目标：在 `q[1..len]` 中找到最大的 r 使得 `q[r] < a[i]`。
  - `mid = l + r + 1 >> 1`（上取整）——防止 l 和 r 相邻时的死循环。
  - `q[0]` 作为哨兵（默认为 0，天然 < 所有正数 a[i]）。

- **算法执行过程**（`3, 1, 2, 1, 8, 5, 6`）：

  ```
  初始化: len = 0

  a[0]=3: r=0, q[1]=3, len=1
  a[1]=1: r=0, q[1]=1 (3被替换), len=1
  a[2]=2: r=1, q[2]=2, len=2
  a[3]=1: r=0, q[1]=1 (不变), len=2
  a[4]=8: r=2, q[3]=8, len=3
  a[5]=5: r=2, q[3]=5 (8被替换), len=3
  a[6]=6: r=3, q[4]=6, len=4

  最终 len = 4
  ```

  注意：`q[]` 中的序列不一定是真正的上升子序列——q[] 只记录每种长度的最小末尾值。

- **与 LinK71 的对比**：
  | 方面 | LinK71（朴素） | LinK72（优化） |
  |------|-------------|-------------|
  | 复杂度 | O($N^2$) | O(N log N) |
  | 适用 N | ≤ 1000 | ≤ 100000 |
  | 能否输出具体子序列 | 能（通过回溯 DP） | 仅长度（q[] 不等于子序列） |
  | 核心技巧 | 双重循环 DP | 贪心 + 二分 |

- **复杂度分析**：时间 O(N log N)，空间 O(N)。N=100000 时 N log N ≈ 1.7×$10^6$。

- **易错点**：
  - 二分模板：`l + r + 1 >> 1`（上取整）配合 `l = mid` 和 `r = mid - 1`，是"找最后一个满足条件的元素"的标准模板。
  - `q[r + 1] = a[i]` 中 r+1 可能等于 len+1（扩展长度）或 ≤ len（替换已有值）。

<a id="link73-拦截导弹"></a>

## LinK73 拦截导弹

### 题目描述

某国为了防御敌国的导弹袭击，发展出一种导弹拦截系统。但是这种导弹拦截系统有一个缺陷：虽然它的第一发炮弹能够到达任意的高度，但是以后每一发炮弹都不能高于前一发的高度。某天，雷达捕捉到敌国的导弹来袭。由于该系统还在试用阶段，所以只有一套系统，因此有可能不能拦截所有的导弹。

输入导弹依次飞来的高度（雷达给出的高度数据是不大于 30000 的正整数），计算：
1. 这套系统最多能拦截多少导弹；
2. 如果要拦截所有导弹，最少要配备多少套这种导弹拦截系统。

### 输入

一行，为导弹依次飞来的高度。

### 输出

两行，分别是最多能拦截的导弹数与要拦截所有导弹最少要配备的系统数。

### 样例

**输入：**
```
389 207 155 300 299 170 158 65
```

**输出：**
```
6
2
```

### 我的代码

```cpp
#include <iostream>
#include <algorithm>
#include <sstream>
using namespace std;

const int N = 1010;
int n;
int h[N], f[N], q[N];

int main()
{
    string line;
    getline(cin, line);
    stringstream ssin(line);
    while (ssin >> h[n])
        n++;

    int res = 0, cnt = 0;
    for (int i = 0; i < n; i++)
    {
        f[i] = 1;
        for (int j = 0; j < i; j++)
            if (h[i] <= h[j])
                f[i] = max(f[i], f[j] + 1);
        res = max(res, f[i]);

        int k = 0;
        while (k < cnt && q[k] < h[i])
            k++;
        if (k == cnt)
            q[cnt++] = h[i];
        else
            q[k] = h[i];
    }

    printf("%d\n", res);
    printf("%d\n", cnt);
    return 0;
}
```

### 思路要点

- **题目本质**：两个经典问题的组合：
  1. **第一问**：最长**不上升**子序列的长度（导弹高度不能高于前一发 → 递减或相等）。
  2. **第二问**：最少的不上升子序列覆盖数 = 最长上升子序列的长度（Dilworth 定理）。

- **第一问——最长不上升子序列**：
  - 与 LIS（LinK71）几乎一样，只是条件从 `a[j] < a[i]` 改为 `h[i] <= h[j]`（序列不上升）。
  - 递推：`if (h[i] <= h[j]) f[i] = max(f[i], f[j] + 1)`。

- **第二问——Dilworth 定理**：
  - 在任意有限偏序集中，最少链覆盖数 = 最长反链长度。
  - 应用到本题：最少的不上升子序列覆盖数 = 最长上升子序列的长度。
  - 代码中用贪心实现：维护数组 `q[]` 表示每套系统当前的拦截高度。对于每个导弹，分配给"当前拦截高度最低但够得着"的系统（贪心分配），如果没有系统能拦截则新增一套。

- **算法执行过程**（`389, 207, 155, 300, 299, 170, 158, 65`）：

  第一问：
  ```
  389 → f[0]=1; 207≤389 → f[1]=2; 155≤389,207 → f[2]=3
  300≤389 → f[3]=2; 299≤389 → f[4]=2
  170≤389,207,155 → f[5]=4; 158 → f[6]=5; 65 → f[7]=6
  答案 = 6
  ```

  第二问（贪心分配）：
  ```
  389 → q=[389]; 207 → q=[207]; 155 → q=[155]
  300 → q=[155, 300]（新系统）; 299 → q=[155, 299]
  170 → q=[155, 170]; 158 → q=[155, 158]
  65  → q=[65, 158]; cnt = 2
  ```

- **一行输入处理**：`getline(cin, line)` 读入整行，然后用 `stringstream ssin(line)` 逐个解析整数。

- **复杂度分析**：第一问 O($N^2$)（朴素 LIS），第二问 O($N^2$)（贪心遍历）。N 不大（≤ 1000），可以接受。

- **易错点**：
  - 第一问是不**上升**子序列（`h[i] <= h[j]`），不是严格递减（`h[i] < h[j]`），漏掉等号会错。
  - 输入是一行空格分隔的整数，需要 `getline` + `stringstream` 解析。

## LinK75 最长公共子序列

### 题目描述

给定两个长度分别为 N 和 M 的字符串 A 和 B，求既是 A 的子序列又是 B 的子序列的字符串长度最长是多少。

**数据范围**：1 ≤ N, M ≤ 1000。

### 输入

第一行包含两个整数 N 和 M。第二行包含一个长度为 N 的字符串，表示字符串 A。第三行包含一个长度为 M 的字符串，表示字符串 B。字符串均由小写字母构成。

### 输出

输出一个整数，表示最大长度。

### 样例

**输入：**
```
4 5
acbd
abedc
```

**输出：**
```
3
```

### 我的代码

```cpp
#include <iostream>
#include <algorithm>
using namespace std;

const int N = 1010;
int n, m;
char a[N], b[N];
int f[N][N];

int main()
{
    cin >> n >> m >> a + 1 >> b + 1;
    for (int i = 1; i <= n; i++)
    {
        for (int j = 1; j <= m; j++)
        {
            if (a[i] == b[j])
                f[i][j] = f[i - 1][j - 1] + 1;
            else
                f[i][j] = max(f[i - 1][j], f[i][j - 1]);
        }
    }

    cout << f[n][m] << '\n';
    return 0;
}
```

### 思路要点

- **题目本质**：最长公共子序列（LCS, Longest Common Subsequence）——在两个字符串中分别取一个子序列（可以不连续），使得两者完全相同，求这种子序列的最大长度。这是"双序列 DP"最经典的代表题。

- **DP 状态定义**：`f[i][j]` 表示 A 的前 i 个字符与 B 的前 j 个字符的最长公共子序列长度。

- **递推关系推导（核心——根据 a[i] 和 b[j] 是否相等分成两种情况）**：

  1. **a[i] == b[j]**：这两个字符可以"配对"成为 LCS 的最后一个字符。
     - `f[i][j] = f[i-1][j-1] + 1`
     - 匹配一个相等的字符不会比不匹配更差。

  2. **a[i] != b[j]**：至少有一个字符不能出现在 LCS 中。
     - `f[i][j] = max(f[i-1][j], f[i][j-1])`
     - 即放弃 a[i] 或放弃 b[j]，取两者中较大者。

- **为什么不需要考虑 `f[i-1][j-1]`**：当 a[i] != b[j] 时，`f[i-1][j-1]` 已经被 `f[i-1][j]` 和 `f[i][j-1]` 覆盖（多一个字符不会减少 LCS 长度）。

- **递推过程示例**（A = "acbd", B = "abedc"）：

  ```
    f    ""  a  b  e  d  c
    ""   0   0  0  0  0  0
    a    0   1  1  1  1  1
    c    0   1  1  1  1  2
    b    0   1  2  2  2  2
    d    0   1  2  2  3  3

  f[4][5] = 3，LCS = "abd"（或 "acd"）
  ```

- **输入技巧——`cin >> a + 1`**：从 a[1] 开始填入字符串，让下标从 1 开始，与 DP 的 `f[i][j]` 对齐。

- **复杂度分析**：时间 O(N×M)，空间 O(N×M)。N, M ≤ 1000 时 N×M = $10^6$。

- **易错点**：
  - `f[i][j] = f[i-1][j-1] + 1` 只在 `a[i] == b[j]` 时执行。
  - 当 `a[i] != b[j]` 时是取 `max`，不是取 `min`。
  - `a + 1` 和 `b + 1` 需要 a 和 b 是全局数组（已零初始化）。

## LinK76 石子合并

### 题目描述

设有 N 堆石子排成一排，其编号为 1, 2, 3, …, N。每堆石子有一定的质量，可以用一个整数来描述，现在要将这 N 堆石子合并成为一堆。每次只能合并相邻的两堆，合并的代价为这两堆石子的质量之和，合并后与这两堆石子相邻的石子将和新堆相邻，合并时由于选择的顺序不同，合并的总代价也不相同。

例如有 4 堆石子分别为 1, 3, 5, 2，我们可以先合并 1、2 堆，代价为 4，得到 4, 5, 2，又合并 1, 2 堆，代价为 9，得到 9, 2，再合并得到 11，总代价为 4+9+11=24；如果第二步是先合并 2, 3 堆，则代价为 7，得到 4, 7，最后一次合并代价为 11，总代价为 4+7+11=22。

问题是：找出一种合理的方法，使总的代价最小，输出最小代价。

**数据范围**：1 ≤ N ≤ 300。

### 输入

第一行一个数 N 表示石子的堆数 N。第二行 N 个数，表示每堆石子的质量（均不超过 1000）。

### 输出

输出一个整数，表示最小代价。

### 样例

**输入：**
```
4
1 3 5 2
```

**输出：**
```
22
```

### 我的代码

```cpp
#include <iostream>
#include <cstring>
using namespace std;

const int N = 307;
int a[N], s[N];
int f[N][N];

int main()
{
    int n;
    cin >> n;

    for (int i = 1; i <= n; i++)
    {
        cin >> a[i];
        s[i] += s[i - 1] + a[i];
    }

    memset(f, 0x3f, sizeof f);

    for (int len = 1; len <= n; len++)
    {
        for (int i = 1; i + len - 1 <= n; i++)
        {
            int j = i + len - 1;
            if (len == 1)
            {
                f[i][j] = 0;
                continue;
            }

            for (int k = i; k <= j - 1; k++)
                f[i][j] = min(f[i][j], f[i][k] + f[k + 1][j] + s[j] - s[i - 1]);
        }
    }

    cout << f[1][n] << endl;
    return 0;
}
```

### 思路要点

- **题目本质**：经典的石子合并问题——N 堆石子排成一排，每次只能合并相邻两堆，代价为两堆质量之和。求将所有石子合并为一堆的最小总代价。这是**区间 DP** 的代表性入门题。

- **为什么不能用贪心（哈夫曼）**：哈夫曼适用于"任意两堆合并"，而本题要求**只能合并相邻的**。由于必须相邻，哈夫曼贪心不是最优。

- **区间 DP 状态定义**：`f[i][j]` 表示将第 i 堆到第 j 堆石子合并为一堆的最小总代价。

- **递推关系推导（核心——枚举最后一次合并的位置）**：
  - 总代价 = 合并左半 [i,k] 的最小代价 + 合并右半 [k+1,j] 的最小代价 + 最后一次合并的代价（[i,j] 的总质量）。
  - `f[i][j] = min_{k=i}^{j-1} (f[i][k] + f[k+1][j] + sum(i, j))`
  - 其中 `sum(i, j) = s[j] - s[i-1]`（前缀和 O(1) 计算）。

- **DP 的枚举顺序——区间长度循环**：
  - 区间 DP 不能简单地 `for i` `for j` 递推，因为 `f[i][j]` 依赖于所有更短的子区间。
  - 正确顺序：**按区间长度枚举**。先处理 len=1，再 len=2，……，最后 len=N。
  - 当 `len == 1` 时，单堆石子不需要合并（`f[i][i] = 0`）。

- **前缀和优化**：`s[i] = s[i-1] + a[i]`，`s[j] - s[i-1]` O(1) 得到区间总质量。

- **算法执行过程**（`1, 3, 5, 2`）：

  ```
  s = [0, 1, 4, 9, 11]

  len=1: f[1][1]=f[2][2]=f[3][3]=f[4][4]=0
  len=2: f[1][2]=4, f[2][3]=8, f[3][4]=7
  len=3: f[1][3]=13 (k=2), f[2][4]=17 (k=2)
  len=4: f[1][4]=min(28, 22←k=2, 24)=22

  最终 f[1][4] = 22
  ```

- **区间 DP 的通用模板**：
  1. 初始化 `f[i][i] = 0`
  2. `for len = 2 to n`
  3. `for i = 1; i+len-1 <= n; i++`
  4. `j = i+len-1`
  5. `for k = i to j-1` 进行状态转移
  6. 答案 = `f[1][n]`

- **复杂度分析**：时间 O($N^3$)，空间 O($N^2$)。N ≤ 300 时 $N^3$ = 2.7×$10^7$，可在 1 秒内完成。N 更大时需要四边形不等式优化到 O($N^2$)。

- **易错点**：
  - `memset(f, 0x3f, sizeof f)` 后一定要把 `len == 1` 的区间设为 0！
  - 分割点 k 的范围是 `[i, j-1]`（左右都要至少有一堆）。
  - 区间 DP 一定按长度递增处理，不能 `for i` `for j` 直接递推。

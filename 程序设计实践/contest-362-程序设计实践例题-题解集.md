### LinK02 完美立方

**思路**：题目要找所有满足 $a^3 = b^3 + c^3 + d^3$ 的组合。最简单的想法：用四重循环把 a、b、c、d 从 2 到 N 全部试一遍。但这样同一个组合会被试很多次（比如 b=3,c=4,d=5 和 b=4,c=3,d=5 其实是一回事）。解决办法：让 b ≤ c ≤ d（从小到大排好队），这样每种组合只会出现一次。N 最大 100，总共要试约 1600 万次，电脑 1 秒内能算完。

**关键代码**：
```cpp
for (a = 2; a <= N; a++) {
    int a3 = a * a * a;              // 预计算 a³，避免内层重复计算
    for (b = 2; b < N; b++)
        for (c = b; c < N; c++)      // b≤c≤d 天然有序，避免重复排列
            for (d = c; d < N; d++)
                if (a3 == b*b*b + c*c*c + d*d*d)
                    cout << "Cube = " << a << ", Triple = (" << b << "," << c << "," << d << ")" << endl;
}
```

**总结**：枚举时利用有序约束（b≤c≤d）能避免同一组合的重复排列。`a*a*a` 提到最外层是常数优化好习惯。

### LinK03 人的周期

**思路**：在 d 天之后，找三个周期（23天、28天、33天）下一次同时出现高峰的日期。不要一天一天地试（最坏要试 21252 天），用"跳着找"的方法：

- **第一步**：从 d+1 开始一天天找，找到第一个满足"体力高峰"的日期（最多找 23 天）。
- **第二步**：从上一步找到的日期开始，每次跳 23 天（这样体力高峰条件一直满足），找第一个也满足"感情高峰"的日期（最多跳 28 次）。
- **第三步**：再每次跳 23×28=644 天（保证前两个条件一直满足），找第一个也满足"智力高峰"的日期（最多跳 33 次）。

这样总共最多试 23+28+33=84 次就能找到答案，比一天天试快了几百倍。

**关键代码**：
```cpp
int k;
for (k = d + 1; (k - p) % 23; ++k);       // 从 d+1 开始，找到第一个满足体力周期的
for (; (k - e) % 28; k += 23);            // 保持体力周期满足，步长 23
for (; (k - i) % 33; k += 23 * 28);       // 保持前两个满足，步长 644
cout << "Case " << caseNumber << ": the next triple peak occurs in " << k - d << " days." << endl;
```

**总结**：逐步缩小搜索步长的"跳跃法"是解决多条件同余问题的利器——步长 = 已满足条件的模数之积。答案不超过 21252（23×28×33）。

### LinK04 排序考试

**思路**：题目给了很多组数据，每组数据第一个数告诉你有几个数字要排序。用 C++ 自带的 `sort()` 函数就行——它是世界上最常用的排序算法之一，比自己写的快且不会出错。需要注意两点：① 用 `vector` 存数据（大小灵活，不会爆栈）；② 输出时数字间加空格，但最后一个数字后面不能有空格。

**关键代码**：
```cpp
int T; cin >> T;
while (T--) {
    int N; cin >> N;
    vector<int> v(N);
    for (int i = 0; i < N; i++) cin >> v[i];
    sort(v.begin(), v.end());               // STL 排序 O(N log N)
    for (int i = 0; i < N; i++) {
        if (i > 0) cout << " ";             // 控制空格，行末无多余空格
        cout << v[i];
    }
    cout << endl;
}
```

**总结**：大数组（>10⁵）用 `vector` 而不用定长栈数组，避免栈溢出。输出格式"数字间空格分隔、行末无空格"是 OJ 常见要求。

### LinK05 假币问题

**思路**：12 枚硬币（编号 A~L），11 枚真、1 枚假，假币重量和真币不同但不确定是轻还是重。天平称了三次，根据三次结果找出假币并判断轻重。

这题的关键是**搜索空间极小**——12 枚币 × 2 种可能（轻/重）= 24 种假设。直接把每种假设代入三次称量结果去验证，矛盾的就是错的，唯一不矛盾的就是答案。验证时有一个减少代码量的对称技巧：

首先理解天平结果的物理含义（以"假币轻"为例）：
- `even`（平衡）：假币**不在**天平任何一端——否则轻的一边会翘起。所以假币不能出现在左盘或右盘。
- `up`（右端高 / 右边翘起）：说明右边轻，**轻假币必须在右边**。
- `down`（右端低 / 右边下沉）：说明左边轻，**轻假币必须在左边**。

那"假币重"怎么办？如果假币是重的，想象把天平左右交换——重的在哪边哪边就沉，交换后"沉"就变成了"翘"，和轻假币的行为完全对称。所以代码中遇到 `!isLight`（假设假币重）时，先把左右字符串 `swap`，然后全部按"轻假币"的逻辑判断。这个 `swap` 是整个函数最妙的一笔。

最后，主函数枚举所有 24 种可能，一旦 `isFake` 返回 true 就输出并 break。

**关键代码**：
```cpp
string Left[3], Right[3], result[3];  // 三次称量：左盘、右盘、结果

bool isFake(char coin, bool isLight) {
    string c; c.push_back(coin);       // 把 char 转成 string 方便 find
    for (int i = 0; i < 3; i++) {
        string l = Left[i], r = Right[i];
        if (!isLight) swap(l, r);      // ★ 假币重 → 交换左右，统一按轻处理
        switch (result[i][0]) {
            case 'e':                  // 平衡：假币不能在任何一边
                if (l.find(c)!=npos || r.find(c)!=npos) return false; break;
            case 'u':                  // 右边翘：轻假币必须在右
                if (r.find(c) == npos) return false; break;
            case 'd':                  // 右边沉：轻假币必须在左
                if (l.find(c) == npos) return false; break;
        }
    }
    return true;  // 三次称量全部吻合，假设成立
}

// 主函数中枚举
for (char coin = 'A'; coin <= 'L'; coin++) {
    if (isFake(coin, true))       // 假设轻
        cout << coin << " is light." << endl;
    else if (isFake(coin, false)) // 假设重
        cout << coin << " is heavy." << endl;
}
```

**总结**：枚举 + 验证是处理逻辑推理题的通用方法。关键技巧：`swap` 将"重假币"对称转化为"轻假币"，避免写两套验证逻辑。物理含义要理清：`up`=右边翘（轻的在右），`down`=右边沉（轻的在左）。

### LinK06 两数之和

**思路**：在一个**升序排列**的数组中，找两个数之和等于 target。暴力做法是双重循环 O($N^2$)，但利用"有序"这个条件可以快得多——**双指针（对撞指针）**：左指针 left 从最小的数开始，右指针 right 从最大的数开始。每次算 `nums[left] + nums[right]`：如果和正好等于 target 就找到了；如果和偏小，说明 left 太小了，左指针右移（拿更大的数）；如果和偏大，说明 right 太大了，右指针左移（拿更小的数）。两个指针就像在数组两端"夹逼"目标值，每次移动排除一端，最多走 N 步就必定找到答案。这个技巧的核心在于**有序性**——数组升序保证了移动左指针能单调增大和、移动右指针能单调减小和。

**关键代码**：
```cpp
pair<int,int> twoSum(const vector<int>& nums, int target) {
    int left = 0, right = nums.size() - 1;
    while (left < right) {
        int sum = nums[left] + nums[right];
        if (sum == target) return {left, right};      // 找到
        else if (sum < target) left++;                 // 和太小 → 左指针右移
        else right--;                                  // 和太大 → 右指针左移
    }
    return {-1, -1};
}
```

**总结**：对撞指针 $O(N)$ 的前提是**数组有序**。移动规则：和小则 left++（增大和），和大则 right--（减小和），方向不能搞反。每次移动至少排除一个元素，最多 N 步找完。

### LinK09 汉诺塔I

**思路**：把 N 个盘子从 A 柱移到 C 柱，B 柱当临时中转站。怎么移？用**递归**的想法：把"移动 N 个盘"拆成三步——① 先把上面 N-1 个小盘从 A 搬到 B（用 C 当临时中转）；② 把最底下那个大盘直接从 A 搬到 C；③ 再把 N-1 个小盘从 B 搬到 C（用 A 当临时中转）。当 N=1 时只剩一个盘，直接搬就行，不用再递归了。
函数包含四个参数：移动盘子的数量n，开始柱子start，中转柱子other，目标柱子target。

**关键代码**：
```cpp
void hanoi(int n, char start, char other, char target) {
    if (n == 1) { cout << start << "->" << target << endl; return; }
    hanoi(n - 1, start, target, other);    // ① n-1: start → other (借助 target)
    cout << start << "->" << target << endl; // ② 最大盘: start → target
    hanoi(n - 1, other, start, target);    // ③ n-1: other → target (借助 start)
}
```

**总结**：汉诺塔是递归思想的典范——把大问题分解为"移动上面 n-1 个"和"移动最底下 1 个"两个子问题。移动次数 = $2^n - 1$。

### LinK10 汉诺塔II

**思路**：和汉诺塔 I 完全一样的思路，只是柱子编号不再是固定的 A/B/C，而是由输入决定（比如可能是 a b c），输出时还要带上"第几号盘子"的编号。盘子从小到大编号为 1~n，代码里用 `id` 参数记住"当前这一摞盘子里最小的那个编号是多少"，最底下那个大盘的编号就是 `id + n - 1`。
函数新增了一个参数代表当前最小盘子的编号。

**关键代码**：
```cpp
void hanoi(int n, int id, char start, char other, char target) {
    if (n == 1) { cout << id << ":" << start << "->" << target << endl; return; }
    hanoi(n - 1, id, start, target, other);          // 上面 n-1 个编号从 id 开始
    cout << id + n - 1 << ":" << start << "->" << target << endl;  // 最大盘编号 = id+n-1
    hanoi(n - 1, id, other, start, target);
}
```

**总结**：盘号追踪——上面 n-1 个盘的最小编号是 `id`，最大盘编号是 `id + n - 1`。

### LinK15 爬天梯

**思路**：爬一个有 N 阶的楼梯，每次可以走 1 阶或 2 阶，问有多少种不同走法。想一下：要到达第 N 阶，最后一步只有两种可能——从第 N-1 阶走 1 步上来，或者从第 N-2 阶走 2 步上来。所以到达第 N 阶的走法数 = 到达第 N-1 阶的走法数 + 到达第 N-2 阶的走法数。显然，这是斐波那契数列，采用**递归**方法解题。注意结果要对 1000000007 取模（防止数字太大溢出）。

**关键代码**：
```cpp
int stairs(int n) {
    if (n <= 1) return 1;
    return (stairs(n - 1) + stairs(n - 2)) % 1000000007;  // 斐波那契，取模防溢出
}
```

**总结**：纯递归 O($2^n$) 易超时，N 大时应改用迭代 DP `for (i=2; i<=N; i++) dp[i] = (dp[i-1] + dp[i-2]) % mod`。取模要在加法之后立即做。

### LinK16 放苹果

**思路**：把 m 个相同的苹果放进 n 个相同的盘子，允许空盘，问有多少种放法。用递归思考：对于每一种放法，要么**至少有一个盘子是空的**（那就等于把 m 个苹果放 n-1 个盘子），要么**所有盘子都不空**（那可以先给每个盘子放 1 个苹果，剩下 m-n 个随便放）。两种情况不重复也不遗漏，加起来就是答案。边界：苹果比盘子少时，多余的盘子直接忽略（因为盘子都一样）。
注意这里分类会比较难懂一些，f(m,n-1)代表的是空一个盘子，

**关键代码**：
```cpp
int f(int m, int n) {
    if (m < n) return f(m, m);          // 苹果比盘子少，多余盘子忽略
    if (m == 0) return 1;               // 没有苹果，全空，1 种方案
    if (n <= 0) return 0;               // 有苹果没盘子，0 种
    return f(m, n - 1) + f(m - n, n);   // 空一盘 + 每盘至少一个
}
```

**总结**：**不重不漏**的关键：将方案按"是否有空盘"二分——`f(m, n-1)` 覆盖有空盘、`f(m-n, n)` 覆盖全不空。

### LinK18 2的幂次方表示

**思路**：把任意正整数 n 用"2 的幂次方的和"的**嵌套形式**来表示——比如 137 = $2^7+2^3+2^0$，但 7 和 3 也要继续展开，7 = $2^2+2^1+2^0$，3 = $2^1+2^0$，最终变成 `2(2(2)+2+2(0))+2(2+2(0))+2(0)`。做法：把 n 的二进制展开，从高位到低位扫描每一位——如果第 i 位是 1，就输出 $2^i$ 这一项。但 i 本身如果不是 0 或 1，就要**递归地把 i 也展开**。递归终止条件：指数为 0 时输出 `2(0)`，指数为 1 时直接输出 `2`。多个项之间用 `+` 连接。

**关键代码**：
```cpp
string dfs(int n) {
    string res;
    for (int i = 14; i >= 0; i--)               // 从高到低扫描二进制位（n≤20000<2^15）
        if (n >> i & 1) {                       // 第 i 位是 1 → 需要 2^i 这一项
            if (res.size()) res += '+';          // 非首项前加 +
            if (!i) res += "2(0)";              // 指数 0 → 2(0)
            else if (i == 1) res += "2";         // 指数 1 → 2（不加括号）
            else res += "2(" + dfs(i) + ")";     // ★ 指数 ≥2 → 递归展开指数
        }
    return res;
}
```

**总结**：递归的核心——问题规则对原数和指数都适用，自然想到用同一个函数递归处理。终止条件 i=0 和 i=1 是递归的 base case。从高位遍历保证输出按指数降序排列。

### LinK19 递归实现指数型枚举

**思路**：从 1~n 这 n 个数中随便选任意多个，列出所有可能的选法。每个数字面临一个选择：选它，还是不选它。这就像一棵二叉树：从数字 1 开始，选（走左分支）或不选（走右分支），到了数字 2 再选或不选……一直到数字 n。每条从根到叶子的路径就是一种选法。总共 n 个数字，每个有 2 种选择，所以一共有 $2^n$ 种方案。

**关键代码**：
```cpp
void dfs(int u) {
    if (u > n) {
        for (int i = 1; i <= n; i++)
            if (st[i]) cout << i << " ";  // 选了才输出
        cout << endl; return;
    }
    st[u] = true;  dfs(u + 1);           // 选 u
    st[u] = false; dfs(u + 1);           // 不选 u
}
```

**总结**：子集枚举三种写法：① DFS 决策树（直观）② 位运算（简洁）③ `next_permutation`（不适用）。输出天然升序因为按 1→n 遍历。

### LinK20 递归实现组合型枚举

**思路**：从 n 个数中选 m 个（比如从 5 个里选 3 个），和"指数型枚举"不同——这次选的数量是固定的。关键问题：{1,3} 和 {3,1} 在组合里是同一种选法，不能输出两次。解决方法是：强制选出来的数字必须从小到大排列——选第 1 个数后，第 2 个数只能从比它大的里面选，第 3 个再从更大的里面选……这样每种组合只会以升序的形式出现一次。用一个 `start` 参数记录"下一个数字至少要从哪开始选"。

**关键代码**：
```cpp
void dfs(int u, int start) {
    if (u > m) {                          // 选满了 m 个
        for (int i = 1; i <= m; i++) cout << path[i] << " ";
        cout << endl; return;
    }
    for (int i = start; i <= n; i++) {    // 从 start 开始，保证升序
        path[u] = i;
        dfs(u + 1, i + 1);                // 下一个从 i+1 开始，杜绝重复
    }
}
```

**总结**：组合 vs 排列的核心区别：组合用 `start` 参数强制升序去重，排列用 `st[]` 布尔数组标记已用元素。

### LinK21 递归实现排列型枚举

**思路**：把 1~n 的所有排列方式都列出来（比如 n=3 有 123、132、213、231、312、321 共 6 种）。和"组合"不同，排列讲究**顺序**——{1,2} 和 {2,1} 是两种不同的排列。做法是：从左到右填每个位置，每次从还没用过的数字里挑一个填进去，填完后**做个标记**表示这个数字已使用。关键一步：递归返回后要把标记清除（"回溯"），否则后面的尝试会少很多数字可以选。

**关键代码**：
```cpp
void dfs(int u) {
    if (u > n) {
        for (int i = 1; i <= n; i++) cout << path[i] << " "; cout << endl; return;
    }
    for (int i = 1; i <= n; i++)
        if (!st[i]) {                     // 只选未使用的数字
            path[u] = i; st[i] = true;
            dfs(u + 1);
            st[i] = false;                // ★ 回溯恢复！忘记会大量漏解
        }
}
```

**总结**：排列的回溯恢复是必须的——不同于组合的 `start` 隐式排除，排列不恢复 `st[i]` 会导致其他分支无法使用该数字。

### LinK27 大数排序（快排）

**思路**：手写快速排序——虽然平时可以调 `sort()`，但理解快排原理很重要。快排的思想：① 挑一个"基准值"（pivot），② 把数组分成两部分——左边全 ≤ 基准值，右边全 ≥ 基准值，③ 对左右两部分分别再快排。分两半的关键操作用两个指针 i 和 j：i 从左往右找"比基准值大的"，j 从右往左找"比基准值小的"，找到了就交换。当 i 和 j 交错时，划分就完成了。

**关键代码**：
```cpp
void quick_sort(int q[], int l, int r) {
    if (l >= r) return;
    int i = l - 1, j = r + 1, x = q[l + r >> 1];  // 中间值为 pivot
    while (i < j) {
        do i++; while (q[i] < x);                   // 找左边 ≥ pivot 的
        do j--; while (q[j] > x);                   // 找右边 ≤ pivot 的
        if (i < j) swap(q[i], q[j]);                // 交换
    }
    quick_sort(q, l, j); quick_sort(q, j + 1, r);  // 递归左右（用 j 分界）
}
```

**总结**：Y 总模板核心——pivot 取 `l+r>>1` 配 `(l,j)(j+1,r)` 递归。取 `l+r+1>>1` 则配 `(l,i-1)(i,r)`。两套不能混用，否则死循环。

### LinK28 快速选择第k个数

**思路**：在无序数组里找第 k 小的数。最笨的办法是先排序再取第 k 个，O(N log N)。但有个更巧妙的办法——**快速选择**（Quick Select），基于快排的 partition 操作：每次把数组分成"左边全 ≤ pivot、右边全 ≥ pivot"的两半，然后判断第 k 小的数在哪一半，**只递归那一半就够了**，另一半直接丢掉不管。就像在一堆试卷里找第 10 名的成绩：随便抽一张当标杆，比它低的放左边、高的放右边，如果左边超过 10 张，第 10 名肯定在左边，右边就不用看了；如果左边不到 10 张，去右边找（排名要扣掉左边的人数）。平均每次砍一半，O(N) 就能找到。

**关键代码**：
```cpp
int quick_select(int q[], int l, int r, int k) {
    if (l >= r) return q[l];                    // 区间缩到 1，就是答案
    int i = l-1, j = r+1, x = q[l+r>>1];
    while (i < j) {                             // partition（同快排）
        do i++; while (q[i] < x);
        do j--; while (q[j] > x);
        if (i < j) swap(q[i], q[j]);
    }
    int sl = j - l + 1;                         // 左半的元素个数
    if (sl >= k) return quick_select(q, l, j, k);      // 第 k 小在左半
    else return quick_select(q, j+1, r, k - sl);        // ★ 在右半，k 要减 sl
}
```

**总结**：快速选择 = 快排的 partition + 只递归一半。平均 O(N)，最坏 O($N^2$)。核心细节：递归右半时 k 要减去左半元素数 `k - sl`。

### LinK30 归并排序

**思路**：手写归并排序——和快排相反，归并是"先递归到底，再合并回来"。想象你把一摞扑克牌不断对半分，直到每摞只有一张牌（天然有序），然后**两两合并**——合并两个有序摞时，每次比较两摞最顶上的牌，把小的那张拿出来放进新摞，直到一摞空。归并是稳定排序（相等元素保持原始顺序），但需要临时数组存合并结果。

**关键代码**：
```cpp
void mergesort(int nums[], int left, int right) {
    if (left >= right) return;
    int mid = left + right >> 1;
    mergesort(nums, left, mid); mergesort(nums, mid + 1, right);
    int k = 0, p = left, q = mid + 1;
    while (p <= mid && q <= right)
        tmp[k++] = nums[p] <= nums[q] ? nums[p++] : nums[q++]; // ≤ 保证稳定
    while (p <= mid) tmp[k++] = nums[p++];      // 左边剩余
    while (q <= right) tmp[k++] = nums[q++];    // 右边剩余
    for (int i = left, k = 0; i <= right; ) nums[i++] = tmp[k++]; // 拷回原数组
}
```

**总结**：快排 vs 归并——快排先分后排（不稳定），归并先递归再合并（稳定，需 O(N) 临时空间）。`<=` 保证了稳定性。

### LinK31 求排列的逆序数

**思路**：逆序对定义为"前面的数 > 后面的数"——即 `i < j` 但 `a[i] > a[j]`。比如数列 `2, 6, 3, 4` 中，(6,3) 和 (6,4) 是逆序对（6 在 3 和 4 前面且比它们大）。求逆序对的总数。暴力双重循环 O(N²) 对 N=100000 会超时（$10^{10}$ 次比较）。

巧妙的方法是在**归并排序的合并过程**中顺带统计。回忆归并排序的合并：把左右两个已经排好序的半段合并成一个有序段。当左半指针 p 指向 `nums[p]`、右半指针 q 指向 `nums[q]`，我们需要决定把谁放进临时数组：

- 如果 `nums[p] <= nums[q]`：把左边的小数放进去，正常操作，没有逆序对产生。
- 如果 `nums[p] > nums[q]`：关键来了！右边的 `nums[q]` 比左边的 `nums[p]` 小。因为左半已经排序，`nums[p]` 后面的数（`nums[p+1]` 到 `nums[mid]`）都比 `nums[p]` 还大，自然也全都大于 `nums[q]`。因此 `nums[q]` 和左半区间 `[p, mid]` 中的**每一个数**都构成逆序对。左半还剩 `mid - p + 1` 个数，这就是新增的逆序对数量！

举个具体例子：左半 `[2, 6, 8]`，右半 `[1, 4, 9]`。p=0 指向 2，q=0 指向 1：
- `2 > 1`（右半更小），1 比左半的 2、6、8 都小（因为 2 是左半最小的，2 已经比 1 大了，6 和 8 当然也大），所以 1 和 {2, 6, 8} 三个数各构成一个逆序对。`res += 3`（即 `mid - p + 1 = 3 - 0 + 1 = ...` wait, mid=2, p=0, so 2-0+1=3）。1 归入 tmp，q++。

这样在 O(N log N) 的排序过程中，所有的"跨区间"逆序对都被统计了。而"同侧内部"的逆序对已经被之前的递归统计过了。`res = 左子区间逆序数 + 右子区间逆序数 + 当前合并时发现的跨区间逆序数`，三部分不重不漏。

注意返回值用 `long long`：n=100000 的降序排列有约 $5\times 10^9$ 个逆序对，超过 int 范围（约 $2.1\times 10^9$）。

**关键代码**：
```cpp
long long mergesort(int nums[], int left, int right) {
    if (left >= right) return 0;       // 区间长度为 0，没有逆序对
    int mid = left + right >> 1;
    // 先递归统计左右子区间内部的逆序对
    long long res = mergesort(nums, left, mid) + mergesort(nums, mid + 1, right);
    
    // 合并过程同时统计跨区间的逆序对
    int k = 0, p = left, q = mid + 1;
    while (p <= mid && q <= right) {
        if (nums[p] <= nums[q])
            tmp[k++] = nums[p++];       // 正常归并，不产生逆序对
        else {
            res += mid - p + 1;         // ★ nums[q] 和左半 [p..mid] 全部构成逆序对
            tmp[k++] = nums[q++];
        }
    }
    while (p <= mid) tmp[k++] = nums[p++];   // 左边剩余（已在 while 中比较完）
    while (q <= right) tmp[k++] = nums[q++]; // 右边剩余
    for (int i = left, k = 0; i <= right; ) nums[i++] = tmp[k++]; // 拷回原数组
    return res;
}
```

**总结**：归并求逆序对的精髓——当 `nums[p] > nums[q]` 时，`nums[q]` 和 `[p, mid]` 全部构成逆序对（因为左半已排序）。`res` 由三部分组成：左子区间 + 右子区间 + 当前跨区间。返回类型用 `long long`。

### LinK13 输出N皇后的全部摆法

**思路**：在国际象棋棋盘上放 N 个皇后，让它们互相吃不到对方（同行、同列、同斜线都不行）。用 DFS 一行一行地放：在第 0 行试每一列，放好后跳到第 1 行，再试每一列（但要避开已被"攻击"的位置）……如果某行所有列都不行，说明前面放错了，退回去换一列重试。判断两个格子是否在同一对角线有个巧妙的公式：两个格子的**行号差 = 列号差**（绝对值相等），说明它们在斜线上。

**关键代码**：
```cpp
void dfs(int row) {
    if (row == N) {
        for (auto x : res) cout << x; cout << endl; return;
    }
    for (int col = 1; col <= N; col++) {
        int k;
        for (k = 0; k < row; k++)
            if (res[k] == col || abs(res[k] - col) == abs(k - row)) break; // 同列或同对角线
        if (k == row) { res[row] = col; dfs(row + 1); }  // 无冲突，递归下一行
    }
}
```

**总结**：对角线判断 `abs(col1-col2) == abs(row1-row2)` 覆盖主副对角线。N≤13 时 O(n) 遍历冲突检查足够，更大时需布尔数组 O(1) 优化。

### LinK14 求八皇后的第n种解

**思路**：8 皇后问题固定只有 92 组解。既然有多个查询（问第 1 个解、第 92 个解……），最省事的办法：**在程序一开始就把 92 组解全部算出来，存进数组**（这叫"打表"）。之后每次查询直接根据编号从数组里取出答案，不用重新算。因为 DFS 从左到右从小到大试列号，先找到的解自然是字典序（数字串从小到大）的，正好符合题目要求。

**关键代码**：
```cpp
void dfs(int row) {
    if (row > 7) {
        for (int k = 0; k < 8; k++) res[count][k] = path[k];  // 存解
        count++; return;
    }
    for (int col = 1; col <= 8; col++) {
        // ... 冲突检测 ...
        path[row] = col; dfs(row + 1);
    }
}
// 查询: for (int i = 0; i < 8; i++) cout << res[n - 1][i];  // n 从 1 开始，下标 -1
```

**总结**：打表法——答案数量固定（92 个）时，一次性生成全部解，查询 O(1)。DFS 从 1→8 列枚举天然按字典序生成。

### LinK14.5 DFS试炼之n皇后问题

**思路**：和 LinK13 一样的 N 皇后，但输出变成棋盘图案（`Q` 表示皇后、`.` 表示空格），并且冲突检测从 O(N) 优化到 O(1)——用三个布尔数组代替循环检查。

首先回顾一下皇后互相攻击的条件：同行、同列、同对角线（主对角线 `\` 和副对角线 `/`）。因为我们是一行一行放的，同行自然不会有冲突，只需要检查列和两条对角线。

三个布尔数组的含义：
- `col[i]`：第 i 列有没有被占。
- `dg[k]`：第 k 条"主对角线"（`\` 方向，从左上到右下）有没有被占。
- `udg[k]`：第 k 条"副对角线"（`/` 方向，从右上到左下）有没有被占。

接下来是最关键的——如何给对角线编号？观察棋盘上同一条主对角线 `\` 上的所有格子，它们的**行号 + 列号**是一个定值！比如 (0,2)、(1,1)、(2,0) 这三个格子在一条 `\` 线上，行+列都等于 2。所以 `dg[u + i]` 就能标记"第 u 行、第 i 列的皇后所在的主对角线"。

同理，同一条副对角线 `/` 上的格子，**行号 - 列号**是一个定值。比如 (1,0) 和 (2,1) 在一条 `/` 线上，行-列都等于 1。但行号减列号可能出现负数（比如 (0,2)→ -2），数组下标不能是负数。解决办法是加一个偏移量 n，用 `n - u + i`（等价于 `u - i + n-1`）作为编号，保证结果非负。这两种写法都可以，只要保证索引落在 [0, 2n] 范围内。

**关键代码**：
```cpp
const int N = 20;  // n ≤ 12, 对角线最多 2n 条, N=20 够用
int n;
char g[N][N];           // 棋盘
bool col[N], dg[N], udg[N];  // 列、主对角线、副对角线占用标记

void dfs(int u) {        // u = 当前行号（0 ~ n-1）
    if (u == n) {        // n 行全部放完，输出棋盘
        for (int i = 0; i < n; i++) puts(g[i]);
        puts("");        // 方案间空行分隔
        return;
    }
    for (int i = 0; i < n; i++)     // 尝试每一列
        if (!col[i] && !dg[u + i] && !udg[n - u + i]) {
            g[u][i] = 'Q';
            col[i] = dg[u + i] = udg[n - u + i] = true;   // 标记占用
            dfs(u + 1);
            col[i] = dg[u + i] = udg[n - u + i] = false;  // ★ 回溯，恢复标记
            g[u][i] = '.';                                 // 恢复棋盘
        }
}
```

**总结**：主对角线用 `u+i` 编号（因为在这条线上行+列为定值），副对角线用 `n-u+i` 编号（偏移防止负数）。三个布尔数组将冲突检测从 O(N) 降到 O(1)，这是 N 皇后的最优写法。回溯时三个数组和棋盘格子都要恢复。

### LinK38 林克的命运之阵

**思路**：在一个无限大的方格矩阵中，从任意位置出发，每次只能向下、向左、向右三个方向走（不能向上，相当于时间不能倒流），且**不能重复访问**已经走过的格子。问走 n 步有多少种不同的路径？n ≤ 20。

这道题是**自回避行走**（Self-Avoiding Walk）的计数问题。用 DFS 回溯来枚举所有路径：

1. 从中心位置出发（因为 n ≤ 20，往左右各预留足够空间）。
2. 走到一个新格子时，把它标记为"已访问"（`fates[i][j] = 1`），防止走回头路。
3. 在当前格子尝试三个方向（下、左、右）。如果某个方向的目标格子未被访问（`fates[x][y] == 0`），就递归走过去。
4. 用 `res += dfs(x, y, n-1)` 累加所有子路径的计数。
5. 递归返回后，**一定要把标记擦掉**（`fates[i][j] = 0`），因为换一条路走时这个格子可能需要再次经过。

这里有一个初学者容易混淆的点：为什么有些 DFS 需要回溯恢复标记（像本题），有些不需要（像 Flood Fill）？

- **需要回溯的**（本题、N 皇后）：你要找的是**所有可能的路径/方案**。一条路走完之后，要回去试另一种走法，已占用的格子必须释放，否则另一种走法会受到限制。
- **不需要回溯的**（Flood Fill）：你只想统计**一共去过多少格**。每格访问一次就够了，不需要释放（反而释放了会重复计数）。

虽然每步最多有 3 个方向可选，理论搜索空间是 $3^n$（n=20 时约 $3.5\times 10^9$），但实际上大量路径因为不能走回头路而被剪掉，n=20 的实际答案只有约 $5.4\times 10^7$ 条路径，在 DFS 可接受的范围内。用 `long long` 类型存储结果防止溢出。

**关键代码**：
```cpp
const int N = 70;               // 给左右各留 35 列缓冲，n ≤ 20
int fates[N][N];                // 0=未访问, 1=已访问
int dx[3] = {0, 0, 1};          // 左、右、下
int dy[3] = {-1, 1, 0};

long long dfs(int i, int j, int n) {
    if (n == 0) return 1;       // 走了 0 步，当前路径算一种方案
    long long res = 0;
    fates[i][j] = 1;            // ★ 标记：进入格子
    for (int k = 0; k < 3; k++) {
        int x = i + dx[k], y = j + dy[k];
        if (fates[x][y] == 0)   // 只走未访问的格子
            res += dfs(x, y, n - 1);
    }
    fates[i][j] = 0;            // ★ 回溯：离开格子时必须恢复
    return res;
}

int main() {
    int n; cin >> n;
    cout << dfs(0, N / 2, n) << endl;  // 从中心列出发
}
```

**总结**：求**所有路径数**时必须回溯恢复标记（释放格子让其他路径使用）。和 Flood Fill 的区别：一个是"有多少种走法"，一个是"去过多少格"。结果用 `long long`。

### LinK39 净化迷雾森林（DFS）

**思路**：地图上有空地（`.`）、墙（`#`）和起点（`@`），问从起点出发能走到多少块空地。这就是"洪水填充"问题——想象从起点倒水，水往四个方向流，遇到墙就停，最后看湿了多少块地。用 DFS 实现：从起点开始，每走到一块新空地就计数 +1 并把它改成墙（相当于标记"已走过"），然后往四个方向继续走。注意这里标记后**不需要恢复**，因为每块地只要数一次。

**关键代码**：
```cpp
int dfs(int i, int j) {
    int res = 1;
    fogforest[i][j] = '#';                   // 标记为已访问（不恢复！这是连通块统计）
    for (int k = 0; k < 4; k++) {
        int x = i + dx[k], y = j + dy[k];
        if (x>=0 && y>=0 && x<h && y<w && fogforest[x][y] == '.')
            res += dfs(x, y);
    }
    return res;
}
```

**总结**：Flood Fill 不需要回溯（与 LinK38 求路径数不同）——统计"去过多少格"，标记后不再使用。DFS 递归深度 ≤ W×H ≤ 400。

### LinK40 骑士林克的怜悯(1)

**思路**：在国际象棋里，骑士走"日"字（8 个方向）。现在棋盘大小可变（p×q ≤ 26），问骑士能不能从某个格子出发、每个格子恰好踩一次、遍历整个棋盘？这就是著名的"骑士巡游"（Knight's Tour）问题。用 DFS 回溯：从一个起点开始，每到一个新格子就标记已访问，然后按字典序尝试 8 个马步方向，跳到下一个未访问的格子……如果某步走不通（后续无法走完全部格子），就回溯换一个方向。因为要求输出**字典序最小**的路径，方向数组已经按字典序排好（优先尝试字母靠前的跳法），DFS 找到的第一条路径就是字典序最小的。枚举所有格子作为起点，某个起点能找到就输出。

**关键代码**：
```cpp
int dx[8]={-2,-2,-1,-1,1,1,2,2};  // 字典序方向：优先小字母
int dy[8]={-1,1,-2,2,-2,2,-1,1};

bool dfs(int x, int y, int cnt) {
    path.push_back({char(x+'A'), y+1});         // 列→字母，行→数字
    if (cnt == p * q) { /* 输出路径 */ return true; }
    st[x][y] = true;
    for (int i = 0; i < 8; i++) {
        int a = x+dx[i], b = y+dy[i];
        if (a<0||a>=q||b<0||b>=p||st[a][b]) continue;
        if (dfs(a, b, cnt+1)) return true;      // 找到就沿路返回
    }
    st[x][y] = false; path.pop_back();          // 回溯
    return false;
}
```

**总结**：骑士巡游是哈密尔顿路径的特例。要求字典序最小时，方向数组的顺序决定搜索优先级，首次找到的解即为答案。p×q 较小时某些棋盘无解（如 5×1），输出 none。

### LinK51 净化迷雾森林（BFS）

**思路**：和 LinK39 一模一样的题，但改用 BFS（广度优先搜索）。DFS 是用递归（一层层深入），BFS 是用队列（一层层扩展）。区别在于遍历顺序：DFS 像走迷宫一条路走到黑，BFS 像水波纹一圈圈往外扩散。关键技巧——**在把格子加入队列之前就标记为已访问**，否则同一格子可能被多个相邻格同时发现、重复入队，导致队列爆炸。

**关键代码**：
```cpp
int bfs(int sx, int sy) {
    queue<PII> q; q.push({sx, sy}); g[sx][sy] = '#';
    int res = 0;
    while (q.size()) {
        auto t = q.front(); q.pop(); res++;
        for (int i = 0; i < 4; i++) {
            int x = t.first + dx[i], y = t.second + dy[i];
            if (x<0||x>=n||y<0||y>=m||g[x][y]!='.') continue;
            g[x][y] = '#'; q.push({x, y});   // ★ 入队前标记，防重复入队
        }
    }
    return res;
}
```

**总结**：BFS 关键技巧——**入队时立即标记**已访问（而非出队时），防止同一节点被重复入队导致队列膨胀。

### LinK52 波克布林的巡逻范围

**思路**：机器人从 (0,0) 出发，有些格子不能去——如果格子的行号和列号的"各位数字之和"太大，就不能进入。比如 k=18 时，(35,37) 的数位和 = (3+5)+(3+7)=18，刚好能进。用 BFS 从起点开始探索：每出队一个格子，先判断它能不能进（数位和 ≤ k 且没去过），能进就计数 +1 然后往四个方向扩展。这题和"机器人的运动范围"是同一道经典题。

**关键代码**：
```cpp
int getSum(int x) { int s = 0; while (x) s += x % 10, x /= 10; return s; }

// BFS 中:
auto t = q.front(); q.pop();
if (st[t.first][t.second] || getSum(t.first)+getSum(t.second) > k) continue; // 出队检查
res++; st[t.first][t.second] = true;
for (int i = 0; i < 4; i++) { /* 四方向扩展 */ }
```

**总结**：数位和问题——用 `while(x) s+=x%10, x/=10` 计算。坐标从 (0,0) 开始，(35,37) 的数位和 = 3+5+3+7=18。

### LinK53 加农的入侵

**思路**：污染从起点开始向 8 个方向扩散（上下左右 + 四个对角），遇到障碍物（`*`）就停。问多少天后所有能污染的地方都被污染。这本质上是 BFS 求**最远距离**——每扩散一步等于过一天，所以最远格子的距离就是所需天数。注意题目坐标系原点在左下角，代码数组原点在左上角，需要转换：`新行号 = 总行数 + 1 - 原行号`。

**关键代码**：
```cpp
int bfs() {
    memset(dist, -1, sizeof(dist));
    queue<PII> q; q.push(start); dist[start.first][start.second] = 0;
    int res = 0;
    while (q.size()) {
        auto t = q.front(); q.pop();
        for (int i = 0; i < 8; i++) {             // 8 方向
            int x = t.first + dx[i], y = t.second + dy[i];
            if (x<1||x>n||y<1||y>m||g[x][y]=='*'||dist[x][y]!=-1) continue;
            dist[x][y] = dist[t.first][t.second] + 1;
            res = max(res, dist[x][y]);            // 最大步数 = 所需天数
            q.push({x, y});
        }
    }
    return res;
}
```

**总结**：坐标系转换——题目 (Mx, My) 中 My 是从下往上数，需 `n+1-My` 转为数组下标。8 方向 BFS 需 8 个偏移量。

### LinK54 骑士林克的怜悯(2)

**思路**：棋盘上有一个骑士（K）和一个守护者（H），骑士按"日"字跳（8 个马步方向），有些格子有障碍（`*`）不能走。问骑士最少跳多少步能到达守护者？每条边的代价都是 1，最短路直接用 BFS 天然解决——BFS 按层次扩展的性质保证了第一次到达终点时的步数就是最短步数。从 K 出发，每步往 8 个马步方向试探，合法（不出界、不撞障碍、未访问）的就入队。一旦某个方向的坐标恰好是 H，立即返回当前距离+1，不用继续等了。

**关键代码**：
```cpp
int dx[]={-2,-1,1,2,2,1,-1,-2};  // 8 个马步方向
int dy[]={1,2,2,1,-1,-2,-2,-1};

int bfs(PII start, PII end) {
    memset(dist, -1, sizeof dist);
    dist[start.first][start.second] = 0;
    queue<PII> q; q.push(start);
    while (q.size()) {
        auto t = q.front(); q.pop();
        for (int i = 0; i < 8; i++) {
            int x = t.first+dx[i], y = t.second+dy[i];
            if (x<0||x>=n||y<0||y>=m||g[x][y]=='*'||dist[x][y]!=-1) continue;
            dist[x][y] = dist[t.first][t.second] + 1;
            if (make_pair(x, y) == end) return dist[x][y];  // ★ 找到立即返回
            q.push({x, y});
        }
    }
    return -1;
}
```

**总结**：BFS 是无权图最短路径的标准解法——每条边代价相同（都是 1 步），第一次到达 = 最短距离，可提前返回。马步方向数组与 LinK40（骑士巡游 DFS）完全相同，但算法目标不同：一个求遍历全盘路径（DFS），一个求两点最短（BFS）。

### LinK57 Dijkstra求最短路(1)

**思路**：有 n 个点 m 条边的有向图，边权非负，求 1 号点到 n 号点的最短距离。这是单源最短路径的经典问题，Dijkstra 算法用贪心策略逐步确定所有点的最短距离。

算法流程（n 个点，朴素 O($N^2$) 实现）：
1. **初始化**：`dist[1] = 0`（源点到自身距离为 0），其余点距离设为无穷大 INF。用 `st[i]` 标记第 i 个点的最短距离是否已确定。
2. **主循环 n-1 次**（因为源点已初始确定）：
   - **选点**：在所有 `st[j] == false`（尚未确定）的点中，找到 `dist` 值最小的点 t。这个 t 就是"下一个可以确定最短距离的点"——因为所有边权非负，从其他尚未确定的点绕路到 t 的距离不可能比 `dist[t]` 更短。
   - **松弛（Relaxation）**：用 t 作为中转，更新 t 所有邻居的距离。对于每条从 t 出发的边 t→j，如果 `dist[t] + g[t][j] < dist[j]`（经 t 到 j 比当前记录的更短），就更新 `dist[j] = dist[t] + g[t][j]`。
   - **标记**：`st[t] = true`，t 的最短距离正式确定，后续不再参与选点。
3. **结果**：`dist[n]` 就是 1 到 n 的最短距离。如果 `dist[n] == INF` 说明不可达。

举个例子：n=3，边：1→2(2), 2→3(1), 1→3(4)。
- 初始：dist = [INF, 0, INF, INF]（下标从 1 开始），st = [F, F, F, F]
- 第 1 轮：选 dist[1]=0 最小的点 t=1，用 1 的边松弛 → dist[2]=2, dist[3]=4，st[1]=T。
- 第 2 轮：未确定点中 dist[2]=2 最小，选 t=2。用 2 的边松弛 → dist[3]=min(4, 2+1)=3（发现更短路径！），st[2]=T。
- 结束：dist[3]=3，即最短距离。

本题使用邻接矩阵 `g[N][N]`，适合 n ≤ 500 的稠密图。对于稀疏图（n 大 m 小），需要改用邻接表 + 堆优化（见 LinK58）。

**关键代码**：
```cpp
const int N = 510;
int n, m;
int g[N][N];     // 邻接矩阵，g[a][b] = a→b 的边权
int dist[N];     // dist[i] = 1号点到 i 的最短距离
bool st[N];      // st[i] = i 的最短距离是否已确定

int dijkstra() {
    memset(dist, 0x3f, sizeof(dist));  // 初始化为 INF
    dist[1] = 0;                       // 源点距离 = 0

    for (int i = 0; i < n - 1; i++) {  // 需要确定 n-1 个点的距离
        // ① 选最小 dist 的未确定点
        int t = -1;
        for (int j = 1; j <= n; j++)
            if (!st[j] && (t == -1 || dist[t] > dist[j]))
                t = j;

        // ② 用 t 松弛所有邻居
        for (int j = 1; j <= n; j++)
            dist[j] = min(dist[j], dist[t] + g[t][j]);

        // ③ 标记 t 为已确定
        st[t] = true;
    }
    return dist[n] == 0x3f3f3f3f ? -1 : dist[n];
}
```

**总结**：Dijkstra 的贪心正确性依赖"边权非负"——如果有负权边，需要改用 Bellman-Ford 或 SPFA。邻接矩阵 O($N^2$) 适合稠密图（N ≤ 500）。`memset(0x3f)` 设置的 INF 值 ≈ $1.06\times 10^9$，两个 INF 相加不溢出 int。重边处理：`g[a][b] = min(g[a][b], c)` 保留最短那条。

### LinK58 Dijkstra求最短路(2)（堆优化）

**思路**：和 Dijkstra(1) 完全一样的题，但 n 从 500 暴增到 15 万。$O(N^2)$ 的朴素做法再也跑不动了，得换一个更快的办法。核心瓶颈在"每次从还没确定的点里找距离最小的那个"——朴素做法每次要 O(N) 扫描全部点，这里改用**小根堆（优先队列）**：把每个新更新的距离 {dist, 顶点号} 扔进堆里，每次直接取堆顶就是最小的。另一个变化是图改用**邻接表**存储（链式前向星），否则 150000×150000 的邻接矩阵内存直接爆炸。

**关键代码**：
```cpp
int dijkstra() {
    memset(dist, 0x3f, sizeof dist); dist[1] = 0;
    priority_queue<PII, vector<PII>, greater<PII>> heap; // 小根堆
    heap.push({0, 1});
    while (heap.size()) {
        auto t = heap.top(); heap.pop();
        int ver = t.second, distance = t.first;
        if (st[ver]) continue;                  // ★ 旧记录跳过
        st[ver] = true;
        for (int i = h[ver]; i != -1; i = ne[i]) {  // 遍历邻接表
            int j = e[i];
            if (dist[j] > dist[ver] + w[i]) {
                dist[j] = dist[ver] + w[i];
                heap.push({dist[j], j});
            }
        }
    }
    return dist[n] == 0x3f3f3f3f ? -1 : dist[n];
}
```

**总结**：堆优化将"找最小 dist"从 O(N) 降到 O(log N)，总复杂度 O(M log N)。邻接表（`h/e/ne/w` 链式前向星）是稀疏图标配。同一个点可能被多次入堆，出队时 `if(st[ver]) continue` 跳过旧记录即可。

### LinK60 突袭路线

**思路**：有 n 个敌人和 m 条"谁盯着谁"的关系（有向边），要找一条逐个击破的路线——如果 A 盯着 B，就得先干掉 A 才能动 B。翻译成图论：给一个有向图，求一个**拓扑序列**（对于每条边 x→y，x 必须排在 y 前面）。拓扑排序存在的条件是图里没有环。算法（Kahn 算法）：① 统计每个点的入度（几个人盯着它），② 把入度为 0 的点（没人盯的）全部入队，③ 出队一个点，把它的所有出边删掉（邻居入度减 1），如果邻居入度变 0 就入队，④ 循环直到队列为空。如果处理过的点数等于 n，说明找到了完整序列；否则图里有环，输出 -1。

**关键代码**：
```cpp
bool topsort() {
    int hh = 0, tt = -1;
    for (int i = 1; i <= n; i++)
        if (!d[i]) q[++tt] = i;                 // 入度为 0 入队
    while (hh <= tt) {
        int t = q[hh++];                         // 出队即加入拓扑序列
        for (int i = head[t]; i != -1; i = nextVertex[i]) {
            int j = edge[i];
            if (--d[j] == 0) q[++tt] = j;        // 删边 + 入度变 0 则入队
        }
    }
    return tt == n - 1;                          // 是否处理了全部 n 个点
}
```

**总结**：拓扑排序 = BFS + 入度管理。关键判断：处理点数 == n 则成功，< n 则有环。$O(N+M)$ 时间，用数组模拟队列比 `queue<int>` 更高效且结果直接就是拓扑序列。

### LinK43 求二进制中1的个数

**思路**：统计一个整数的二进制形式里有多少个 1（比如 9 的二进制是 1001，有 2 个 1）。有一个神奇的位运算叫 `lowbit`：`n & -n` 可以提取出 n 的二进制最低位那个 1 所代表的数值（比如 12 是 1100，lowbit=4，即第三位的那个 1）。每次提取一个 1 然后减去它，直到 n 变成 0，循环了几次就有几个 1。比逐位检查快，特别是 1 比较少的时候。

**关键代码**：
```cpp
int lowbit(int n) { return n & -n; }   // 提取最低位 1，如 12(1100) → 4(0100)

int NumberOf1(int n) {
    int res = 0;
    while (n) { n -= lowbit(n); res++; }  // 每次消去最低位 1
    return res;
}
```

**总结**：lowbit 原理——`n & -n` 在补码下提取最低位 1。对于稀疏的 1（如只有几个位为 1），这比移位法（固定 32 次）更高效。

### LinK44 二进制中1的最低位位置

**思路**：找一个 16 位整数的二进制最低位 1 在第几位（从 0 开始数）。比如 9 的二进制是 1001，最低位 1 在第 0 位。分两步：① 用 `lowbit(n)` 提取最低位 1 的权值（比如 8 = 2³），② 查表得到这个权值对应的是 2 的几次方（也就是第几位）。打表就是提前算好 `log[1]=0, log[2]=1, log[4]=2, …`，查的时候 O(1) 直接出结果。

**关键代码**：
```cpp
void BuildLogTable(int n) {
    for (int i = 0; i < n; i++) log[1 << i] = i;  // log[1]=0, log[2]=1, log[4]=2...
}
inline int lowbit(int n) { return n & -n; }

// 查询:
int n; cin >> n;
cout << log[lowbit(n)];  // lowbit 提取权值 → log 查表得位置
```

**总结**：打表法——结果范围有限（16 位，$2^{17}$=131072）时预计算所有可能答案，O(1) 查询。`inline` 对单表达式函数是好习惯。

### LinK45 真假记忆碎片

**思路**：给你一张已经填满的数独，判断它是不是正确的解。检查三件事：① 拼图有没有改动过初始给出的数字（题目给的非零数字不能变）；② 每行是不是 1~9 各出现一次；③ 每列是不是 1~9 各出现一次；④ 每个 3×3 小九宫格是不是 1~9 各出现一次。用布尔数组标记每个数字是否出现过，一重复就判错。这题是后面三道数独求解的热身。

```cpp
bool check_row() {
    for (int i = 0; i < 9; i++) {

            if (st[t]) return false;     // 重复出现

}
// check_col 同理；check_block 枚举 9 个 3×3 块左上角
```

**总结**：数独验证的四步：输入合法性 → 行唯一 → 列唯一 → 块唯一。检查前需 `memset(st, false)`。

### LinK46 寻找林克的回忆(1)

**思路**：求解一个 9×9 标准数独。输入是 9 行字符串，`0` 表示空格需要填。用 DFS 一个格子一个格子地填数字，找到任意一组可行解即可。

数独的规则三条：每行 1~9 不重复、每列 1~9 不重复、每个 3×3 小九宫格 1~9 不重复。DFS 过程中每次填一个数字都要快速检查它是否和已填的数字冲突。检查方法——维护三个布尔数组：
- `st_row[x][t]`：第 x 行是否已经用了数字 t（t ∈ 1~9）
- `st_col[y][t]`：第 y 列是否已经用了数字 t
- `st_block[bx][by][t]`：第 (bx, by) 个 3×3 块是否已经用了数字 t。格子 (x,y) 属于哪个块？`bx = x/3`（整数除），`by = y/3`。

这三个数组在**放置一个数字时全部设为 true**，**回溯撤销时全部恢复为 false**，保证 O(1) 判冲突。

DFS 的递进顺序：按坐标 (x, y) 从左到右、从上到下。`y == 9` 时换行（`x++, y=0`），`x == 9` 时说明所有 81 格填完，输出并返回 true。遇到已填数字（g[x][y] != 0）直接跳过递归下一个。因为是"找任意一组解"，一旦 `dfs` 返回 true 就沿路 return true，不继续尝试其他可能。

初始化：读入时如果格子的数值非 0，就立即把三个约束数组对应位置标为 true，这样初始数字在后续 DFS 中不会被覆盖。

**关键代码**：
```cpp
const int N = 9;
int g[N][N];
bool st_row[N][N+1], st_col[N][N+1], st_block[3][3][N+1];

bool dfs(int x, int y) {
    if (y == 9) x++, y = 0;                  // 换行
    if (x == 9) {                            // 全部填完，输出解
        for (int i = 0; i < 9; i++) {
            for (int j = 0; j < 9; j++) cout << g[i][j];
            cout << endl;
        }
        return true;                         // 找到解，停止搜索
    }
    if (g[x][y] != 0) return dfs(x, y + 1);  // 已有数字，跳过

    for (int t = 1; t <= 9; t++)             // 尝试 1~9
        if (!st_row[x][t] && !st_col[y][t] && !st_block[x/3][y/3][t]) {
            // 放置
            st_row[x][t] = st_col[y][t] = st_block[x/3][y/3][t] = true;
            g[x][y] = t;
            if (dfs(x, y + 1)) return true;  // 沿路返回
            // 回溯
            g[x][y] = 0;
            st_row[x][t] = st_col[y][t] = st_block[x/3][y/3][t] = false;
        }
    return false;                            // 1~9 全失败，回溯
}
```

**总结**：三数组 O(1) 判冲突是标准数独 DFS 的核心。`st_block[x/3][y/3][t]` 自动把格子映射到正确的小九宫格。找到第一组解就沿路 return true 停止——和靶形数独（必须搜全解）形成对比。

### LinK47 寻找林克的回忆(2)

**思路**：和上一题同样解数独，但有两项重大升级：① 用**位运算**替代布尔数组来存储"哪些数字还可以用"，② 用 **MRV 启发式**（最少剩余值）来大幅加速搜索。输入是 81 字符的长串（`.` 表示空），多组数据直到 "end"。

**位运算状态存储**：每行/每列/每个 3×3 块用一个 9 位二进制数（实际是 int 的低 9 位）表示"哪些数字还能用"——第 t 位（t 从 0 到 8）为 1 表示数字 t+1 还没被占用，为 0 表示已被占用。

- 初始化时所有位都是 1（`111111111₂ = (1<<9)-1 = 511`），表示 1~9 全部可用。
- 放置数字 t 时：`row[x] -= 1<<t`（把第 t 位从 1 变成 0）。
- 撤销时：`row[x] += 1<<t`（把第 t 位从 0 变回 1）。
- 查询格子 (x,y) 能填哪些数字：`get(x, y) = row[x] & col[y] & block[x/3][y/3]`，三者的位与运算正好是"三个约束都允许的数字集合"。
- 遍历这个候选集合中的所有数字：`for (int i = get(x, y); i; i -= lowbit(i))`——每次用 `lowbit(i)` 提取最低位的 1，用完后把它减掉（清零），直到集合为空。这是在 bitmask 中枚举所有 1 位的经典写法。

**MRV 启发式**：标准数独的 DFS 如果按固定顺序填格子，可能要试到十万量级的节点。但如果每次优先填"候选数字最少的那个空格"——比如另一个格子从 6 个数里选、这个格子从 2 个数里选，先填 2 个的，搜索树的分支会少很多。这就是 CSP（约束满足问题）中最有效的优化之一：Minimum Remaining Values。实现：每一层 DFS 都扫描全部空格，用 `ones[get(i,j)]`（预计算好的"mask 中有多少个 1"的表）找出候选数最少的格子 (x,y)，然后只枚举 (x,y) 的候选数字。

**辅助表预计算**：
- `ones[mask]`：mask 中有几个 1（即候选数字个数）。对 0~511 每个值预处理，O(1) 查。
- `log[1<<i] = i`：知道某个 bit（如 `8 = 1000₂`）对应数字几（`log[8] = 3` → 数字 4）。

**关键代码**：
```cpp
const int N = 9;
int ones[1 << N], log[1 << N];   // 预计算表
int row[N], col[N], block[3][3]; // 位掩码：每行/列/块的可用数字
string str;                       // 81 字符的输入

inline int lowbit(int x) { return x & -x; }
inline int get(int x, int y) { return row[x] & col[y] & block[x/3][y/3]; }

void init() {
    for (int i = 0; i < N; i++) row[i] = col[i] = (1 << N) - 1; // 全 1 = 全部可用
    for (int i = 0; i < 3; i++)
        for (int j = 0; j < 3; j++) block[i][j] = (1 << N) - 1;
}

bool dfs(int cnt) {          // cnt = 还剩几个空格
    if (!cnt) return true;   // 全部填完

    // ★ MRV: 找候选最少的空格
    int minv = 10, x, y;
    for (int i = 0; i < N; i++)
        for (int j = 0; j < N; j++)
            if (str[i * 9 + j] == '.') {
                int t = ones[get(i, j)];       // 候选数 = mask 中 1 的个数
                if (t < minv) { minv = t; x = i; y = j; }
            }

    // 枚举该格子的所有候选数字
    for (int i = get(x, y); i; i -= lowbit(i)) {
        int t = log[lowbit(i)];               // lowbit 权值 → 位号
        row[x] -= 1 << t;                      // 放置：清零第 t 位
        col[y] -= 1 << t;
        block[x/3][y/3] -= 1 << t;
        str[x * 9 + y] = '1' + t;             // 0→'1', 1→'2', ...
        if (dfs(cnt - 1)) return true;
        row[x] += 1 << t;                      // 撤销：恢复第 t 位
        col[y] += 1 << t;
        block[x/3][y/3] += 1 << t;
        str[x * 9 + y] = '.';
    }
    return false;
}
```

**总结**：位掩码 + MRV 是数独求解的工业级写法。位与 `&` 自动求候选集交集，`lowbit` 逐位枚举候选数字。MRV 每次选候选数最少的空格，搜索树规模缩小数个数量级（标准数独通常 < 1000 次递归）。

### LinK48 寻找林克的回忆(3)

**思路**：靶形数独除了标准规则外，每个格子还有一个分值——越靠近中心分越高（最外圈 6 分，最内圈 10 分）。要求总分最高（填入数字 × 格子分值）的解。和之前数独最大的区别：**不能找到一组解就停**，必须把**所有解都搜完**才能确定哪个分数最高。无解时输出 -1。代码中用 `draw(x, y, -t)` 的负数技巧来撤销放置，放置和撤销共用同一个函数很优雅。

**关键代码**：
```cpp
int getScore(int x, int y, int t) {
    return (min(min(x, 8-x), min(y, 8-y)) + 6) * t;  // 离中心越近分越高
}

void dfs(int cnt, int score) {
    if (!cnt) { ans = max(ans, score); return; }       // 找所有解，取最大分
    // ... MRV 选格 ...
    for (int i = get(x, y); i; i -= lowbit(i)) {
        int t = log[lowbit(i)] + 1;
        draw(x, y, t);
        dfs(cnt - 1, score + getScore(x, y, t));       // 累加分数
        draw(x, y, -t);                                 // 负号 = 撤销
    }
}
```

**总结**：`draw(x, y, -t)` 用负数标记撤销的设计很巧妙，统一了放置和撤销逻辑。`ans = -1` 初始以区分无解情况。

### LinK62 数字三角形

**思路**：动态规划的第一道入门题。从三角形底部往上推：站在倒数第二行的某个数字上，往下走只有两种选择——正下方或右下方。哪个更大就走哪个，把这个数字加到当前位置。这样一行行往上累加，到最顶层时，那个数字就是从顶部到底部所有路径中的最大和。代码里直接原地修改原数组，不需要额外空间——`f[i][j] += max(f[i+1][j], f[i+1][j+1])`。

**关键代码**：
```cpp
for (int i = n - 1; i; i--)                   // 从倒数第二行往上
    for (int j = 1; j <= i; j++)
        f[i][j] += max(f[i + 1][j], f[i + 1][j + 1]); // 正下 vs 右下
cout << f[1][1] << endl;                       // 答案在顶部
```

**总结**：DP 两个方向——自顶向下（答案在最后一行）vs 自底向上（答案集中在起点）。自底向上可以原地修改数组。

### LinK69 摘花生

**思路**：和数字三角形几乎一样的思路，只是形状从三角形变成了矩形。从左上角走到右下角，每一步只能往右或往下，走到每个格子时把上方和左方的最大值加上当前格子的花生数。和数字三角形的区别是方向——一个从底往上推，一个从左往右、从上往下推，本质都是"到达当前位置的最优值 = 来自上方或左方的较优值 + 当前值"。

**关键代码**：
```cpp
for (int i = 1; i <= n; i++)
    for (int j = 1; j <= m; j++)
        f[i][j] = max(f[i - 1][j], f[i][j - 1]) + w[i][j];  // 上方 vs 左方
cout << f[n][m] << endl;
```

**总结**：求**最大值**时全局数组默认 0 恰好适用——第一行/列边界 `f[0][j]=f[i][0]=0` 天然正确。多组数据不必清空 f（会被覆写）。

### LinK70 最低通行费

**思路**：和"摘花生"像是镜像题——一个求最多花生，一个求最少过路费。但求最小值有一个坑：非起点位置要初始化为一个很大的数（INF），否则 `min(上方, 左方)` 会因为边界外的 0 而选错。另外，题目说必须在 2N-1 步内走完——其实从左上到右下只走右/下的最短路径刚好就是 2N-1 步，所以等于告诉你"不能绕路，只能往右和往下走"。

**关键代码**：
```cpp
for (int i = 1; i <= n; i++)
    for (int j = 1; j <= n; j++) {
        if (i == 1 && j == 1) f[i][j] = w[i][j];              // 起点
        else {
            f[i][j] = INF;
            if (i > 1) f[i][j] = min(f[i][j], f[i-1][j] + w[i][j]);
            if (j > 1) f[i][j] = min(f[i][j], f[i][j-1] + w[i][j]);
        }
    }
```

**总结**：求最小值时**边界必须设 INF**——否则 `min(dp[0][j], ...)` 会错选 0。这是求 max 和求 min 在初始化上的关键区别。

### LinK63 林克的01背包

**思路**：有 N 件物品，每件有体积 v[i] 和价值 w[i]，背包容量为 V。每件物品**只能选一次**（要么拿、要么不拿，所以叫"01"）。问在总体积不超过 V 的前提下，总价值最大能到多少。这是动态规划的经典模型，所有背包问题的基石。

**DP 分析**：定义 `f[i][j]` = 只考虑前 i 件物品、背包容量为 j 时能获得的最大价值。对于第 i 件物品，只有两个选择：
1. **不选第 i 件**：问题退化为"前 i-1 件物品、容量为 j"，价值 = `f[i-1][j]`。
2. **选第 i 件**（前提 `j >= v[i]`）：占用 v[i] 的体积获得 w[i] 的价值，剩下的容量 j-v[i] 从前 i-1 件中选。价值 = `f[i-1][j-v[i]] + w[i]`。

两者取 max：`f[i][j] = max(f[i-1][j], f[i-1][j-v[i]] + w[i])`。最终答案 = `f[N][V]`。

**二维到一维的降维优化**：观察递推关系，`f[i][j]` **只依赖上一行** `f[i-1][...]`（上一行的 j 列和 j-v[i] 列）。因此可以用一维数组滚动更新：`f[j] = max(f[j], f[j-v[i]] + w[i])`。但有个关键陷阱——j 必须**从大到小逆序遍历**（`for j = V down to v[i]`）。为什么？因为 `f[j-v[i]]` 需要的是"上一轮"的旧值（对应 `f[i-1][j-v[i]]`），如果 j 正序递增，`f[j-v[i]]` 可能已经被**本轮第 i 件物品**更新过了，那就等于"同一件物品被拿了多次"——恰好变成完全背包的行为！记住：**01 逆序，完全正序**，这个方向区分是所有背包变体的核心。

数据范围 N, V ≤ 1000，二维 O(N×V) = $10^6$ 完全可行。

**关键代码**：
```cpp
const int N = 1007;
int n, m;
int v[N], w[N];    // 每件物品的体积和价值
int f[N][N];       // 二维 DP

int main() {
    cin >> n >> m;
    for (int i = 1; i <= n; i++) cin >> v[i] >> w[i];

    for (int i = 1; i <= n; i++)
        for (int j = 0; j <= m; j++) {
            f[i][j] = f[i - 1][j];                     // 不选第 i 件
            if (j >= v[i])
                f[i][j] = max(f[i][j], f[i - 1][j - v[i]] + w[i]); // 选第 i 件
        }
    cout << f[n][m] << endl;
}
```

**一维优化版**（推荐记忆）：
```cpp
int f[N];  // 一维滚动
for (int i = 1; i <= n; i++)
    for (int j = m; j >= v[i]; j--)          // ★ 逆序！防止重复选取
        f[j] = max(f[j], f[j - v[i]] + w[i]);
```

**总结**：01 背包的递推核心：`f[i][j] = max(f[i-1][j], f[i-1][j-v[i]] + w[i])`。一维优化时 j 必须逆序（`j = m → v[i]`），否则 `f[j-v[i]]` 用的是本轮更新值，变成完全背包行为。物品编号从 1 开始让 `i=0` 天然成为"0 件物品"的 base case。

### LinK64 林克的完全背包

**思路**：和 01 背包的唯一区别——每件物品可以拿无限次。神奇的是一维代码也只有一个区别：j 要**正序**（从 v[i] 到 m）而不是逆序。为什么？正序时 `f[j-v[i]]` 可能已经被**本物品在这一轮**更新过了，这意味着同一件物品可以被反复拿取。而逆序时 `f[j-v[i]]` 还是上一轮的旧值，等于每件只能拿一次。递推公式完全相同，仅仅循环方向不同——记住这个，01 和完全背包就不会搞混。

**关键代码**：
```cpp
for (int i = 1; i <= n; i++)
    for (int j = v[i]; j <= m; j++)          // ★ 正序！与 01 背包的唯一区别
        f[j] = max(f[j], f[j - v[i]] + w[i]);
```

**总结**：01 背包逆序 vs 完全背包正序——两者递推公式相同，仅 j 遍历方向不同。这是背包问题最重要的区分点。

### LinK65 多重背包问题(1)

**思路**：每种物品有了数量限制（比如最多拿 3 个），介于 01 背包（最多 1 个）和完全背包（无限个）之间。数据范围小（N, V ≤ 100），直接笨办法：对每种物品，枚举拿 k 个（k 从 1 到 s[i]），每个 k 当作一个独立的"虚拟物品"用 01 背包的方式处理。注意 j 要逆序（和 01 背包一样），否则同一物品会被多次计算。

**关键代码**：
```cpp
for (int i = 1; i <= n; i++) {
    int v, w, s; cin >> v >> w >> s;
    for (int j = m; j >= 0; j--)             // 逆序（01 模式）
        for (int k = 1; k <= s && k * v <= j; k++)  // 枚举选几个
            f[j] = max(f[j], f[j - k * v] + k * w);
}
```

**总结**：朴素多重背包 = 把每种物品拆成 s 件独立物品 + 01 背包。$O(N \times V \times s) \approx 10^6$（N,V,s≤100）。

### LinK66 多重背包问题(2)

**思路**：和 LinK65 完全一样的多重背包，但 N 从 100 暴增到 1000，V 从 100 到 2000，s[i] 从 100 到 2000。朴素三重循环 O(N×V×s) 最坏 = 1000×2000×2000 = 4×$10^9$，铁定超时。必须优化。

关键优化——**二进制拆分**。朴素做法把每种物品拆成 s 件独立物品走 01 背包，物品总数 = Σ s[i]，最多可能 2×$10^6$ 件。但有一个巧妙的数学事实：**任何正整数都可以用一组"2 的幂"来表示**。例如 13 = 1+2+4+6（1,2,4 是 2 的幂，6 是余数）。用这 4 个"打包"物品，通过选择不同的组合，可以表示 0~13 之间**任意一个整数**——因为 0~7 可以用 {1,2,4} 的子集表示（三位的二进制），8~13 可以用 {1,2,4}+6 表示。一般地：1, 2, 4, 8, ..., $2^k$, 余数 这组数可以覆盖 0~s 的全部整数。

具体拆分步骤（以 s=13 为例）：
```
k=1: 打包 1件 (体积=1v, 价值=1w), s=13-1=12, k=1*2=2
k=2: 打包 2件 (体积=2v, 价值=2w), s=12-2=10, k=2*2=4
k=4: 打包 4件 (体积=4v, 价值=4w), s=10-4=6,  k=4*2=8
k=8 > s=6, 停止循环
剩余 s=6: 打包 6件 (体积=6v, 价值=6w)
```
拆分后共 4 个打包物品，每个打包物品只能用一次（走 01 背包）。验证：0~7 用 {1,2,4} 组合，8~13 用 {1,2,4}+6 组合，确实能覆盖全部。

物品总数从 Σ s[i] 骤降到 Σ log(s[i])。最坏：1000 种物品 × log₂(2000) ≈ 1000×11 = 11000 件。再走 O(物品数×V) = 11000×2000 ≈ 2.2×$10^7$ 的 01 背包，轻松通过。

**关键代码**：
```cpp
const int N = 12010, M = 2010;  // N: 拆分后最多 1000*log2000 ≈ 11000 件
int n, m;
int v[N], w[N];  // 拆分后的所有打包物品
int f[M];        // 一维 DP 数组

int main() {
    cin >> n >> m;
    int cnt = 0;  // 拆分后的总物品数
    for (int i = 1; i <= n; i++) {
        int a, b, s;
        cin >> a >> b >> s;   // 体积、价值、数量

        // 二进制拆分
        int k = 1;
        while (k <= s) {
            cnt++;
            v[cnt] = a * k;    // k 件的总重量打包成一个"大物品"
            w[cnt] = b * k;    // k 件的总价值
            s -= k;
            k *= 2;
        }
        if (s > 0) {           // 剩余的零头打包
            cnt++;
            v[cnt] = a * s;
            w[cnt] = b * s;
        }
    }
    n = cnt;  // 更新物品数为打包后的数量

    // 标准 01 背包（一维逆序）
    for (int i = 1; i <= n; i++)
        for (int j = m; j >= v[i]; j--)
            f[j] = max(f[j], f[j - v[i]] + w[i]);

    cout << f[m] << endl;
}
```

**总结**：二进制拆分将多重背包转化为 01 背包——1,2,4,...,$2^k$,余数 可组合出 0~s 的所有数量。物品数从 O(Σs) 降到 O(Σlog s)，原题从 $10^9$ 级降到 $10^7$ 级。`s -= k` 后别忘记把余数也打包。

### LinK67 分组背包问题

**思路**：物品被分成了若干组，**每组最多只能选一件物品**。比如"武器"组有剑、弓、斧三件，你最多只能拿一样。这本质上是 01 背包的升级——01 背包是每组只有一件物品（拿或不拿），分组背包是每组有多件但至多选一。关键写法：三层循环，**第一层枚举组，第二层逆序容量，第三层枚举组内物品**。容量循环在组内物品循环的外面，保证了互斥（一个容量只能被组内一件物品占用）。

**关键代码**：
```cpp
for (int i = 1; i <= n; i++) {               // 枚举组
    for (int j = m; j >= 1; j--) {            // 逆序容量
        for (int k = 1; k <= s[i]; k++) {     // 枚举组内物品
            if (v[i][k] <= j)
                f[j] = max(f[j], f[j - v[i][k]] + w[i][k]);
        }
    }
}
```

**总结**：循环顺序至关重要——`i → j(逆序) → k` 保证互斥。若 `i → k → j(正序)` 则同一物品会被多次选，失去分组意义。

### LinK68 混合背包问题

**思路**：把 01 背包、完全背包、多重背包混在一起出题。解法也不复杂：读入每件物品时看 si 的值——si=-1 就是 01 背包（当多重处理，s 设成 1 走二进制拆分）；si=0 就是完全背包（正序循环）；si>0 就是多重背包（二进制拆分后 01 背包）。三种情况用同一个 `f[]` 数组处理即可，互不影响。核心在于**分类处理 + 共用数组**。

**关键代码**：
```cpp
if (!s) {                                     // 完全背包
    for (int j = v; j <= m; j++) f[j] = max(f[j], f[j - v] + w);
} else {
    if (s == -1) s = 1;                       // 01 背包 → 转多重
    for (int k = 1; k <= s; k *= 2) {          // 二进制拆分
        for (int j = m; j >= k * v; j--) f[j] = max(f[j], f[j - k*v] + k*w);
        s -= k;
    }
    if (s) for (int j = m; j >= s*v; j--) f[j] = max(f[j], f[j - s*v] + s*w);
}
```

**总结**：三种背包混合时，按 si 分类处理即可，都操作同一个 f[] 数组——各类物品互相独立、可以混合选取。

### LinK71 最长上升子序列

**思路**：在一个序列中找到最长的严格递增子序列（不要求连续）。比如 `3, 1, 2, 1, 8, 5, 6` 的最长上升子序列是 `1, 2, 5, 6`，长度为 4。用 DP：`f[i]` 表示"以第 i 个数结尾的最长上升子序列有多长"。对于每个 i，往前看所有 j < i，如果 `a[j] < a[i]`，说明可以把 a[i] 接在以 a[j] 结尾的子序列后面，长度就是 `f[j] + 1`。最后答案不是 `f[n]` 而是所有 `f[i]` 的最大值——因为最长子序列不一定以最后一个数结尾。

**关键代码**：
```cpp
for (int i = 1; i <= n; i++) {
    f[i] = 1;                                  // 自己成序列，长度至少 1
    for (int j = 1; j < i; j++)
        if (a[j] < a[i]) f[i] = max(f[i], f[j] + 1);
}
int ans = 0;
for (int i = 1; i <= n; i++) ans = max(ans, f[i]);  // ★ 答案遍历取 max，不是 f[n]!
```

**总结**：最终答案不一定是 `f[n]`——最长上升子序列未必以最后一个元素结尾。这个坑很常见。

### LinK72 最长上升子序列(2)

**思路**：和 LinK71 完全相同的题目，但 N 从 1000 暴增到 100000。O($N^2$) 的朴素 DP 超时严重（$10^{10}$ 次操作）。需要换一种思路——**贪心 + 二分**，复杂度 O(N log N)。

核心思想：维护一个数组 `q`，`q[i]` 的含义是——**在所有长度为 i 的上升子序列中，最小的"末尾元素"是多少**。这个定义有几个关键性质：
1. `q` 数组天然是**严格单调递增**的。因为如果长度更长的子序列末尾还能更小，那短的必然也能更小。
2. 对于新来的数字 a[i]，我们在 q 中二分查找**最后一个小于 a[i] 的位置 r**。这意味着 a[i] 可以接在任意长度 ≤ r 的上升子序列后面，形成长度为 r+1 的新子序列。而且 a[i] 作为这个新子序列的末尾，可以更新 `q[r+1]`（因为 a[i] 比原有的 `q[r+1]` 更小或相同，更有利于后续接数字）。
3. 如果 r == len（当前最长长度），说明 a[i] 扩展出了一个新的最长长度：`len++`，`q[len] = a[i]`。

举例：序列 `3, 1, 2, 1, 8, 5, 6`：
```
a[0]=3: q[0]=-∞(哨兵), r=0, q[1]=3, len=1
a[1]=1: r=0(1<3, 只能接在0长度后面), q[1]=1, len=1
a[2]=2: r=1(2 比 q[1]=1大), q[2]=2, len=2
a[3]=1: r=0, q[1]=1(不变), len=2
a[4]=8: r=2(8 比 q[2]=2大), q[3]=8, len=3
a[5]=5: r=2(5 比 q[2]=2大, 比 q[3]=8小), q[3]=5, len=3
a[6]=6: r=3(6 比 q[3]=5大), q[4]=6, len=4
```
最终 len=4。注意 `q` 数组里的 `[1, 2, 5, 6]` 恰好就是本例的 LIS，但这是巧合——通常 `q` 不一定是真正的子序列，只保证长度正确。

二分查找用的是"找最后一个满足条件的位置"模板：`mid = l+r+1>>1`（上取整），配合 `l=mid` 和 `r=mid-1`，防止相邻时死循环。

**关键代码**：
```cpp
const int N = 100010;
int n, a[N];
int q[N];  // q[i] = 长度为 i 的上升子序列的最小末尾值

int main() {
    scanf("%d", &n);
    for (int i = 0; i < n; i++) scanf("%d", &a[i]);

    int len = 0;                         // 当前最长长度
    q[0] = -2e9;                         // 哨兵：比任何 a[i] 都小
    for (int i = 0; i < n; i++) {
        // 二分查找 q[0..len] 中最后一个 < a[i] 的位置
        int l = 0, r = len;
        while (l < r) {
            int mid = l + r + 1 >> 1;    // 上取整
            if (q[mid] < a[i]) l = mid;
            else r = mid - 1;
        }
        // r 是最后一个 < a[i] 的位置
        len = max(len, r + 1);           // a[i] 让长度扩展到 r+1
        q[r + 1] = a[i];                 // 更新（比原先的更小或扩展新长度）
    }
    printf("%d\n", len);
}
```

**总结**：`q[i]` 存的是每种长度的"最小末尾"，利用其单调性 O(log N) 二分找插入位置。注意 `q` 不是真正的 LIS 序列（只保证长度正确）。二分用上取整 `l+r+1>>1` 模板，否则相邻时死循环。

### LinK73 拦截导弹

**思路**：题目给了若干枚导弹的高度，一套拦截系统有一个特点：发射的第一枚可以飞到任意高度，但之后每一枚都不能超过前一发的高度（只能拦截高度 ≤ 前一发的导弹）。问两件事——

**第一问：这一套系统最多能拦截多少枚导弹？** 其实就是求**最长不上升子序列**的长度。和 LIS 几乎一样，只是方向反了——LIS 要求严格递增（后面的 > 前面的），这里要求"不上升"，即后面的 ≤ 前面的。判断条件从 `a[j] < a[i]` 改为 `h[i] <= h[j]`。递推式：`f[i] = max(1, max_{j<i && h[j] >= h[i]} (f[j] + 1))`。

**第二问：最少需要多少套系统才能拦截全部导弹？** 直觉上，每次出现一枚"比当前所有系统拦截高度都高"的导弹，就必须新增一套系统。更严格地说，这其实是一个经典的偏序集覆盖问题——**Dilworth 定理**：在一个偏序集中，用最少的"链"覆盖所有元素，这个最小链数等于"最长反链"的长度。应用到本题：
- "链" = 不上升子序列（一套系统拦截的导弹串）：高度单调不增。
- "反链" = 上升子序列（高度严格递增的导弹串）：因为上升的导弹无法被同一套系统拦截（前高后低才合法）。
- Dilworth 定理说：最少的不上升子序列数 = 最长上升子序列的长度。

所以第二问直接转化为求 LIS（严格递增）的长度。代码用贪心法实现第二问（本质和 LIS 二分优化一致）：维护数组 q，q[k] 表示第 k 套系统当前拦截的最后一枚导弹高度。对于每枚新导弹，找最低能拦截它的系统（`q[k] >= h[i]` 且 k 最小），如果找不到就新开一套。

**关键代码**：
```cpp
#include <sstream>
string line; getline(cin, line);
stringstream ssin(line);
int n = 0;
while (ssin >> h[n]) n++;  // 解析单行不定个数输入

// 第一问：最长不上升子序列（类似 LIS，条件反转）
int res = 0;
for (int i = 0; i < n; i++) {
    f[i] = 1;
    for (int j = 0; j < i; j++)
        if (h[i] <= h[j])                    // 不上升：后面的 ≤ 前面的
            f[i] = max(f[i], f[j] + 1);
    res = max(res, f[i]);
}
printf("%d\n", res);

// 第二问：最少系统数 = 贪心分配（本质 = LIS 长度）
int cnt = 0;  // q[] 是各系统最后拦截高度
for (int i = 0; i < n; i++) {
    int k = 0;
    while (k < cnt && q[k] < h[i]) k++;     // 找第一个 ≥ h[i] 的系统
    if (k == cnt) q[cnt++] = h[i];           // 都够不着，新开一套
    else q[k] = h[i];                        // 分配给第 k 套
}
printf("%d\n", cnt);
```

**总结**：第一问 = 最长不上升子序列（`h[i] <= h[j]`）。第二问 = Dilworth 定理：最少链覆盖 = 最长反链长度，也就是最长上升子序列的长度。输入是单行空格分隔，用 `getline + stringstream` 解析。

### LinK75 最长公共子序列

**思路**：在两个字符串中分别取一个子序列（可以不连续），让它们一模一样，求最长能有多长。用 DP：`f[i][j]` 表示 A 的前 i 个字符和 B 的前 j 个字符的最长公共子序列长度。从最后一个字符看：如果 `a[i] == b[j]`，这两个字符刚好可以配对，长度 = 前 i-1 和前 j-1 的 LCS + 1；如果不等，至少有一个字符得被丢弃——要么丢 a[i]（看前 i-1 个和前 j 个），要么丢 b[j]（看前 i 个和前 j-1 个），取较大者。

**关键代码**：
```cpp
cin >> n >> m >> a + 1 >> b + 1;       // 下标从 1 开始
for (int i = 1; i <= n; i++)
    for (int j = 1; j <= m; j++) {
        if (a[i] == b[j])
            f[i][j] = f[i - 1][j - 1] + 1;           // 匹配
        else
            f[i][j] = max(f[i - 1][j], f[i][j - 1]); // 不匹配
    }
```

**总结**：`cin >> a+1` 从 a[1] 开始填，让字符串下标与 DP 对齐。当 a[i]!=b[j] 时不需要考虑 `f[i-1][j-1]`（已被 max 覆盖）。

### LinK76 石子合并

**思路**：N 堆石子排成一排，每次只能合并**相邻**的两堆，合并的代价是这两堆石子质量之和。问把所有石子合并成一堆的最小总代价。这道题不能像哈夫曼编码那样任意两堆合并（那样用优先队列就行），**必须相邻**——这使得问题变成典型的**区间 DP**。

**DP 分析**：
- 状态定义：`f[i][j]` = 把第 i 堆到第 j 堆石子合并成一堆的**最小总代价**。
- 递推思路：区间 [i, j] 怎么合并成一堆？**最后一次合并**一定是把左右两个已经合并好的大堆合在一起。假设最后一次合并的分割点在 k——左边 [i, k] 已经合成了一堆，右边 [k+1, j] 也合成了一堆，这次合并的代价就是**这两大堆的质量之和**，即整个区间 [i, j] 的总质量（用前缀和 O(1) 求）。
- 所以：`f[i][j] = min_{k=i}^{j-1} ( f[i][k] + f[k+1][j] ) + sum(i, j)`。枚举所有可能的分割点 k，取最小的。

**区间 DP 的枚举顺序（至关重要！）**：不能简单地 `for i`、`for j` 递推，因为长区间 [i,j] 依赖所有更短的子区间（[i,k] 和 [k+1,j] 都比 [i,j] 短）。正确的枚举顺序是——**按区间长度从小到大**：
1. `len = 1`（单堆）：`f[i][i] = 0`（不需要合并）。
2. `len = 2`：依赖 len=1 的结果，可以算了。
3. `len = 3`：依赖 len=1 和 len=2 的结果……
4. 最终 `len = N` 时 `f[1][N]` 就是答案。

**前缀和**：`s[i] = a[1] + a[2] + ... + a[i]`，则 `sum(i, j) = s[j] - s[i-1]`，O(1) 算出任意区间的总质量。

**手动推演示例**（石子 = [1, 3, 5, 2]）：
```
s = [0, 1, 4, 9, 11]

len=1: f[1][1]=f[2][2]=f[3][3]=f[4][4]=0
len=2: f[1][2]=1+3=4, f[2][3]=3+5=8, f[3][4]=5+2=7
len=3: f[1][3]=min(k=1: f[1][1]+f[2][3]=8, k=2: f[1][2]+f[3][3]=4) + sum(1,3)=9
             = 4+9=13
       f[2][4]=min(k=2: f[2][2]+f[3][4]=7, k=3: f[2][3]+f[4][4]=8) + sum(2,4)=8
             = 7+8=15
len=4: f[1][4]=min(k=1: 0+15=15, k=2: 4+7=11, k=3: 13+0=13) + sum(1,4)=11
             = 11+11=22  ← 最优方案
```

最优方案：先合并 [1,2]（代价 4），再合并 [3,4]（代价 7），最后合并两大堆（代价 11），总代价 22。

**关键代码**：
```cpp
const int N = 307;
int n;
int a[N], s[N];        // s 是前缀和
int f[N][N];           // f[i][j] = 合并 [i,j] 的最小代价

int main() {
    cin >> n;
    for (int i = 1; i <= n; i++) {
        cin >> a[i];
        s[i] = s[i - 1] + a[i];      // 前缀和
    }

    memset(f, 0x3f, sizeof f);       // 初始化为 INF

    for (int len = 1; len <= n; len++)                    // ★ 按区间长度枚举
        for (int i = 1; i + len - 1 <= n; i++) {          // 左端点
            int j = i + len - 1;                          // 右端点
            if (len == 1) { f[i][j] = 0; continue; }      // 单堆不需合并
            for (int k = i; k < j; k++)                   // 枚举分割点
                f[i][j] = min(f[i][j], f[i][k] + f[k+1][j] + s[j] - s[i-1]);
        }

    cout << f[1][n] << endl;
}
```

**总结**：区间 DP 的核心要素：① 状态定义 `f[i][j]` 表示区间的最优值；② 递推时**必须按区间长度递增**（因为长区间依赖短区间）；③ 枚举分割点 k 遍历所有可能的最后一次合并位置；④ 前缀和 O(1) 算区间和。复杂度 O($N^3$)，N ≤ 300 可过。区间 DP 的通用模板同样适用于"最长回文子序列""矩阵链乘法"等问题。
